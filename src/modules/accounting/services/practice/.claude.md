# Practice service group

Accounting practice management: time tracking, WIP → invoice, jobs + tasks, staff rate cards, client management, scheduled reports. Designed for professional services firms (accounting practices, auditors) that bill clients by the hour or fixed fee.

## Files

### Time tracking + WIP
| File | Role |
|---|---|
| `practiceTimeEntryTypes.ts` | Types: `PracticeTimeEntry`, `PracticeTimeEntryInput`, `PracticeTimeEntryUpdateInput`, `PracticeEntryFilters`. |
| `practiceTimeEntryService.ts` | DB CRUD for `time_entries`. Exports `mapEntry` + `validateClientCategoryWorkItem` (@internal — only for workflow). Validates client/category/work_item all belong to the calling company. |
| `practiceTimeEntryWorkflow.ts` | State machine — `submitEntry`, `approveEntry`, `rejectEntry`, `markEntriesBilled`. Sets `billed_at` + `invoice_id`. |
| `practiceWipService.ts` | **`getWipByClient`** aggregates approved+unbilled entries per client. **`generateWipInvoice(companyId, userId, { practiceClientId, timeEntryIds, taxRate })`** creates the customer_invoices row + items and calls `markEntriesBilled`. Requires `practice_clients.link_customer_id`. Returns `{ invoiceId, invoiceNumber, lineCount, subtotal, taxAmount, totalAmount }`. |
| `practiceEntryTemplateService.ts` | Recurring time-entry templates (e.g. "Monthly bookkeeping — client X, 4h"). |

## Multi-tenant rules

Every DB call scopes on `company_id`. `validateClientCategoryWorkItem` verifies client, job category, AND work item each belong to the calling company before allowing time entry creation.

## Key tables

- `time_entries` — core. `status`: draft|submitted|approved|rejected|billed|not_billable. Practice columns added by mig 373/385: `practice_client_id`, `job_category_id`, `work_item_id`, `job_id`, `applied_rate`, `line_total`, `billable`, `approved_by`/`approved_at`, `billed_at`, `invoice_id`.
- `practice_clients` — practice-side master. `link_customer_id` connects to the AR `customers` table for invoicing.
- `practice_job_categories` + `practice_work_items` — billable work hierarchy.
- `practice_jobs` + `practice_tasks` — job/task lifecycle.
- `practice_staff_rates` + `practice_staff_cost_rates` — rate cards.
- `practice_client_rate_overrides` (mig 395) — per-client-per-staff overrides.

## Gotchas

- **`mapEntry` and `validateClientCategoryWorkItem` are `@internal`** — exported only so `practiceTimeEntryWorkflow` can reuse them. Import from the workflow (public API), not the service directly.
- **`generateWipInvoice` does NOT post the invoice** — it creates the `customer_invoices` record in draft and calls `markEntriesBilled`. The caller must post separately if GL posting is required.
- **Rate cascade**: staff+category → staff default → category default → company default. If no rate resolves, `resolveRate` returns `null` and `line_total` stays `null` until rate is configured.
- **WIP grouping modes**: `detailed` (one line per entry) vs `by_work_item` / `by_category` (collapsed). Affects invoice line count and client visibility.
- **`link_customer_id` is required** for `generateWipInvoice`. Seeds / tests must create a customer and link each practice_client before billing works.
- **Mig 395 is an ALTER, not a CREATE** — earlier `practice_client_rate_overrides` table was created in mig 372 with (`user_id`, `rate`). Mig 395 adds (`staff_user_id`, `rate_per_hour`, `notes`) and back-fills. The service uses the new columns.
- **`customers.name` is the only required field when linking a practice client** — `registration_no` is stored as `registration_number`, `tax_no` as `vat_number`, and there's no `status` column (use `is_active boolean` instead).
