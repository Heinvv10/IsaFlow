# Practice service group

Accounting practice management: time tracking for staff against client engagements, WIP (Work-In-Progress) billing, rate card management, and workflow state transitions. Designed for professional services firms (accounting practices, auditors) that bill clients by the hour.

## Files

| File | Role |
|---|---|
| `practiceTimeEntryTypes.ts` | Types: `PracticeTimeEntry`, `PracticeTimeEntryInput`, `PracticeTimeEntryUpdateInput`, `PracticeEntryFilters`. |
| `practiceTimeEntryService.ts` | DB CRUD for `time_entries`. Exports `mapEntry` and `validateClientCategoryWorkItem` (marked `@internal` — only for use by `practiceTimeEntryWorkflow`). Validates client, job category, and work item all belong to the calling company. |
| `practiceTimeEntryWorkflow.ts` | State machine for time entries: `submitEntry`, `approveEntry`, `rejectEntry`, `markEntriesBilled`. `markEntriesBilled` sets `billed_at` and links `invoice_id`. |
| `practiceWipService.ts` | `getWipByClient` — aggregates approved-but-unbilled entries by client. `generateWipInvoice` — converts selected time entries into a customer invoice (with grouping: detailed | by_work_item | by_category). Calls `markEntriesBilled` after invoice creation. |
| `practiceClientService.ts` | DB CRUD for `practice_clients`. Optional `link_customer_id` links a practice client to an AR customer for invoice delivery. |
| `practiceJobCategoryService.ts` | DB CRUD for `practice_job_categories` (e.g. Tax Returns, Audit, Bookkeeping). |
| `practiceStaffRateService.ts` | DB CRUD for staff rate cards. `resolveRate(companyId, userId, jobCategoryId)` — resolution order: staff+category override → staff default → category default → company default. |
| `practiceTimeEntryWorkflow.ts` | Workflow transitions; re-used by WIP service for billing state. |

## Multi-tenant rules

Every DB call scopes on `company_id`. `validateClientCategoryWorkItem` verifies client, job category, and work item each belong to the calling company before allowing time entry creation — this prevents cross-tenant WIP creation if IDs are guessed.

## Key tables

- `time_entries` — core. `status`: `draft | submitted | approved | rejected | billed`. `billed_at` + `invoice_id` set by `markEntriesBilled`.
- `practice_clients` — practice-side client master. Optionally links to `customers` via `link_customer_id`.
- `practice_job_categories` — billable work categories per company.
- `practice_work_items` — specific tasks within a job category.
- `practice_staff_rates` — hourly rates per staff member / category combination.

## Gotchas

- **`mapEntry` and `validateClientCategoryWorkItem` are `@internal`** — they are exported only because `practiceTimeEntryWorkflow` imports them. Import from `practiceTimeEntryWorkflow` (the public API), not from `practiceTimeEntryService` directly.
- **`generateWipInvoice` does not post the invoice** — it creates the `customer_invoices` record in draft status and calls `markEntriesBilled`. The caller must post the invoice separately if GL posting is required.
- **Rate resolution cascade**: staff+category is most specific; company default is the fallback. If no rate resolves, `resolveRate` returns `null` — `practiceTimeEntryService` will record `applied_rate = null` and `line_total = null` until a rate is configured.
- **WIP grouping**: `by_work_item` and `by_category` groupings collapse multiple time entries into single invoice lines. `detailed` creates one line per entry. Choice affects invoice line count and client visibility.
- **`link_customer_id`** on `practice_clients`: when set, `generateWipInvoice` uses this customer for AR invoice creation. When null, the practice client cannot be invoiced through AR — caller receives an error.
