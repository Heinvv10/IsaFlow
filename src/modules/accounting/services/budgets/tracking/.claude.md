# Budget tracking engine (`services/budgets/tracking/`)

Budget vs Actual rebuilt (budgets P3 PR-A; spec `docs/plans/budgets/P3-tracking-spec.md`, contract `docs/plans/budgets/00-shared-contract.md`). One engine for the BvA page (PR-B), its CSV/XLSX export, and from PR-C `getBudgetVariance`, the comparator, packs and MCP.

## Caller contract
- `buildBudgetTrackingReport(companyId, params, now?)` → `BudgetTrackingReport` (`trackingTypes.ts`). Every query is SEQUENTIAL (one pg client under withAuth). Refusals are `TrackingError` (400/404/409) or P1's `BudgetVersionError`; routes answer both through `@/lib/budgetTrackingResponse`.
- Routes: `GET /api/accounting/reports-budget-tracking` (JSON) and `GET /api/accounting/budget-tracking-export?format=csv|xlsx` (same query, `trackingQuery.parseTrackingQuery`, zod). Read-only: no withWriteAccess (decision 15). Rate limited per company.
- Money is rands rounded to the cent here (integer cents via `budgets/grid/cents.ts`); `null` = absent (no budget / no version), never 0. Band keys, labels and signs are the grid's (`budgets/grid/subtotals.ts`), one set for both budget surfaces.
- `window.postedThrough` = P0's figure (budgetVarianceService): latest posted, non-year-end entry date anywhere in the window, COMPANY-WIDE, any account, unfiltered, so it can be forward-dated. `window.inProgress.actualsTo` = latest entry date of the postings the FILTERED actuals read consumed IN the in-progress month (same filter, income-statement accounts only, month 1st to month end, forward-dated included: it never names a posting Actual leaves out, nor omits one it holds); null when that month has none, never an earlier month's date.
- For PR-B (UI): the wire shape is `window.inProgress.{month, actualsTo}` plus `window.postedThrough`, not the spec's `inProgress.postedThrough`. `fiscal_year` is refused (400) with period=month and period=custom, `quarter` without period=quarter, `from`/`to` outside custom: the page must drop the parameters the chosen period does not take.
- `trackingActualRead.ts` is THE actuals SQL of the budgets programme (P4/P5/P6 read through it). P2's `budgets/priorActuals.ts` still has its own SQL: PR-B makes it delegate.

## Files
- Registry misses anywhere on the path (window, year options, a named version's year) go through `mapRegistryMiss` (4xx); invariant breaks (`BudgetGrainContradictionError`, `TrackingOrderError`) are logged 500s.
- `trackingWindow.ts` month / quarter (3-month blocks from the FY start; 14 months → Q5 of 2) / ytd / fy / custom (month-granular, ≤ 24 months). Registry only; a year not on calendar months is a 409; a year the registry cannot place is a 400 (22023 no start month: 409), any other error propagates. A parameter of another period, or a year outside 1900-2200, is a 400 (`assertParamsApply`, also run by `trackingQuery`).
- `trackingBudgetRead.ts` versions (primary per year, or a named one: 404 foreign, 400 when the window reaches another year), built from `window.years` (no second registry walk), and amounts at their stored grain. `trackingFilter.ts` cc1/cc2/bu ids looked up under company_id (404); `cc1_id` must be a CC1 and `cc2_id` a CC2 centre (400). The CC2 chains are loaded ONCE per request (filter + budget rows). Lines print in Postgres' `ORDER BY account_code` (`readAccountOrder`).
- `trackingDimRollup.ts` included / coarser / other per budget row (pure). `trackingLines.ts`, `trackingBands.ts`, `trackingProjection.ts`, `trackingByMember.ts`, `budgetBridgeSteps.ts`: pure.
- Heatmap: a month with no included budget but one above the filter says "Budgeted above this filter" (`TrackingMonth.budgetAboveFilter`), not "No budget for this month".
- `trackingExport.ts` CSV/XLSX of `statementRows/budgetTrackingRows` (copy-only adapter); XLSX text takes csvVal's leading-character guard (`=+-@`, tab, CR). A cross-FY window's Version line names each year's version ("FY2027: Original · approved; FY2028: no budget in this window"). Charts: `components/accounting/charts/varianceHeatmapOption.ts` + `VarianceHeatmap.tsx`.

## Rules (spec §2)
- Var R = actual − budget (movement); `favourable` by polarity (income ≥ 0, expense ≤ 0, profit totals ≥ 0). Var % = variance / |budget|, null on 0.
- Budgeted = an INCLUDED row exists in the window months (D5): a zero budget prints 0; no row is absent ("—"). A window month in a year that is BUDGET-ABSENT FOR THE WINDOW (`budgetAbsentYears`, decided from what the scoped budget read returns: no version, or its version contributes no income-statement row in that year's window months; a row outside the window, on a balance-sheet account or dated in another year's month does not count; FY* outside the window is judged over its whole year) makes the WINDOW Budget / Var R / Var % AND unallocated budget absent on every line, band, member bullet and the footer (no bridge); `monthly[].budget` keeps the versioned months; nothing is then called unbudgeted; the export header carries a "No budget for FYxxxx in this window" notice line. `notices.noVersionYears` (wire name kept) lists those years: it means "no budget in this window", and the year may hold budget outside it; `versionsByFy[y].empty` marks such a year's version, and the export prints "FYxxxx: no budget in this window" for it. A single-year window keeps D5 per line (an account with no row in the window is unbudgeted; the others print). The projection's FY budget goes absent per line only when FY* has no included row for it in the whole year. Band unallocated takes the window's absence (`buildBands(lines, { budgetAbsent })`), so a gap window with no lines is null, not 0.
- Grain change across versions (review r2 A3; flagged for Hein): an account with INCLUDED rows in some window months and only COARSER rows in others (one version at the filter's level, another above it) has no window Budget / Var R / Var %, `budgetAboveFilter` true, its unallocated as computed; bands treat it as unbudgeted. A month with neither is not a change (a budget for part of the window stays a budget).
- Notices: unbudgeted = no included budget AND none above the filter AND actual ≠ 0. Unbudgeted actual and unallocated budget are `{ income, expense }`, never one mixed sum (D1); on GP / OP / NP rows unallocated budget is netted by polarity (income − expense, like the NP budget).
- Actuals: posted, not `year_end`, revenue/expense, entry_date inclusive, EXPLICIT levels ANDed (`jl.cc1_id = F.cc1` …); `costCentre` is the either-level filter (PR-C). Invariant 1 = income statement / dimension P&L to the cent.
- Budget rows: eff.cc1 = cc1 ?? FNO(cc2); a stored cc1 contradicting the chain is a logged `BudgetGrainContradictionError` (500). Coarser (level NULL, nothing conflicts) is `unallocatedBudget`, never in Budget, never apportioned. A CC2 filter knows its FNO: that FNO's CC1 budget is coarser, another FNO's is other (deviation from the §2.4 table's literal text, which would list every FNO as "above" a project). Either level (`cost_centre_id`) follows the spec literally: included on `eff.cc1 = X OR eff.cc2 = X`, coarser only when both are NULL, else other.
- Bands and NP are computed here (GP = T − COS; OP = GP + OI − Opex; NP = OP − OE), never revenue + expense; a band with no budgeted line is absent.
- Projection: cutoff = min(window end, end of the month before today) clamped to [FY*.start − 1, FY*.end]; projected = actual to cutoff + budget after the cutoff's month; FY budget = every FY* month. FY* = the year holding the window's end. A past month of an ENDED year projects as at the window end (the formula), not the FY actual: the spec's "FY* ended → FY actual" holds only for windows ending at FY end (contradiction flagged for Hein).
- Bullets (`group_by`, unfiltered only): member net profit; the untagged member carries every row without a member at that level, so members partition the company NP. Order: the masters' SQL `ORDER BY code, id` (`readMemberOrder`, the ledger's collation), unknown ids by id after them, untagged last.
