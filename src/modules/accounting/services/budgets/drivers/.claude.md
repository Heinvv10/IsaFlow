# budgets/drivers/

Budget drivers (Budgets P4, spec `docs/plans/budgets/P4-drivers-forecast-spec.md` §1, §2, §4, §5, §6).

- **Engine files are PURE** (no `@/lib/neon`, no I/O; PR-1): `driverTypes.ts`, `driverGraph.ts`, `driverEngine.ts`, `headcount.ts`, `reforecast.ts`; also `driverLine.ts`, `driverErrors.ts`, `driverApiTypes.ts` (PR-3).
- **Service files do I/O** (PR-3): `driverRepository.ts`, `payrollHeadcountReader.ts`, `driverHeadcount.ts`, `driverCellSources.ts`, `driverRecomputeService.ts`, `driverValidate.ts`, `driverWriteScope.ts`, `driverWriteService.ts`, `plannedHireService.ts`. They read rows, cells, drivers and payroll, call the engine, and write only what `writes` lists. Routes: `pages/api/accounting/budget-drivers/**`.
- **Reforecast + rolling** (PR-4): `reforecastInputs.ts`, `reforecastService.ts`, `rollingForecastService.ts`, `budgetRollQueue.ts`, `budgetRollJob.ts`. Route: `pages/api/accounting/budget-versions/[id]/reforecast.ts`.

## Caller contract
- Money is integer cents; months are `'YYYY-MM'`; pass the version's month list (12, or 14 in a transition year from `gl/fiscalYearRegistry`). Never assume 12.
- `RowKey` = `rowKeyFor({glAccountId, cc1Id, cc2Id, buId})` = grid `rowKeyOf` shape `acct|cc1|cc2|bu`. A row sets at most one dimension.
- `rows` must list every row that cells or drivers name (unknown → `DriverRefError`). One driver per row.
- `drivers` must be EVERY driver line of the version, never the dependents only: a row missing from it has its `driver` cells re-sourced `manual`.
- Actuals passed to `planReforecast` are cents in budget sign, from P3's `readTrackingActuals` with groupBy null / cc1 / cc2 / bu.
- Errors: `DriverCycleError(path)` (400 `DRIVER_CYCLE`, path first == last), `DriverRefError` (bad row / range / base / percent), `DriverRangeError` (beyond NUMERIC(15,2), bad headcount). Headcount input that is malformed (date not `YYYY-MM-DD`, end before start, allocation % outside 0..100) throws `RangeError`.

## Services (PR-3)
- `driverLine.ts`: `DriverLine` (rand amounts, 'YYYY-MM' months, `rounding` = stored `rounding_unit`); `normaliseLine` (lower-cased ids, every column the kind does not use null, as the table's per-kind CHECK wants); `toDriverDef` (exact cents, DriverRangeError past NUMERIC(15,2); percent bounds stay the engine's).
- `payrollHeadcountReader.ts` `readPayrollHeadcount(companyId)`: the ONLY file joining payroll tables, read-only; payroll_employees id / start / end / status / cost_centre_id and the allocation split, never names, ID/tax numbers or pay. company_id on BOTH tables: payroll's app_user RLS admits every company the user belongs to. A NULL start (impossible: NOT NULL, 380) or an end before the start (no CHECK in payroll; the engine refuses it) is not counted, the latter logged by employee id. One employee's allocations summing past 100% (checked in hundredths) are kept as stored and logged once per employee, by id only.
- `driverRecomputeService.ts` `recomputeVersion(companyId, versionId, userId)` → `{changed, warnings}`: the caller holds the version lock. Rows = every revenue/expense account + grain holding cells or named by a driver or ref, banded by `bandOf`; closedMonths empty. Writes ONLY the engine's `writes` with their source (never an 'override' or 'actual'). It passes EVERY driver of the version (a subset would strip the rest). No driver and no 'driver' cell = no cell read. A cycle here is a 500 (the save-time check refuses it first). `recomputeDependents` is the grid-save hook (Range/Ref → 400 BUDGET_VERSION_INPUT).
- `driverWriteScope.ts` `runDriverWrite(companyId, userId, { versionId, expectedUpdatedAt }, action, write)`: `holdYearRegistry` → ONE savepoint (`takeVersion` FIRST, the grid save's compare-and-set from `budgets/versionTake.ts`: 404, 409 LOCKED, 409 STALE with `currentUpdatedAt` + `status` → write → recompute → one audit row, `driverAction` + `recomputed` → the new token). EVERY driver, override, hire and refresh write requires the token. withAuth COMMITs a 4xx, so the savepoint carries a refusal's rollback.
- `driverWriteService.ts`: `saveDriver` (assertDriverMonths, `checkDriverLine`, `assertNoCycle` with this driver substituted → `BudgetDriverError` DRIVER_CYCLE + path, labelled), `deleteDriver` (the row's overrides → 'manual' in the same savepoint, before the recompute; audit `releasedOverrides`), `resetOverride` (one month or the row), `refreshHeadcount` (audit `headcountAsOf`), `listDrivers`. 'driver' cells a driver no longer covers are re-sourced 'manual' by the engine; an override survives a shrunk range (only reset or delete ends it). `plannedHireService.ts`: hire CRUD (label 1-120 trimmed, FTE > 0 ≤ 9999.99 2 dp, months overlapping the version, a cost centre of the company) and `readHeadcount` (counts + `asOf`).
- Grid-save hook (P2 `gridSave.ts`): an 'actual' cell is read-only (typing over or clearing it is 400); typed cells inside their row's driver range become 'override' (`markOverrides`); then ONE `recomputeDependents` per batch that changed something, in the save's savepoint (audit `overrides`, `recomputed`; result `recomputed`). A clear inside a driver range is refilled. The read model carries each cell's `source` and the version's `drivers` (read in a separate statement from the cells).

## Reforecast + rolling (PR-4)
- `reforecastInputs.ts`: `closedMonthsOf(companyId, year, months)` = months whose periods (matched by DATE, never by label: legacy Jan-Dec period labels) are all closed/locked; `readClosedActuals` = `readTrackingActuals` x4 (null/cc1/cc2/bu) over the closed months, cents (an amount past the budget range is DriverRangeError → 400 DRIVER_RANGE); `planOver` (bands as `loadVersionModel`); `writePlannedCells` = INSERT … ON CONFLICT one_per_cell DO UPDATE … WHERE (amount, source) IS DISTINCT FROM: unchanged cells keep updated_at/xmin.
- `createReforecastFromActuals(companyId, actor, sourceId, {name, rolling})` → `{version, rolling, closedMonths, cells, unplaced, warnings}` (201). One savepoint: source FOR SHARE (404; a locked source is only read) → `createVersion` (draft reforecast, based_on) → `lockVersionForWrite` → drivers, hires and non-P&L cells copied (granted columns) → plan → cells → rolling row (second per year = 409 STATE naming it) → audit (`reforecastFrom`, `closedMonths`, `cells`, `unplaced`, `unplacedTotal`).
- `rollVersion(companyId, userId, versionId, 'auto' | {expectedUpdatedAt})`: auto = `lockVersionForWrite` (no token; bumps the token), Roll now = `takeVersion`. Source = the version's OWN cells/drivers/hires; ALL closed months. Locked: `last_error='version locked'` written OUTSIDE the savepoint; auto returns `status:'locked'`, Roll now 409. Audit only when cells changed. `rollingStatus` → `{rolling, rolledThroughMonth, latestClosedMonth, staleMonths, lastRolledAt, lastError}`. `setRolling` (PUT; reforecast only).
- `scheduleBudgetRoll(companyId, endDate)` (fiscalPeriodService closePeriod / lockPeriod / closeYear): one after-commit job per request, lazy import, never throws; no principal = nothing queued. `runBudgetRolls` runs each roll in its OWN pooled tx as app_user with the closer's claims + company GUC; a failure is logged and stored as `last_error`.
- Payroll labour journal lines carry no `cc1_id` (spec §11, dev 2026-10-29): labour budgeted by CC1 reforecasts those actuals as `unplaced`, never on a company row.

## Signatures
- `driverGraph.ts`: `buildDriverGraph(rows, drivers)`, `topoOrder(graph)` (Kahn, ties by key), `assertNoCycle(rows, drivers)` (driver-save validator).
- `driverEngine.ts`: `computeVersion({months, rows, cells, drivers, headcount, closedMonths, rounding})` → `{writes, warnings}`; `assertDriverMonths(monthIndex(months), driver)` for driver save.
- `headcount.ts`: `headcountByMonth({employees, allocations, hires, months, scope})` → `Map<month, {payroll, hires, total}>` (2 dp).
- `reforecast.ts`: `planReforecast({...})` → `{rows, cells, unplaced, warnings}` (reforecast create and the rolling re-roll).

## Business rules
- Drivers write months in `[fromMonth, toMonth]` only; never a closed month, never an `override` or `actual` cell. Downstream rows read the effective value (whatever source).
- Kinds: fixed = amount; pct_of_line = ref × pct/100; pct_of_section = Σ band rows at scope (same_grain or company) × pct/100 (a row in its own section is a cycle); growth = base × (1 + pct/100)^k, k = list distance from baseMonth (compounding; base strictly before fromMonth); per_head = amount × FTE.
- Exact BigInt arithmetic; percent to 4 dp, |pct| <= 99999.9999 (NUMERIC(9,4)), growth >= -100. ONE half-away rounding from the exact ratio straight to the unit (the driver's own `rounding`, else the caller's; R1/R100/R1000, no residue). Never cents-then-unit (R1.495 is R1, not R2).
- Missing input reads 0 with ONE warning per ref: `REF_MISSING` (pct_of_line), `SECTION_EMPTY` (no section row has a cell that month), `BASE_MISSING` (growth).
- A `driver` cell no driver covers (driver removed, range shrunk) is re-sourced `manual`, value kept (closed months untouched). An `override` is never touched by the engine: only Reset to driver, or deleting the driver (the service re-sources that row's overrides), ends one; a range shrunk and regrown keeps it (spec §1.2).
- `writes` = cells whose amount or source changed: per row in topo order, its driver writes in month order, then its `manual` re-sourcings in month order. An unchanged recompute is `[]`.
- Headcount (decision 7, Hein 2026-10-29): one full head when start <= last day of M and (end null or >= first day of M) and status ≠ `inactive`; CC scope = Σ allocation % when allocation rows exist, else 1 on the employee's own centre; NULL centre counts only at company scope; hires add FTE for startMonth <= M <= endMonth. Allocations are used as payroll stores them: one employee's rows summing past 100% count more than one head (the reader logs it).
- Reforecast: closed months = actual at the account's grain (0 when none, new rows for unbudgeted members/accounts); untagged actuals at a dimension grain are `unplaced` (non-zero net per account + month), never on a company row; open months keep the source cell and source, except a source `actual` (month reopened after a roll) becomes `manual`, value kept; drivers then recompute.
