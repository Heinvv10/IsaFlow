# afs/

Annual Financial Statements engine — IFRS / IFRS-for-SMEs packs (BS/IS/CF/notes) from GL, renders to HTML/DOCX/PDF, review workflow, portal delivery. Largest single module (42 files).

## Modules
- **Document + version**: `afsDocumentService.ts` (a "document" = one year × company), `afsSectionService.ts` (20+ ordered sections), `afsVersionHistoryService.ts`, `afsGenerationJobService.ts` (async job queue `queued → running → complete|failed`), `afsTypes.ts`.
- **Mapping**: `afsMappingService.ts` — COA → AFS line mapping.
- **Note engine**: `noteEngineService.ts` (4-stage: fetch → generate → suppress → persist), `noteDataQueryService.ts`, `noteTemplateRegistry.ts`, `noteRendererService.ts`, `noteAiService.ts` (AI narrative for qualitative), `noteGenerators/` (one file per note: PPE, intangibles, tax, leases…).
- **Statement calculators**: `cashFlowDirectService.ts`, `cashFlowReconciliationService.ts`, `changesInEquityService.ts`, `pisCalculatorService.ts` (Public Interest Score — Companies Act reg 26 → audit/review/compiled), `kpiScorecardService.ts`.
- **Rendering / export**: `afsHtmlRendererService.ts`, `afsHtmlCoverTemplates.ts`, `afsHtmlTableRenderer.ts`, `docxExportService.ts`, `docxTableRenderer.ts`, `pdfExportService.ts`, `weasyprintService.ts` (Python WeasyPrint HTTP service), `serverChartSvg.ts`, `casewareExportExtService.ts`.
- **Branding / templates**: `brandProfileService.ts`, `imageLibraryService.ts`, `reportTemplates.ts`, `entityTerminology.ts` (Company/CC/Trust label swap).
- **Review workflow**: `afsReviewService.ts` (`draft → review → approved → issued`), `afsSectionCommentService.ts`, `afsPreExportChecks.ts` (blocker gate).
- **Proof / signing**: `afsProofCopyService.ts`, `signumIntegrationService.ts` (e-signature), `cipcFilingGuideService.ts`.
- **Compliance**: `complianceCheckerService.ts` (IFRS structural/mathematical/disclosure checks), `complianceAlertService.ts`. The AFS filing deadline is ONE rule, `afsFilingDeadline.ts` (`afsFilingDeadline(companyId, fiscalYear)`: last day of the sixth month after the END of the registry year with that label, `gl/fiscalYearRegistry`; a label no year carries throws `FilingDeadlineUnknownError`, no March fallback), read by the alert detector and by `reports/statutoryFilingsService`. `cashFlowDirectService` logs a failure by class and SQLSTATE only. With an unresolvable year the alert detector fires ONE visible alert, `afs_filing_deadline_unknown` ("AFS filing deadline cannot be assessed: the financial year start is not set"; now raised when a statement's fiscal year label matches no financial year), not a server warning alone — an empty alert list reads as "nothing is due". That alert is withdrawn (system: `dismissed_by` null) in any run that does not raise it, and is not raised again while a USER-dismissed row of its type exists. Types: `afsTypes.ts` re-exports `afsReviewTypes.ts` (review workflow, portal) and `afsComplianceTypes.ts` (PIS, compliance, CIPC, alerts) — add new types to the cohesive file, not back into `afsTypes.ts`.
- **Management pack**: `managementPackConfigService.ts`, `managementPackGeneratorService.ts`, `managementPackComparison.ts` (`comparison_mode` and the two budget sections), `managementPackVarianceNotes.ts` (the APPROVED budget variance notes of the pack month's version, printed under the `budget_variance` table; a failed read prints a fixed sentence and is logged; the scheduled pack — `isaflow-management-packs.timer` → `afs/cron/management-packs` → `runDailyScheduler` — runs on the service pool as isaflow_service with no claims and reads the notes through the `app_service_*` mirrors `app_service_sync_policies()` keeps, proved in `budgets-p5-variance-pack.int.test.ts`), `packAiSummaryService.ts`, `packSchedulerService.ts`, `packDeliveryService.ts`.
- **Portal (client-facing review/approval)**: `portalContactsService.ts`, `magicLinkService.ts` (30-min single-use tokens), `portalNotificationService.ts`.

## Caller contract
Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/afs/*` and `pages/api/portal/afs/*`. Every public function takes `companyId` first (or documentId+companyId). `weasyprintService` shells out over HTTP to a separate Python service.

## Main function signatures
- `enqueueGenerationJob(companyId, documentId, userId): Promise<AfsGenerationJob>` / `markJobStarted / markJobComplete`.
- `generateSection(companyId, documentId, sectionKey): Promise<AfsSection>` / `generateAllSections(...)` — note-engine orchestrator.
- `markSectionReviewed / signOffSection / submitDocumentForReview(companyId, documentId, userId)`.
- `getCashFlowDirect(companyId, yearStart, yearEnd)` — direct-method cash flow. It places each journal by `reports/cashFlowIndirectClassification.journalSections` (the indirect statement's rule: only cash that moved is investing/financing), so the two methods agree on the section totals; see reports/.claude.md.
- `runComplianceCheck(companyId, documentId)` — IFRS structural/math/disclosure.
- `createMagicLink(contactId, documentId): Promise<{ token }>` / `verifyMagicLink(token)` — single-use, 30-min expiry, atomic consume.
- `deliverPack(documentId, companyId)` / `scheduleDelivery(companyId, documentId, config)`.

## Business rules
- Section order and keys are fixed in `reportTemplates` / `noteTemplateRegistry`. Add new notes via `noteGenerators/` + registry entry.
- Document state machine: `draft → review → approved → issued`; `afsPreExportChecks` runs before `issued` and blocks on imbalances / missing mandatory notes.
- PIS calculator drives outcome (audit/review/compiled) — required before generation.
- Magic-link tokens are single-use and consumed atomically inside `verifyMagicLink` (UPDATE…RETURNING with `used_at IS NULL` guard).
- Portal contacts are a separate auth path — magic link only, no password; tenant scope enforced by joining `portal_contacts.company_id`.
- WeasyPrint runs out-of-process — handle timeouts; large packs may hit connection reset.
- Version history: every generation snapshots the rendered output so earlier drafts are recoverable; callers NEVER overwrite in place.
