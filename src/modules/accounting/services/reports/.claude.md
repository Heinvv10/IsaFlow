# Reports service group

Financial + operational reporting engine. Balance sheet, income statement, trial balance, cash flow forecasts, VAT returns, SARS e-filing, KPI dashboards, consolidations, custom reports, trend + ratio analysis. 55 files — the widest service module. AFS note engine lives in `services/afs/`; this module is the core reports surface the UI binds to.

## Functional areas

### Primary statements
- `balanceSheetService.ts` — point-in-time balance sheet with current/non-current split.
- `incomeStatementService.ts` — P&L by period, optional business-unit / cost-centre slice.
- `cashFlowDirectService.ts` (actually in `afs/`) — direct-method cash flow.
- `financialReportingService.ts` — orchestrates a full report pack (BS + IS + CF) in one call.
- `reportingEngineService.ts` — shared helpers: period selection, fiscal calendar, comparatives.

### Trial balance + transaction reports
- `transactionReportingService.ts` — GL transaction-level reports (detailed ledger, GL listings).
- `accountReportingGroupsService.ts` + `groupCrudService.ts` — custom account roll-up hierarchies for reporting.
- `reportNarrativeService.ts` — AI-generated narrative intro / commentary for any report pack.
- `reportPackService.ts` — bundles a set of reports (BS + IS + KPI + commentary) into one PDF/DOCX.

### Cash flow forecast
- `cashFlowForecastService.ts` — 13-week forecast (configurable horizon).
- `cashFlowForecastDataService.ts` — pulls AR/AP/payroll/loan cashflows into the forecast.
- `cashFlowAIService.ts` / `cashFlowForecastAiService.ts` — AI commentary + scenario suggestions.
- `scenarioPlanningService.ts` — what-if cash scenarios (salary increase, lost customer, etc.).
- `threeWayForecastService.ts` — BS + IS + CF 3-statement projections.
- `waterfallDataService.ts` — cash-movement waterfall data for the dashboard chart.

### VAT + SARS compliance
- `vat201Service.ts` — VAT201 return builder (preparer + validator).
- `vatReturnService.ts` — `getVATReturn(companyId, periodStart, periodEnd)` — compute output/input boxes + totals. Read-only.
- `vatSubmissionService.ts` — **`submitVATReturn`** posts the clearing journal (DR 2120 VAT Output / CR 1140 VAT Input / net → 2130 Accrued Exp payable, flip to DR on refund). Inserts into `vat_returns` table (mig 402, UNIQUE per period). `listVATReturns`.
- `vatAdjustmentService.ts` — manual adjustments outside the auto-generated return.
- `drcVatService.ts` — domestic reverse charge VAT (construction sector special rules).
- `sarsService.ts` — central SARS entry point (top-level orchestration).
- `sarsEfilingService.ts` — SARS eFiling HTTP adapter (uses tenant credentials).
- `sarsComplianceService.ts` — high-level compliance overview: what's due, what's submitted.
- `sarsTaxPeriodsService.ts` — period registration + period roll.
- `taxDirectiveService.ts` — tax directive handling (severance packages, etc.).
- `irp5Service.ts` — IRP5 certificate generator for payroll year-end.

### Consolidation (group reporting)
- `consolidationService.ts` — parent: drives the consolidation run.
- `consolidatedTrialBalanceService.ts` — consolidated TB with elimination journals.
- `consolidatedStatementsService.ts` — consolidated BS + IS + CF.
- `consolidatedReportingService.ts` — high-level report pack builder for the group.
- `consolidationTypes.ts` — DTO types.
- `intercompanyService.ts` — intercompany balance matching + eliminations.

### KPIs + trend analysis
- `kpiService.ts` — top-level: list + compute KPIs.
- `kpiDashboardService.ts` — dashboard-specific assembly (widgets + layouts).
- `kpiChartsService.ts` — chart-ready datasets.
- `kpiScorecardService.ts` — scorecard (in this module + duplicate in `afs/`; see gotchas).
- `ratioTrendService.ts` — multi-period financial ratios with trend lines.
- `trendAnalysisService.ts` — generic trend engine (any metric over time).

### Other reports
- `beeComplianceService.ts` — BEE / B-BBEE scorecard (employment equity, procurement, skills).
- `projectAccountingService.ts` — project P&L (used by practice / construction tenants).
- `projectProfitabilityService.ts` — project margin analysis.
- `timeTrackingReportService.ts` — time entries rolled up by staff / client / job.
- `customReportService.ts` + `customReportRunner.ts` + `customReportFieldDefs.ts` — user-defined reports over any table.
- `casewareExportService.ts` — Caseware-compatible export from reports side (sibling to AFS export).
- `statutoryDocService.ts` — statutory documents (share register, company info, etc.).

### AI + commentary
- `aiCommentaryService.ts` — general-purpose AI commentary helper.
- `reportNarrativeService.ts` — narrative intros for reports (separate from AFS note AI).

## Multi-tenant rules
Every query scopes by `company_id`. **Consolidation** is the exception: the parent company queries child `company_id`s it is authorised to see via `company_hierarchy` — audit this logic carefully when changing it because it's the one place where a legitimate cross-tenant read happens. `intercompanyService` must verify both legs' `company_id` belong to the same group.

## Key tables
- `company_hierarchy` — consolidation permissions.
- `account_reporting_groups` — custom account roll-ups.
- `vat_returns` (mig 402 — one row per submitted period with journal_entry_id FK), `vat_adjustments`, `vat_periods` — VAT state.
- `sars_submissions`, `sars_tax_periods`, `sars_efiling_credentials` — SARS integration.
- `irp5_certificates`, `tax_directives` — payroll year-end.
- `cashflow_forecasts`, `cashflow_scenarios` — forecast state.
- `kpi_definitions`, `kpi_dashboards`, `kpi_values` — KPI engine.
- `custom_reports`, `custom_report_fields` — user-defined reports.
- `bee_scorecards`, `bee_evidence` — BEE.
- `project_profit_data` — project accounting (also read by practice services).

## Gotchas
- **`kpiScorecardService.ts` is duplicated** — there's one here AND one in `afs/`. They share state via the `kpi_dashboards` table. Diverging behaviour = bug.
- **Consolidation is authoritative, not synced** — changes to child `gl_journal_entries` don't auto-propagate; consolidation must be re-run. `consolidatedTrialBalanceService` reads directly, no cache.
- **SARS e-filing credentials are encrypted** — `sarsEfilingService` decrypts on read via `@/lib/encryption`. Never log the decrypted value.
- **`customReportRunner.ts` is SQL-constructed at runtime** — it uses `customReportFieldDefs.ts` as an allowlist; adding fields outside that allowlist opens a SQL injection hole. Treat the allowlist as security-critical.
- **`drcVatService` applies on a per-line-item basis** — domestic reverse charge is not all-or-nothing per invoice. Each line can be DRC or standard. Violating this misreports VAT to SARS.
- **`threeWayForecastService` uses the cashflow forecast as the source of truth** — changes to assumptions there propagate to the BS + IS. Don't double-compute.
- **`reportNarrativeService` sends company data to an LLM** — tenant data leaves the boundary. POPIA-sensitive columns (names, IDs) are scrubbed before send; audit this if you add a new field to the prompt.
- **BEE scorecard formulas change annually** — `beeComplianceService.ts` is version-pinned via `bee_scorecard_version`. Check the current DTI gazette before changing weights.
- **`vat_returns` needs an explicit GRANT for app_user** — mig 402 was initially deployed without grants and the submit API 500'd with "permission denied". Always include grants in migrations for new tables.
- **`auto_vat_submission`** is a valid value in the `gl_journal_entries.source` CHECK constraint — added together with mig 402. The `GLEntrySource` TS union in `gl.types.ts` must stay in sync.
