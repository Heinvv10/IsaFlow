## Caller contract
Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/reports/*`, `pages/api/accounting/vat/*`, `pages/api/accounting/sars/*`, `pages/api/accounting/kpi/*`. Every public function takes `companyId` first. Services are predominantly read-only over GL; VAT/SARS submission services write back (`vat_submissions`, `sars_efiling_logs`, etc.).

## Main function signatures
- `getBalanceSheet(companyId, asOfDate, opts?)` / `getIncomeStatement(companyId, periodStart, periodEnd, opts?)`.
- `getVATReturn(companyId, periodStart, periodEnd)` — VAT201 box breakdown from GL lines.
- `generateForecast(companyId, horizonWeeks, opts)` / `getHistoricalForChart(companyId, months=6)`.
- `getConsolidatedTrialBalance(parentCompanyId, periodEnd)`; `getGroupCompanies(companyId)`; `createCompanyRelationship(...)`.
- `getTemplates(companyId, userId) / saveTemplate(...) / runReport(companyId, templateId, params)`.
- `getKpiDashboard(companyId, period)`; `getKpiCharts(companyId, metric, range)`.

## Business rules
- All queries scope by `company_id`; trial-balance-derived reports filter both `je.company_id` AND `jl.company_id` (mig 329).
- VAT return uses GL journal lines tagged with `vat_code` + `vat_amount`; don't double-count by joining `customer_invoices` or `supplier_invoices`.
- Consolidation: eliminations scoped to parent company; intercompany balances removed via `intercompanyService` before roll-up.
- Custom reports: `customReportRunner` compiles user-defined field defs into parameterised SQL — all params bound, no interpolation.
- Facade files (`sarsService`, `kpiService`) re-export; add logic to the split services.
- Date handling: pg returns `Date` objects from timestamp columns — all report formatters accept both `Date` and ISO string.
