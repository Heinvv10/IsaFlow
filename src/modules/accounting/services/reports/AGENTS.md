Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/reports/*`, `pages/api/accounting/vat/*`, `pages/api/accounting/sars/*`, `pages/api/accounting/kpi/*`. ## Business rules
- All queries scope by `company_id`; trial-balance-derived reports filter both `je.company_id` AND `jl.company_id` (mig 329).
- VAT return uses GL journal lines tagged with `vat_code` + `vat_amount`; don't double-count by joining `customer_invoices` or `supplier_invoices`.
- Consolidation: eliminations scoped to parent company; intercompany balances removed via `intercompanyService` before roll-up.
- **Group listing must use `listGroupsForUser(userId)`, never `listGroups()`** — the latter is unscoped and returns every tenant's groups. `listGroupsForUser` admits a group when the caller belongs to a member company **OR** created it; the creator clause exists because a group created without a holding company has no members, and an INNER JOIN made it invisible to its own creator — permanently orphaned, only fixable by direct DB access. `createGroup` does auto-enrol a holding company as the first member, so the orphan only occurs when that optional field is left empty.
- Custom reports: `customReportRunner` compiles user-defined field defs into parameterised SQL — all params bound, no interpolation.
- **A bank account is a `gl_accounts` row with `account_subtype='bank'`, never a `bank_accounts` row.** `bank_transactions.bank_account_id` FKs to `gl_accounts(id)`; `bank_accounts` is vestigial metadata (0 rows in production). Cash = `SUM(bank_transactions.amount)` over active bank-subtype GL accounts.
- **Outstanding AR/AP is `total_amount - COALESCE(amount_paid,0)`.** There is no `balance_due` column on either invoice table. Always gate on the shared `AR_OPEN_STATUSES` / `AP_OPEN_STATUSES` from `@/lib/constants/invoiceStatuses` — `'partial'` is not a legal status on either table, and `supplier_invoices` has no `'overdue'`.
- **As at any date but today, outstanding comes from the aged report (R-059).** `total_amount - amount_paid` over the open statuses is TODAY's figure: it nets settlement made since and drops what was settled since. A year-end note, a period report's outstanding column or an integrity check's `as_at` takes the ageing's population and `shared/agingRewind`, or sums `getARAging`/`getAPAging` through `agedBucketTotals.ts`.
- **`approveVATAdjustment` holds the adjustment row `FOR UPDATE` (5s bound) and refuses before any write** (`VatAdjustmentRefusal`: `not_found` 404, `not_draft` 400, `contended` 503 + Retry-After, D11); the journal create + post + stamp run in ONE `withSavepoint`, because `postJournalEntry` refuses a closed period only after the draft exists and the route's 400 is COMMITted by `withAuth` (R-051). Needs a request transaction. `cancelVATAdjustment` takes the same bounded wait and the same typed refusals. The route maps contention and a 23505 on `uq_gl_je_company_entry_number` to 409.
- **Statutory AFS deadline is the LAST DAY of the sixth month after year end** — the rule is `afs/afsFilingDeadline.ts` (`afsFilingDeadline`, `wholeDaysBetween`, `FilingDeadlineUnknownError`), shared with `afs/complianceAlertService`; never `setMonth(+6)`, never a March fallback. `statutoryFilingsService` lists what was outstanding as at the PACK date (whole calendar days): a signed-off AFS counts as outstanding if its `locked_at` (SAST day) is after that date; a signed-off row with no `locked_at`, and a row with no fiscal year, stay out. Only AFS is tracked; no CIPC/VAT/EMP due dates are invented. Run against real rows by `tests/integration/statutory-filings-as-at.int.test.ts`.
- **`unusualJournalsService` flags posted journals only** (round-number amounts — on every source except postings generated from documents, classified per source in `journalSourceKinds.ts` (a `Record<GLEntrySource, …>`; recurring, GL import, VAT adjustment and opening balances count as keyed in) — and journals recorded more than 5 days after their date — except on a bulk-load day, a SAST day on which the company recorded `BULK_LOAD_MIN` (10) or more backdated journals, e.g. Velocity's Sept 2026 reload; those are counted — with the oldest date they carry — and raised as ONE matter on pages 4 and 11 by `packBulkLoadedJournals.bulkLoadedMatter`, never dropped), scoped on both `je.company_id` and `jl.company_id`, and its `ORDER BY` ends in `je.id` (`entry_number` is nullable) so equal-exposure journals print in a stable order.
- **`reportPackDataService` reads the three pack cash flows from `afs/cashFlowDirectService.getCashFlowDirect`** in its own savepoint (`pack_cash_flows`); only a failed read degrades (`cashFlowUnavailable` set, the three fields unset), a defect re-throws. `investingCashFlow` is NET investing; operating takes the rounded net movement less investing and financing so the three foot to the cent. `capitalExpenditure` stays unpopulated. Run against real journals by `tests/integration/report-pack-cash-flows.int.test.ts`.
- **A ratio is `number | null`, and null means not meaningful, never zero** (`ratioTypes.ts`, `ratioCalculations.ts`; `reportingEngineService` re-exports). The engine states a ratio only on a POSITIVE base and from inputs that were supplied; otherwise it is null with its reason in `notMeaningful` under the same key (`ratioBasis.ts`). So a margin on non-positive revenue, a liquidity ratio with no current liabilities, free cash flow with no capex, interest cover with no interest expense are all null. **A reason must be TRUE of the caller, so an absent input has two**: `notCaptured` — the input is `undefined`, this report never read it ("Interest expense is not captured in this report") — and `noneRecorded` — it was read and is nil ("No interest expense recorded in the period"). Never say "none recorded" of a figure the report did not read; an absent dividend is not a nil dividend (retention rate is null, not 100%). Net interest that is income says so (`NET_INTEREST_IS_INCOME`). **Cost of sales is a base**: creditor days and inventory days are measured against it, so a company with NO cost of sales (a pure service company) has no creditor days, no inventory days and therefore no cash conversion cycle — each null with its reason; with positive cost of sales and no stock, inventory days is 0 and the cycle is stated. **A loss** (net profit or profit before tax not positive) has no retention rate and no effective tax rate. The three Financial Analysis endpoints (`reports-kpi-scorecard`, `reports-extended-ratios`, `reports-ratio-trends`) take their input from ONE read, `extendedRatioInputs.readExtendedRatioInputs`, so the scorecard and the ratio list cannot disagree. **The report pack reads the same inputs**: `readReportPackInput` calls `readLedgerRatioInputs` (the same read without the figures, which it already has) in savepoint `pack_ratio_inputs`. A failed read (`isFailedRead`) supplies none of the five and sets `ratioInputsUnavailable`, which the engine gives as the reason (`FinancialData.ledgerInputsNotRead`) instead of `notCaptured`; anything else is re-thrown. The BOARD pack passes them on too (`packFiguresToFinancialData`, since 4b472e66e): page 9's Interest cover row is the engine's. A unit test that reaches `readReportPackInput` without mocking `@/lib/neon` or `extendedRatioInputs` sends these queries to whatever database the environment names — stand the reader in. Every consumer prints the reason: never `?? 0`, never `.toFixed()` on the value. `packRatios` is the engine's result.
- **A ratio input is a LINE OF THE INCOME STATEMENT, by the statement's classifier** (`ledgerRatioLines.ts`, folded from the same `account_type, account_subtype` movement `getFinancialFigures` reads; account type FIRST — a liability with subtype `tax` is a VAT control account). **Interest expense** = the `finance_cost` band WITHOUT `bank_charges` (the vocabulary aliases bank charges into the band; read whole, a debt-free company with bank fees printed a cover in the hundreds). The generic `finance_cost` spelling counts as interest: the seeded chart's "Interest Expense" account carries it and its bank charges are an operating expense; a new non-interest spelling aliased into the band goes in `NOT_INTEREST`. Residual risk, accepted: fees posted to a generic `finance_cost` account are read as interest (cover understated), and interest booked to an operating-expense account is not read at all — which is why nil says "No interest expense under a finance-cost classification recorded in the period", not "none recorded". **Interest income** = raw `interest_income` on a REVENUE account (the vocabulary has no such band; it is a sub-line of whichever revenue band the statement uses). **Tax** = the `tax_expense` band on expense accounts. **Employee cost** = the `payroll_expense` band only — `uif`, `medical_aid`, `provident_fund`, `leave_pay`, `bonuses` are not in the vocabulary and are NOT added by hand; nil says "No employee cost under a payroll classification recorded", because salaries in a general operating-expense account are not "none". **Direct materials**: no such line (`raw_materials` is an inventory asset subtype), so nothing supplies `directMaterialCosts` and the margin is "not captured". Do not add a subtype list here; extend the vocabulary.
- **Profit before tax is the statement's: net profit + tax expense** — never `ebit − interest + interest income` (interest income is already above the operating line; bank charges and other expenses are below it). No tax figure → no PBT → effective tax rate and PBT-to-net-interest are not stated. Nil tax on a positive PBT IS stated, 0.0% (a rate of nil is a fact); nil interest is NOT a cover (nothing to cover: "none recorded"); a net CREDIT to interest says so (`INTEREST_IS_NET_CREDIT`).
- **Head count is as at the window END** (`readHeadCounts`): `start_date <= end` and (`end_date > end`, or no end date and `status = 'active'`) — an inactive or terminated row with no end date is counted on no date. Per window: the comparative and each trend month get their own, and ratio trends reads all its month ends in ONE query. Not an average over the period; per-employee ratios divide the whole period by closing staff. Dividends and capex are still read by nobody.
- **A reason agrees with its subject**: `notPositive` says "are" for the plural bases (`PLURAL_BASES`: total assets, current liabilities, net operating assets, accounts receivable/payable) — add a new plural base there.
- **Revenue on top is still a revenue base.** Every ratio with revenue as numerator OR denominator is not stated on non-positive revenue, revenue checked first: the margins, debtor days, the turnovers (asset, receivables, net operating asset, DuPont) and the per-head figures (revenue, PBIT and EBITDA per employee — profit per head follows the margins; on positive revenue a negative one is stated). The cost-of-sales turnovers (inventory, payables) follow creditor and inventory days. **No inventory classification** (`inventoryClassified` false, carried into `FinancialData` by `readReportPackInput` and `readExtendedRatioInputs`): inventory days, inventory turnover, the quick ratio (nothing established to take off current assets; the board publishes no acid test) and the cash conversion cycle are not stated (`NO_INVENTORY_CLASSIFIED`, and for the cycle the board pack's own sentence `NO_INVENTORY_CLASSIFIED_CYCLE`) — nil stock on a chart with no inventory account is not established. **Inventory pair** (classified): positive cost of sales and no stock → inventory days 0 (base cost of sales, defined; the cycle stands on it) and inventory turnover not stated with `NO_STOCK_HELD`, which says inventory days are nil; negative inventory → both "Inventory is not positive".
- **Prose and tiles use the pack's formatters.** The legacy commentary writes money with `formatStatementFigure({ cents, symbol, pack })` via `inProse`, and a margin as its own sentence through `pctWithWord` ("Net profit margin is a negative 1 522.9%"); none on non-positive revenue. A KPI tile's value AND target go through `formatRatioOf(key, n)` (`scorecardFigure`, read by the pack screen, print view, deck, the legacy PDF/HTML packs, and the KPI tiles on Executive Dashboard and Financial Analysis). A percentage in prose that ROUNDS to 0.0% has no direction: pass `pctWithWord` its nil words (4th argument, e.g. 'nil') and it returns them instead of "a positive 0.0%" / "a negative 0.0%". Opt-in: the board pack's sentences pass none and are unchanged. The executive summary, the AI commentary risk sentences and the legacy pack commentary pass 'nil'.
- **One name and one unit per ratio: `ratioPresentation.ts`** (`ratioLabel`, `RATIO_FORMATS`, `formatRatioFigure`, `ratioLine`, `ratioLines`). `pct` margins/returns — LEVELS, printed unsigned by `formatPctLevel` ("45.0%", never "+45.0%"; the sign is for changes) — `times` for EVERY multiple, × always (covers, turnovers, current/quick/cash/operating-cash-flow ratio, debt ratio, debt to equity: "(0.14)×"; no ratio key uses bare `ratio`), `days`, `currency` for a per-head amount (money WITH the symbol: "R 10 140.00") and `money` for a statement amount (EBITDA, working capital, free cash flow: unsymbolled, as the statement tables). A KPI target is written in its value's unit ("(0.14)× / 1.50×"). An unknown key throws `UnknownRatioError` naming it (labels, lines, the pack document, KPI targets): a ratio added to the engine without an entry here must not print unlabelled or drop out. Read by `packs/packDocument`, the PDF/HTML packs (`packUnstatedRows.ratioPackRows`), `kpiScorecardService` and the Financial Analysis page. Never split a key on capitals or `toFixed(2)` a ratio.
- **`buildReportPack` passes `depreciation` to the engine**, so the management pack's EBITDA equals the board pack's (`reportPackEbitda.test.ts`).
- **The `cash_flow` section carries an `unavailable` map** (per line, plus `netCashFlow`/`openingCash` when any line is unread) and `ratios` a `notMeaningful` map. Renderers print the reason, never the stand-in; `packUnstatedRows.ts` is the one reading (a row has a figure or a reason, never both nor neither).
- **`buildProfitWaterfall` returns `{ steps, omitted }`.** `omitted` holds the nil movement lines and, when the walk disagrees with the classifier, the `Operating Profit` subtotal it refused; the walk draws an Operating Profit subtotal where it lands on the classifier's figure. The nil-movement rule lives in the builder so every caller applies it.
- **Home's AR/AP figures are ONE read: `dashboardOpenBook.getOpenBook(companyId, side, todayStr)`** (`todayStr` = `todayInSast()`, never `CURRENT_DATE`). It runs the aging report's own population (`ar/arAgingInvoices`, `ap/apAgingInvoices`) through `calculateAgingBuckets` and returns `{ buckets, total, overdue, overdueDisputed }`. The donut (`getAgingBreakdown`, five age buckets plus Disputed) and the Receivables/Payables tiles (`getDashboardKPIs`) take the SAME object: the kpi-dashboard route reads each side once and passes it to both (`getDashboardKPIs(…, books)`, `getAgingBreakdown(…, book)`); called without it each reads for itself. Disputed amounts leave their age bucket on Home and stay inside it on the AR/AP Age Analysis report, so a bucket here plus its disputed share is the report's; the legend caption says so. The Overdue tile is the report's overdue (disputed included): overdue donut slices + `overdueDisputed` = `overdue`, and the tile prints "of which R x disputed". An invoice whose `client_id` points at no customer row stays in (LEFT JOIN, "Unknown customer"), because the report's summary reads `customer_invoices` alone; `getARAgingDetail` answers for that id with those invoices (not found only when there is no customer and no open invoice). Not netted, by decision pending with the owner: unallocated credit notes and overpayments. `getDashboardKPIs` also returns `revenueMtd`, posted revenue from the 1st of the SAST month to `todayStr` (the `revenue` tile spans the ~13-month window). Both are TURNOVER as the income statement's Revenue line: revenue-type rows are read per subtype and banded with `revenueBand`, so other income (aliases included) is left out; the profit tiles still sum every revenue-type account, as the statement's net profit does. The dashboard's profit tile is `kpis.netProfit` (revenue-type accounts less all expenses = the statement's Net Profit; margin over turnover, `null` (drawn "—") unless turnover is positive: Home does NOT pass `allowNegativeRevenue` as the statement does, because +150% beside a loss misleads on a tile); there is no `grossProfit` on it. `getRevenueChart(companyId, months, todayStr)` draws signed turnover per month (same banding, bounded by the SAST today, never `Math.abs`), so the current bar equals Revenue MTD. Run against `getIncomeStatement` by `tests/integration/home-revenue-equals-income-statement.int.test.ts`.
- Facade files (`sarsService`, `kpiService`) re-export; add logic to the split services.
- Date handling: pg returns `Date` objects from timestamp columns — all report formatters accept both `Date` and ISO string.
- **The indirect cash flow statement is ONE service: `cashFlowIndirectService.getIndirectCashFlow(companyId, start, end)`** (the Reports screen `reports-cash-flow` and `cash-flow-export` both read it). Opening cash is `cash.balance.v1`; the movement is the credit-less-debit of every posted non-cash line (year-end journal excluded), each account classified ONCE by `cashFlowIndirectClassification.classifyIndirectLine` (net income; receivable, payable, VAT control, inventory, accumulated-depreciation add-back, other operating; investing; equity, loans, retained earnings movements). A journal balances, so on sound books closing cash equals the ledger cash, and when it does not the `Unexplained Difference` section says by how much; `cashFlowIndirectClassification.test.ts` walks the whole subtype vocabulary and `cash-flow-indirect-ties-to-cash.int.test.ts` holds the tie-out. A new account kind must land in a bucket, never fall through. Only the cash a journal moved is an investing or financing flow (`placeJournal`, per journal, from its net movement on its cash accounts): the rest of those legs lands in operating `non_cash` ("Non-cash Investing and Financing Items"), so an asset bought on a loan nets to nothing, one bought on account is payables +X, non-cash -X, and a R10 000 asset on R2 000 cash and an R8 000 loan is investing -2 000 and nothing else (a disposal is investing for the proceeds alone). Operating legs keep their lines; those running the same way as the cash take it first (input VAT paid in cash). Legs competing for too little cash share it pro rata. Limit: a journal that batches unrelated items is netted as one, since a journal does not say which cash paid for which leg. **The current portion of debt is a loan** (financing; a repayment, not "other operating"): `current_liability` alone cannot say so, since ordinary current liabilities carry it too, so the query flags the seeded system account (`SEEDED_CURRENT_PORTION_CODE` 2215, `is_system_account`, `current_liability`: an imported chart's own 2215 is not one) and any account a loan names (`loans.current_portion_account_id`); the flag only lifts a liability with no line of its own, so a loan pointed at a trade payable leaves it in payables. The direct method (`afs/cashFlowClassification`) has no such flag: these repayments stay operating there, so the two methods' section totals differ for them; their net change does not. Tests: `cash-flow-indirect-mixed-journals.int.test.ts`. 2026-11-05: the old inline calculation had no VAT, inventory, prepayment, payroll, depreciation, loan or retained-earnings lines (closing cash 287 750 against the ledger's 287 900 after a R1 150 cash sale).

## Pulling the GL export with a Personal Access Token

`/api/accounting/gl-lines-export` accepts a Bearer token as well as a browser session (`withBearerOrCookieAuth` + `withScope('read:reports')`), so an external system (FibreFlow) can pull it on a schedule:

1. Create the token in **Settings → Personal Access Tokens** (`/developer/personal-tokens`) with scope `read:reports`; add `read:contacts` only if you need `table=counterparties` (names and VAT numbers) and `read:bank-tx` only if you need `table=bank_accounts` (statement, reconciliation and feed facts). The token is bound to the company it was created in.
2. Send `Authorization: Bearer pat_…` on a GET, e.g. `curl -H "Authorization: Bearer $ISAFLOW_PAT" "https://app.isaflow.co.za/api/accounting/gl-lines-export?table=ap_open_items" -o ap_open_items.csv`.
3. Read the facts from the headers (`X-Control-Total`; for the open items `X-Aged-Total`, `X-Control-Difference` — an internal consistency check, 0.00, NOT a tie to the GL control account — and `X-Disputed-Total`; for bank accounts `X-No-Ledger-Balance-Count`), or call with `manifest=1` for the JSON summary first. The computed tables are as at today and refuse `date_from` / `date_to` / `status` (400).

A token without `read:reports` gets 403 `INSUFFICIENT_SCOPE`; `counterparties` without `read:contacts`, and `bank_accounts` without `read:bank-tx`, likewise (the MCP tool's rule, from the one map `GL_EXPORT_EXTRA_SCOPE`). The per-company rate limits apply to token calls exactly as to sessions. Full reference: `docs/api/gl-lines-export.md`.

functions, `expenseBand` and `revenueBand`. Turnover, other income, cost of
sales, operating expenses, other expenses, gross profit, operating profit and
net profit agree to the cent, and `incomeStatementConvergence.test.ts` asserts
every band — so a future edit to either side fails rather than silently
re-diverging.

**Do not re-implement either layering locally.** They previously diverged: the
page counted other income as turnover and put finance cost and tax inside
operating expenses, so it reported a different GROSS profit while the registry
claimed the two agreed to the cent — true of net profit, false of gross, and
nothing tested it. That was finding B75.

The operating line is the one finance cost and tax sit BELOW: other income is
ABOVE it. `aggregateFigures.operatingProfit` is the single definition; the
`profit_and_loss` tool reads that field rather than recomputing it, because a
local copy of the formula is exactly how the first divergence happened.

Consumers that render this shape must show every band or their statement stops
footing. **Seven surfaces do**: the income-statement page
(`components/accounting/IncomeStatementSections`), the management pack
(`components/accounting/ManagementPandLRows`), the CSV and XLSX exports,
`components/accounting/afs/AfsStatementsTab`, and the report pack's HTML and PDF
renderers (`reports-html.ts` / `reports-pdf.ts`, fed by `reportPackService`).

**Finding them all took three review rounds, and the misses rhymed.** AFS is not
in `services/afs/` — it is a component — so grepping that directory says AFS is
unaffected when it is not. The report pack renders from `ReportPackInput`, whose
optional `otherIncome`/`otherExpenses` `getReportPackInput` simply never
populated, so the pack's P&L was short by `otherIncome - otherExpenses` and
`buildProfitWaterfall` suppressed both its steps on every pack ever produced.
When this shape changes, grep for the CONSUMERS of the figures — `grossProfit`,
`totalRevenue`, `netProfit` — across `src/` and `pages/`, not for a directory
name.

Every surface is pinned by a test, though not all in the same way, and the
distinction matters when you add one:

- **Rendered components** — the page, the management pack and the AFS tab — have

  `vitest.config.ts` loads `@vitejs/plugin-react`; `tsconfig`'s
  `jsx: "preserve"` otherwise makes any `.tsx` unimportable from a test, which
  is why a whole section could vanish from a statutory statement with the full
  suite green. Importing a PAGE still fails on Next's font loader, so the

  table cell, so `renderSectionHtml` and `renderSection` are exported and their

- **The CSV and XLSX exports** are tested through their handler and workbook
  builder (`incomeStatementExportDisclosure.test.ts`,

- **The data behind the packs** is pinned at `getReportPackInput`'s own boundary
  (`reportPackInputCarry.test.ts`) — asserting `toFinancialData` instead left
  the carry mutations green, because that is not the function that drops them.

`classificationCoverageService` is what makes either safe to read. Every band is
chosen from `account_subtype`, and on these books the subtypes barely exist —
100% of Velocity Fibre's revenue and 97.6% of its expenses are on unclassified
accounts. `profit_and_loss` reports it at every detail level and it is not
suppressible.

`priorPeriod.ts` owns the comparative window. Pure, `'YYYY-MM-DD'` in and out,
constructs no `Date`. The income-statement PAGE still computes its own in
milliseconds and compares March against 29 January – 28 February; that fix
belongs with the convergence PR.

## `trendRowsService` duplicates the balance sheet's shape rules

`getMonthlyBalances` re-implements two rules `balanceSheetService` already
owns: the signing convention (by SECTION: assets debit − credit, liabilities
and equity credit − debit, so every contra account subtracts) and the leaf
filter (`level >= 3 OR no children`). They are copies, not a shared helper, so
a change to one is silently a divergence.

What keeps them honest today is `tests/integration/accountTrends.int.test.ts`,
which foots the series against `getBalanceSheet` itself rather than against a
SUM written in the test: the last month must equal the printed balance at
as-of, and month 6 the printed balance at that month end, for every line on
both tenants. Mutating either rule in the service turns both red — EXCEPT for
contra equity/liability accounts, which neither tenant holds: those are footed
by `accountTrendsContraAccounts.int.test.ts` against any company in the
database that has one (2026-10-07, PR #662: the balance sheet had added
Dividends Declared to equity, and the trend copied the same sign).

Know how that test reaches you. It reads the real tenants in isaflow_dev. The
FILE refuses to skip by hand: with no real `DATABASE_URL` its `beforeAll`
throws and the suite fails rather than reporting green on nothing. It skips in
one place only, `bun run ci`'s integration step (`scripts/ci/integration/run.sh`;
on GitHub, or locally with `CI_INTEGRATION=1`; `CI_INTEGRATION_GATE=1`,
`tests/helpers/integrationGate.ts`), whose disposable databases hold no
tenants; the step prints it by name with the reason from its
`ci-integration-skip:` comment. Against dev it has to be asked for:

```bash
DATABASE_URL=<isaflow_dev URL> node_modules/.bin/vitest run --config vitest.integration.config.ts tests/integration/accountTrends.int.test.ts
```
