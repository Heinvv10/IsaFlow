# payroll/

South African payroll: PAYE, UIF, SDL, ETI + run lifecycle, leave, termination/IRP5 prep, tax directives, UIF declarations. Pure engines have no DB; DB services are all company-scoped.

## Modules
- **Pure engines (no DB)**: `payrollTypes.ts`, `taxTables.ts` (TAX_2025/2026; SA tax year ends Feb → March N ⇒ tax year N+1), `payeEngine.ts` (annual→rebates→medical credits→monthly), `uifEngine.ts` (1%+1%, capped at ceiling), `sdlEngine.ts` (1% leviable; exempt <= R500 000 annual remuneration), `etiEngine.ts` (18–35, non-UIF-excluded, ≤24m employed), `payrollCalculator.ts` (`calculatePayrollLine` orchestrator), `validationEngine.ts`, `irp5ValidationEngine.ts`, `payrollJournalSplitBuilder.ts`.
- **Run lifecycle**: `payrollRunService.ts` (CRUD + `calculatePayrollRun` populates lines), `payrollRunLock.ts` (period lock), `sdlLeviabilityService.ts` (SDL threshold basis), `payrollApprovalService.ts` (`approvePayrollRun` → approved + posts JE), `payrollJournalPostingService.ts` (`postPayrollRunJournal` / `reversePayrollRunJournal`), `payrollBatchService.ts`, `payrollBulkEmployeeService.ts`.
- **Employees + history**: `payrollEmployeeService.ts`, `payrollEmployeeComponentService.ts`, `payrollEmployeeHistoryService.ts`, `payrollComponentService.ts`, `payPackageService.ts`, `payScaleService.ts`, `sarsCodesService.ts`.
- **Leave**: `payrollLeaveService.ts`, `leaveAccrualService.ts` (pure BCEA accrual), `payrollTerminationService.ts`.
- **Statutory**: `uifDeclarationService.ts` (UI-19 + `markUifDeclarationPaid`: DR 2150 / CR 1110), `taxDirectiveService.ts`, `taxDirectivePaymentService.ts` (`applyTaxDirective`: DR 5200 / CR 2140 / CR 1110), `easyFileExportService.ts` (e@syFile EMP501 CSV).
- **Loans / costing**: `payrollLoanService.ts`, `payrollCostAllocationService.ts`, `costCentreGlMappingService.ts`, `costCentreService.ts`, `cashPayRegisterService.ts`.
- **Variance / duplicates / training / equity**: `payrollVarianceService.ts`, `payrollDuplicateDetectionService.ts`, `trainingEventService.ts`, `equityReportService.ts`.
- **Parallel-run comparison (Dotbiz Workstream C)**: `payrollParallelRunTypes.ts`, `payrollExternalCsvParser.ts` (pure; SA number formats → integer cents), `payrollParallelRunComparator.ts` (pure; IsaFlow run vs imported external payslips, per-employee per-component cent diffs), `payrollParallelRunCsv.ts` (pure CSV render), `payrollExternalImportService.ts` (DB; mig 495), `payrollParallelRunReportService.ts` (DB; assembles report).

## Caller contract
Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/payroll/*`. Every DB function takes `companyId` first. Pure engines accept plain typed inputs and return plain results.

## Main function signatures
- `createPayrollRun(companyId, input) / getPayrollRun(companyId, id) / calculatePayrollRun(runId, companyId)`.
- `approvePayrollRun(companyId, runId, userId)` — status `draft|calculated|processed → approved`, posts JE, links `payroll_run_headers.journal_entry_id`.
- `postPayrollRunJournal(companyId, runId, userId)` — DR 5200 Labour = gross + (total_uif÷2) + sdl − eti; CR 2140 PAYE; CR 2150 UIF (employee+employer combined); CR 2160 SDL; CR 1110 Bank (net).
- `calculatePayrollLine(input): PayrollLineResult` — pure orchestrator.
- `markUifDeclarationPaid(companyId, declarationId, userId)` — idempotent (returns existing row when already paid).
- `applyTaxDirective(companyId, directiveId, input)` — one payment per directive.
- `computeExpectedAccrual(input): number`, `computeCarryOver(balance, maxCarryOver)` — pure leave helpers.
- `parseExternalPayslipCsv(csv): ExternalCsvParseResult` — pure; header aliases (VIP/Sage), comma/semicolon, SA amount formats; integer cents out.
- `compareParallelRun(isaflowLines, externalRows, opts?): ParallelRunComparisonReport` — pure; employee-number matching is trim/case/zero-pad-insensitive (numeric only); `uifTotal` compares vs ee+er sum; only components present in the external data are compared.
- `getParallelRunReport(companyId, importId, runId?)` — resolves the run by the import's period when runId omitted; `run`/`comparison` null when no run exists.

## Business rules
- Run state: `draft → calculated → processed → approved`. Re-approve is allowed when `status=approved` but journal unposted (2026-04-24 fix).
- JE posting: do NOT include `runId` inside `sourceDocumentId` (2026-04-24 fix — FK is to `documents`).
- Leave accrual INSERTs supply `company_id` for RLS (2026-04-24 fix); EXCLUDED out of scope in RETURNING clause (same-day fix).
- Employee active-check uses `payroll_employees.status`, NOT `is_active` column (2026-04-24 fix).
- VIP-parity foundations (2026-04-24): SARS codes table, bureau mode, period lock, variance engine.
- Cash-pay register, IRP5 certificate validation, e@syFile EMP501 CSV — SARS compliance export paths.
- `payrollRunLock`: once locked, period rejects new runs and edits.
- SDL leviability is an EMPLOYER test, not a per-line one: section 4(b) exempts total remuneration <= R500 000 over twelve months. `estimateAnnualRemuneration` bases it on the company's own trailing twelve periods (the eleven `calculated|approved|paid` runs before this one plus this run) using GROSS pay, divided by ELAPSED CALENDAR MONTHS since the company's first run, capped at 12 — so a seasonal employer's unpaid months count as zero and only a company younger than a year extrapolates; the 1% is then charged per line on `sdlLeviable` only. Never gate on the leviable subset — one component flagged `is_sdl_applicable = false` would exempt the whole employer.
- `calculatePayrollLine` takes `annualPayrollEstimate: number | 'defer'`; a run passes `'defer'` and sets `sdl` itself in the second pass.
