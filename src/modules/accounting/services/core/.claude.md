## Caller contract
Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/**`. Most functions take `companyId` first; exceptions: `companyService.listCompanies` (admin, returns all), `jobQueueService` (job rows carry their own `company_id`), `userInvitationService` (invitations are orgless at create time).

## Main function signatures
- `createCompany(input) / updateCompany(id, input)`; `createInvitation(companyId, email, role) / acceptInvitation(token)`.
- `logAudit({ companyId, entity, action, before?, after?, userId })` — never throws.
- `uploadDocument({ companyId, file, entityId?, entityType? })` — validates magic bytes, enforces entity ownership.
- `resolveAccountEvidence(companyId, accountId, period)` / `resolveJournalEntryEvidence(companyId, jeId)` — PRD-05 drill.

- `importLedgerTransactions(companyId, userId) / importSupplierInvoices(companyId, userId)` — Sage Phase 6 importers.

## Business rules
- **User identity is a STRING, never a uuid.** `users.id` is `character varying`; `company_users.user_id` is `text`. NEVER write `user_id = ${x}::UUID` or `users.id = ${x}::UUID` — Postgres has no `text = uuid` operator, so it throws at RUNTIME (500), and neither `tsc` nor eslint can see inside a SQL template string. When joining a uuid column onto `users.id`, cast the **uuid** side: `ON u.id = t.approved_by::TEXT`. `company_id` IS a uuid and keeps its cast. Guarded by `scripts/ci/audit-user-id-casts.ts` (static) + `tests/integration/user-id-join-compat.int.test.ts` (schema probe).
- **Tenant-membership guards live in `companyAccessService`** — `userBelongsToCompany` / `userBelongsToGroup`. Do not re-inline them into API routes; four routes each kept their own broken copy before this was extracted.
- `listCompanies` and other admin-only calls must NOT appear in tenant-scoped API paths — enforce via route selection.
- `logAudit` is fire-and-forget: callers don't await failure; service swallows its own errors to keep write-paths unblocked (but no empty `catch` — logs via `log`).
- `documentStorageService`: magic-byte check runs before S3 put; entity ownership verified against `companyId` before linking.
- `jobQueueService`: concurrent workers safe via `SELECT ... FOR UPDATE SKIP LOCKED`; lifecycle `pending → running → completed|failed`.
- PayFast ITN: validated via HMAC signature in `paymentGatewayCore`; idempotency via PayFast transaction id.
- Evidence graph is read-only — joins GL lines back to `captured_documents` / `extracted_data`.
- Sage import uses savepoints per record so one bad row doesn't roll back the whole run; dates coerced Date→ISO (2026-04-24 fix).

## Recent changes

- 2026-09-09: **A document the migration wizard imports is a TAKE-ON, not an origination** (audit K-015 / R-001, R-002, R-020). `importARInvoices` and `importAPInvoices` post ONE two-line entry at `total_amount - amount_paid` — DR the control account, CR `opening_balance_equity` (mirrored for AP) — and **no revenue, expense or VAT line at all**. `buildTakeOnLines` in `migrationPostingSupport` is the single place that shape is decided; a document settled in full before the cutover creates the document and posts nothing, leaving `gl_journal_entry_id` NULL. The deciding reason is VAT: `getVATReturn` is GL-based and sweeps every posted `vat_input`/`vat_output` line with a NULL `vat_type` into boxes 1 and 15, so posting the invoice in full re-declared its VAT in a period that is usually already filed. Lines that are never written need no filter. Consequences worth knowing: (a) every take-on file now needs an `opening_balance_equity` account on the chart — `resolveTakeOnClearingAccountId` refuses the step up front, once, naming the role and the remedy; (b) `subtotal + tax` no longer has to equal `total` to the cent — up to 5c imports with a warning (persisted on the session as an `errors` entry with `severity: 'warning'`, so it survives a reload), beyond that the row is refused; (c) the trial balance may carry an AR or AP control total **instead of** the documents (a summary-only take-on) but never as well — `importOpeningBalances` records which control totals it accepted in `steps_completed` (`opening_balances_ar_control` / `_ap_control`) and `assertNoOpeningControlTotal` refuses the matching document step, and vice versa. The refusal in that direction is gated on `{ar,ap}_invoices_imported > 0` — documents actually TAKEN ON — not on the step flag, which is written even by a run that imported nothing and would otherwise bar the summary-only route for good; (d) `completeSession` records, but does not enforce, the `opening_balance_equity` residual for entries posted since the session started — it is a warning, and the message says the residual is expected when the whole trial balance was balanced on that account rather than accusing the operator of a double count. Both document steps AND `importOpeningBalances` take `lockMigrationImport` (a transaction-scoped advisory lock keyed on the company) before reading the session: the interlock is a read-then-write both sides perform, and without it an overlapping pair each read a session without the other's mark and both post. The persisted `severity: 'warning'` entries are read back by the migration hub (`SessionIssues` on `pages/accounting/migration/index.tsx`), which is what makes the durability real. WIZARD PATH ONLY: the Sage commit path posts its own journals and still re-declares VAT.
