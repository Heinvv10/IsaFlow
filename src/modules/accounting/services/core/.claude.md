## Business rules
- **User identity is a STRING, never a uuid.** `users.id` is `character varying`; `company_users.user_id` is `text`. NEVER write `user_id = ${x}::UUID` or `users.id = ${x}::UUID` — Postgres has no `text = uuid` operator, so it throws at RUNTIME (500), and neither `tsc` nor eslint can see inside a SQL template string. When joining a uuid column onto `users.id`, cast the **uuid** side: `ON u.id = t.approved_by::TEXT`. `company_id` IS a uuid and keeps its cast. Guarded by `scripts/ci/audit-user-id-casts.ts` (static) + `tests/integration/user-id-join-compat.int.test.ts` (schema probe).
- **Tenant-membership guards live in `companyAccessService`** — `userBelongsToCompany` / `userBelongsToGroup`. Do not re-inline them into API routes; four routes each kept their own broken copy before this was extracted.
- `listCompanies` and other admin-only calls must NOT appear in tenant-scoped API paths — enforce via route selection.
- `logAudit` is fire-and-forget: callers don't await failure; service swallows its own errors to keep write-paths unblocked (but no empty `catch` — logs via `log`).
- `documentStorageService`: magic-byte check runs before S3 put; entity ownership verified against `companyId` before linking.
- `jobQueueService`: concurrent workers safe via `SELECT ... FOR UPDATE SKIP LOCKED`; lifecycle `pending → running → completed|failed`.
- PayFast ITN: validated via HMAC signature in `paymentGatewayCore`; idempotency via PayFast transaction id.
- Evidence graph is read-only — joins GL lines back to `captured_documents` / `extracted_data`.
- Sage import uses savepoints per record so one bad row doesn't roll back the whole run; dates coerced Date→ISO (2026-04-24 fix).
- **Migration opening balances are signed against the account's normal side.** In `ParsedAccount.openingBalance` a positive figure sits on the account's own normal side and a negative one on the opposite side (a bank in overdraft, a supplier in debit, a negative contra). `migrationOpeningBalanceService.postOpeningBalances` and `migrationExecuteService.verifyBalances` (`isaflowBalance = normal_balance === 'debit' ? net_debit : -net_debit`) share that convention — change one and you must change the other. A debit-signed source export is not importable and the totals check refuses it. `postOpeningBalances` is all-or-nothing: an unresolved account, an account this source does not own (`imported_from !== source`, which is also how a rolled-back account is released back to the company), or a source that does not foot throws before anything is written. The separate wizard path (`migrationImportService.importOpeningBalances` → `openingBalancePostingService`) takes explicit debit/credit columns instead and rejects negatives outright.
