# services/capture/

## Endpoints / Modules
PRD-05 autonomous capture + evidence-first ledger module. All files are pure business logic (no HTTP handlers here — those live under `pages/api/accounting/capture/` and siblings).

- `captureInboxService.ts` — mints per-company email inboxes (`cap-<6hex>@inbox.isaflow.co.za`), CRUD on `capture_inboxes` table.
- `captureRouterService.ts` — orchestrates VLM extraction for a new `capture_events` row. `routeEvent(eventId, companyId)` is called fire-and-forget from every ingress path.
- `captureQueryService.ts` — inbox listing with joined `captured_documents` + `extracted_data` for UI.
- `inboundEmailService.ts` — Postmark webhook ingest. Resolves tenant by `To` address match on `capture_inboxes`, decodes base64 attachments, stores via `storeCapturedBytes`, creates one `capture_event` per invoice-shaped attachment. Returns `captureEventIds[]` so the webhook handler can fire routeEvent for each.
- `whatsAppTextCommandParser.ts` — **pure function** parsing SA expense shorthand ("paid R850 Shell, company card") → `{amount, supplierHint, paymentMethod, description}`. 5 regex layers: amount / verb / preposition / payment method / trailing noise.
- `whatsAppInboundService.ts` — Twilio WABA webhook ingest. Env-gated Twilio media download (graceful no-op when `TWILIO_*` unset). Creates text-only capture_events when body parses but no media (PRD-05 Phase 8).
- `whatsAppReplyService.ts` — outbound Twilio send; pure `composePostingConfirmation` template ("✅ Posted to Motor Expenses R850 (VAT R113) — Shell").
- `whatsAppChaseService.ts` — WA sibling to `sendEmailChase`; JOIN supplier + SELECT company for opt-in, pure `composeChaseWhatsApp` (<400 chars).
- `supplierRulesService.ts` — per-supplier coding defaults + auto-publish + learning loop. `recordCoding` auto-seeds the rule on first human coding (non-null GL), tracks consecutive-match `learned_sample_count`, promotes `auto_publish=true` at threshold (5).
- `duplicateDetectionService.ts` — fingerprint (`lower(vat|invoice#|total)`) exact match + fuzzy fallback (same supplier + total ±0.5% + date ±2d).
- `autoPublishGateService.ts` — decision ladder: duplicate_blocked → no rule → disabled → confidence too low → amount over cap → PO match required → auto_publish.
- `fourWayMatchService.ts` — flips `supplier_invoices.payment_matched=true` when cumulative allocation ≥ total (±R0.01). Idempotent.
- `provisionalPostingService.ts` — Phase 5 bank-first: `predictFromHistory` reads `supplier_coding_history` mode; `postProvisional` creates JE with `posting_agent='ai-provisional:v1'`, `needs_evidence=true`.
- `evidenceAttachmentService.ts` — attaches captured doc to matching provisional JE (supplier + amount ±R0.01 + date ±2d), flips agent to `ai-evidenced`.
- `expectationEngineService.ts` — infers cadence (monthly 25–40d, quarterly 80–100d, annual 330–400d, irregular), trimmed-mean amount, locks at sampleSize≥3.
- `missingInvoiceChaseService.ts` — `detectGaps` per locked expectation; `composeChaseEmail` pure template; `sendEmailChase` with no-email guard.
- `alertResolutionService.ts` — single UPDATE…RETURNING flips pending alerts to resolved when new invoice lands within ±14d of `expected_by`.
- `expectationCronService.ts` — daily orchestrator (per-company loop, failure isolation); prefers WhatsApp when company opt-in + supplier has number, falls back to email.

## Auth
Services are company-scoped. Every exported function takes `companyId` as first arg and every query filters on it. Not bound to a request context — callable from API handlers, cron jobs, or inline.

## Request / Response
All services return typed interfaces matching their DB row shape mapped snake→camel. See per-file JSDoc for exact shapes.

## Business rules
- **Evidence-first ledger**: every JE must carry `posting_agent` (`human:<uid>` | `ai:<name>:v1` | `rule:<id>` | `system:<job>` | `legacy:*`). Enforced at write-path, not DB constraint (so missing stamps surface as service failures, not migration crashes).
- **Auto-publish is opt-in**: PRD §9 "Auto-publish posts bad data to the GL" risk. Company-level `chase_auto_send_enabled` + per-supplier `chase_opted_out` gate chase; supplier-rule `auto_publish` + confidence threshold gate posting.
- **Idempotency everywhere**: `expected_invoice_alerts(company, supplier, expected_by)` UNIQUE + `ON CONFLICT DO NOTHING` on detectGaps; `payment_matched` stays true once flipped; `ai-provisional → ai-evidenced` transition is one-way.
- **Graceful degradation on missing env**: Twilio, Postmark, Storage all return `{ sent: false, reason }` or null when env vars absent — never throw.

## Learnings
- **Singleton mocks + `vi.clearAllMocks`**: clears `.mockResolvedValue` defaults too; re-establish cross-service mocks in `beforeEach` (see `captureRouterService.test.ts` for the pattern).
- **`(intermediate value) is not iterable`**: destructure-from-empty-array symptom when a mock sequence is short by one `mockResolvedValueOnce` — service added an SQL call the test didn't mock.
- **Twilio webhook signature uses `NEXT_PUBLIC_APP_URL`** to reconstruct the full URL Twilio signed; must match the Twilio console entry exactly.
