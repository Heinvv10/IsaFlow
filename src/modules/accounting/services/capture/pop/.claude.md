# capture/pop/

POP inbox, phase 1 (Hein, 2026-11-14): ABSA "Notice of payment" mail reaching a mirrored mailbox is filed as `proof_of_payments` (migration 989). Runs inside the IMAP mirror scan (`../imapMirrorService.ts`); no route, no UI yet.

## Modules
- `absaPopParser.ts` — pure: pdf-parse text of a notice → `{ transactionNumber, paymentDate, payerAccountName, beneficiary, beneficiaryBank, amountCents, reference }` or a refusal reason. Both ABSA layouts (business banking, Absa Online).
- `absaPopTrust.ts` — `isTrustedAbsaNotice(raw)`: From is exactly `ibreply@absa.co.za` AND a DKIM signature by `absa.co.za` verifies over the whole body (mailauth). Node only: under Bun mailauth reports every signature neutral, so it refuses all.
- `pdfText.ts` — the PDF text layer (its own module so tests can stub it: vitest cannot intercept a CommonJS `require`).
- `popIngest.ts` — `ingestAbsaPop(companyId, att)`: captured_documents (`document_type 'proof_of_payment'`, `status 'processed'`, fields in `extracted_data.proofOfPayment`) + storage + proof_of_payments, in one transaction.
- `popMirrorBranch.ts` — `isAbsaNoticeEnvelope` (lets the message past the invoice-subject filter), `isNoticeAttachment` (PDF by bytes: ABSA labels some `*/*`), `fileAbsaNotice` (trust, then file each PDF).

## Business rules
- Only a DKIM-trusted notice that parses completely is filed unattended. An untrusted ABSA-looking message, or a PDF that does not parse, goes to the normal capture ingest (VLM read, capture inbox, a person decides). Nothing is dropped.
- A notice gets no capture_event and no VLM read. Scan log outcome `pop_filed`.
- One row per (company, source, ABSA transaction number): pre-check, then `ON CONFLICT ON CONSTRAINT proof_of_payments_one_per_bank_txn DO NOTHING`; a lost race rolls its document back (its uploaded blob stays, unreferenced).
- Non-ABSA POPs are NOT filed in phase 1: widening the subject filter to "proof of payment" would capture every tenant's customer POPs as bills. Such mail keeps the mirror's existing behaviour.
- The notice names the paying account by nickname only ("Payment made from"), never its number.
