# Loans service group

PRD-03 Loan Amortisation Module. Pure TS amortisation engine sits in `src/lib/amortisation/` — this directory is the DB-integrated service layer that wraps it.

## Files

| File | Role |
|---|---|
| `loanService.ts` | Loan CRUD + event CRUD. `createLoan`, `listLoans(filter)`, `getLoanById`, `updateLoan`, `addLoanEvent`, `getLoanEvents`. Includes origination-fee + VAT-type fields (migration 394). |
| `loanRateCurveService.ts` | Rate curve CRUD. `listRateCurves` returns tenant curves AND system curves (`company_id IS NULL + is_system = true`). `getRateCurveWithPoints` / `getRatePointsForCurve` use defence-in-depth JOINs. `upsertRatePoints` has an IDOR guard — verifies `company_id` ownership before writing. |
| `loanScheduleService.ts` | `previewSchedule` (dry-run), `getOrComputeSchedule` (with SHA-256 `inputs_hash` caching in `loan_schedule_runs` / `loan_schedule_rows`), `getPortfolioSummary`. |
| `loanGlPostingService.ts` | `buildPeriodJournalInput` is a **pure** double-entry builder: non-skip = `Dr Interest Expense + Dr Loan Liability, Cr Bank`; skip = `Dr Interest Expense, Cr Interest Payable`; lump adds `Dr Loan Liability / Cr Bank`. When `payment < interest`, principal is signed (negative → Cr Loan Liability, "interest capitalised"). `postPeriodJournals` blocks posting when `row.nca_flagged` or the period is locked. |
| `loanPeriodCloseService.ts` | `closeLoanPeriod(companyId, yyyymm, userId)` — single `LEFT JOIN LATERAL` query fetches all active loans + their period-end snapshot (not N+1). Returns `skippedLoans: [{loanId, reason}]` for loans missing GL accounts or schedule rows. Post-reclass + insert into `loan_period_locks`. Re-closing a locked period throws. |
| `loanComplianceService.ts` | NCA + IFRS 9 + IFRS 7. `checkNcaCompliance`, `determineEclStage` (0–30 DPD → 1, 31–90 → 2, >90 → 3), `computeEclAmount` (stage 1 = 12m ECL = 1%·45%·next-12m-exposure, stage 2 = 10%·45%·outstanding, stage 3 = full), `computeNpvImpact` (IFRS 9 §5.4.3, flags >10% NPV delta), `computeRateSensitivity` (±100bp/±200bp shocks for IFRS 7). `assessLoan` persists results in `loan_compliance_assessments`. |

## Multi-tenant rules
Every DB query scopes by `company_id`. `upsertRatePoints` has an explicit ownership gate. `getRateCurveWithPoints` / `getRatePointsForCurve` additionally JOIN back to `loan_rate_curves` on `company_id` as defence-in-depth, but both read APIs also allow system curves (`is_system = true AND company_id IS NULL`) regardless of caller.

## Engine contract
All numeric IO is `number` (2dp at output); internally the engine uses `decimal.js` (20dp, ROUND_HALF_UP) and rounds `balance` to 2dp at the end of each period to match Excel row-by-row arithmetic. Golden-file test against `Amortisation Report AI ver.xlsx` (Prime+4%, 72mo, skip + 2 lumps) is cent-accurate.

## Key tables
- `loans` — master. `company_id`, `curve_id`, `gl_account_id` + `interest_expense_account_id` + `interest_payable_account_id` + `bank_account_id` + `current_portion_account_id` (migration 391). `origination_fee` + `origination_fee_vat_type` (migration 394).
- `loan_rate_curves`, `loan_rate_points` — curve data. System-level curves have `company_id IS NULL` (migration 393).
- `loan_events` — append-only log: LUMP / SKIP / RESTRUCTURE / WRITEOFF.
- `loan_schedule_runs` + `loan_schedule_rows` — computed cache keyed by inputs-hash.
- `loan_gl_postings` — every journal line, with `journal_entry_id` pointing at the posted GL entry.
- `loan_period_locks` — (company_id, yyyymm) one-time lock per period.
- `loan_compliance_assessments` — history of NCA + IFRS 9 assessments.

## Gotchas
- **NCA blocking** runs _before_ period lock check in `postPeriodJournals` — cleaner UX (the user sees the compliance error first).
- **`principalPaid = payment − interest`** is signed. Earlier implementations clamped to `max(0, …)` which made journals unbalanced when interest capitalised on a small balance.
- **`inputs_hash`** is `sha256(loan + events + points).slice(0,16)` — any change to events or curve invalidates the cached run.
- **Period close is not atomic** across loans — partial failure leaves some reclass entries posted. The lock row is inserted at the end, so a retry correctly throws "already locked" rather than double-posting. `skippedLoans` surfaces partial failures.
- **Compliance DPD** — "last payment" is derived from `MAX(loan_gl_postings.posting_date)`. "Scheduled date" is the next non-skip schedule row whose date ≥ asOf. No last payment → DPD = asOf − scheduled.
