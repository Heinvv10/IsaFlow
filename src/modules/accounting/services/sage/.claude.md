# sage/ — Connect to Sage (official Sage SA API take-on)

## Purpose
Moves a company's books from **Sage Business Cloud Accounting (South Africa)** into IsaFlow without spreadsheets: the client signs in with their Sage login, picks a Sage company, reviews, and imports. Uses Sage's official API `https://accounting.sageone.co.za/api/2.0.0` (vendor key `SAGE_API_KEY` + the client's login as Basic auth). Page: `pages/accounting/migration/sage.tsx` (hook `src/components/accounting/migration/sage/useSageConnect.ts`). Routes: `pages/api/accounting/sage-connect/{status,companies,preview,import,discard}.ts` + `pulls/[pullId].ts` (GET, the poll).

**The read is a background job.** `preview` inserts a `sage_connect_pulls` row `'pulling'` and answers `{ pullId }` at once; `sagePullJob.runSagePull` runs after the commit (`runAfterCommit`), as the pool role outside RLS (every statement names `company_id`, every write is fenced on `status = 'pulling'`), and ends the row `'ready'` (pull + summary) or `'failed'` (a safe message). The Sage client — so the login — lives in the job's closure only. The page polls `pulls/{id}`; `status` returns the open read/review so a refresh resumes it.

It does NOT post journals of its own. The take-on runs through the migration wizard's existing steps (`core/migrationCoaService`, `migrationContactService`, `migrationWizardOpeningBalanceService`, `migrationImportService`, `ap/migrationApService`), so every audit fix those carry (take-on documents post no VAT, opening balances re-run safely, R-020 interlock, …) applies here too.

Not to be confused with the older Sage code: `core/sageImportService.ts` / `sageMigrationService.ts` (staging-table pipeline, never fed) and the staff-only cookie tool `pages/admin/tools/sage-import.tsx` → `admin/services/sageMigrationCommitService.ts` (posts its own journals, re-declares VAT, wrong category map).

## Business rules
- **Category ids are not meaning.** On a live Sage company (2026-10-21) id 7 = Non-Current Liabilities and id 9 = Owners Equity; the old id table read them the other way round. Classify by `Category.Description` only; an unknown category is an issue (error if the account has a balance).
- **Sage system accounts have NEGATIVE ids** (-1 Sales, -2 Purchases, -7 Trade Receivables, -8 Trade Payables, -9 VAT Payable, -11 Retained Income, -13 Opening Balance and VAT Adjustments …) and report `Balance: 0` in the account list; their balances exist only on the trial balance. Bank accounts are `AccountType 3`.
- **Opening balances come from `TrialBalance/Export`** (FromDate = current financial year start, ToDate = cut-over date, which is *today* SAST). The AR and AP control lines are removed (R-020: documents OR control total, never both) and a clearing line on Opening Balance Equity balances the rest; the AR/AP documents post the opposite, so OBE nets to zero.
- **Contact balance is the truth**, not the outstanding-document list (live data: balances summed exactly to the control lines; documents did not). Unallocated credits are applied oldest-first (raise `amountPaid`); a shortfall becomes one `SAGE-BF-C<id>` / `SAGE-BF-S<id>` balance-brought-forward document; a balance on the wrong side (customer in credit, supplier overpaid) cannot be a document → warning naming the amount the control account is overstated by and OBE carries.
- **Fail closed on documents.** `DocumentTypeId`'s values are undocumented, so a document is an invoice only if its ID AND number are in Sage's still-owed `TaxInvoice/Get` / `SupplierInvoice/Get` list; anything else (credit note, receipt, opening balance) is a blocking issue. A contact `CurrencySymbol` other than the company's, or a document `*_ExchangeRate` ≠ 1, blocks. A Sage company not in the IsaFlow company's currency (ZAR only) blocks.
- **Same financial year.** Sage's year start month must equal `companies.financial_year_start` (blocking otherwise): the opening TB carries this year's P&L to date, posted in the cut-over month (the review says so, `profitAndLossNote`).
- **Closed periods are named up front.** The opening balances post on the as-at date, each document on its own date (the wizard's dates are not changed); one in a closed/locked IsaFlow period is a blocking issue naming the period to reopen.
- **Roles land on the company's existing holder** (e.g. Sage Trade Receivables → the seeded receivable account, renamed) so no duplicate control accounts; roles Sage lacks (vat_input, admin_expense) reuse the holder or are created. New codes are allocated per band (bank 1010…, current assets 1210…, …, expenses 6010…) skipping every taken code and OBE's reserved 3300/3310/3320/3390.
- **The login is never stored.** The pull (data only) is kept in `sage_connect_pulls` while `'ready'`, cleared (`pull = NULL`) on import, discard, or once 24 h old (`'expired'`; on every status/poll/preview call for the company and by the nightly `pages/api/cron/rate-limit-cleanup` — which as at 2026-10-21 has NO host timer). Import refuses a ready review older than 24 h. Import rebuilds the take-on from the stored pull against the chart as it is NOW.
- **One take-on per company.** `importSagePull` takes `lockMigrationImport` FIRST, then refuses when the company has an `'imported'` pull or a standing `auto_migration` opening-balance entry (`findPriorTakeOn`); `uq_sage_connect_pulls_one_imported` is the backstop. One read at a time per company (advisory lock + `uq_sage_connect_pulls_one_pulling`); a `'pulling'` row with no heartbeat for 15 min reads as failed.
- **Exact contacts.** Contacts are imported with `nameMatch: 'exact'` and every document carries its contact's id (`exactContactIds`); the wizard's near-spelling match (CSV) is unchanged.
- **All or nothing.** Any row a wizard step refuses (COA row errors included; COA warnings not) → `SageImportRefused` → the route's savepoint rolls the whole import back; blocking review issues disable Import.
- **Limits:** Sage allows 100 req/min/company (exceeding blocks the IP for an hour) and 5000/day. One pull ≈ 8 calls + 2 invoice-list calls per 100 unpaid invoices + 1 per contact with a balance; paced process-wide, at most 2 pulls at once.
