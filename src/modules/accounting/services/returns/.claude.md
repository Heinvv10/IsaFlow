# returns/ (tax return versions)

Wave 5 L1a. One `tax_return_versions` row (mig 969) per finalised VAT201 or EMP201 for a period, plus the version chain an amendment builds (L1b adds file, amend and the one-open-draft index).

## Caller contract
Called by `pages/api/accounting/sars/returns/[form]/{finalise,versions}.ts`. Every function takes `companyId` first; `finaliseReturn` takes the actor's `{ userId, role }` from withAuth.

## Main signatures
- `finaliseReturn(companyId, form, periodStart, periodEnd, actor, { overrideReason?, force? })` -> `ReturnVersion`. `assertNotImpersonating` first (Login-as 403). One savepoint around everything, so a refusal leaves no lock, no `vat_gate_overrides` row and no version even though withAuth commits a 4xx. `ReturnRefusal` (400/409) is raised only before the first write.
- `listVersions(companyId, form, start, end)` -> `{ versions: (ReturnVersion & { drift, lockRemoved })[], vatReturn }`. Read-only.

## Business rules
- **Periods** (`returnPeriod.ts`, after `reportWindowProblem`): an EMP201 is exactly one ended calendar month (1st to last day, `periodEnd` before today SAST; a nil return for it is allowed). A VAT201 is one period of the company's cycle (`companies.vat_period` monthly or bi-monthly, `vat_period_alignment` odd/even end months, as `bureau/vatPeriodHelper`); a non-vendor is refused. Overlap with ANY live version of the form is 409 (`assertNoLiveOverlap`, re-run under the VAT key).
- A submitted `vat_returns` row with other figures is 409 unless the request carries `acknowledgeVatReturnMismatch: true` and `mismatchReason`, kept in `figures.meta.vatReturnMismatch`. The finalise response returns the record with its `mismatch` flag.
- Stored EMP201 figures carry `directiveTotals` only; `directivePayments` is always `[]` (one person's pay each).
- **Dead end, pinned:** a VAT version whose lock was unlocked directly through `/vat-period-locks` stays live (`lockRemoved`), so finalising again (or an overlapping period) is 409; L1b's amend owns the way out. `lockVatPeriod`'s auto-snapshot is scheduled after its insert and may fire for a lock a refusal then rolls back.
- **VAT201** = `computeVatLockFigures` -> 15% check (`force` records it) -> `assertVatGateClear` (owner/admin override with a reason) -> `lockVatPeriod`. `created: false` is a 409 ("locked outside the lifecycle"). The version copies the LOCK ROW's figures; nothing is computed a second time. The sole guard against a pre-existing lock is `created`, not a pre-read.
- **EMP201** is refused (409) unless every non-cancelled run of the period is final by `isPayRunFinal` (R-035, never a status string; FS's stamp replaces it once FS merges). `generateEMP201` still sums by status string, so the check is on its output: a summed run that is not final blocks. Headers are `FOR SHARE`d so a reopen waits. No payroll lock (decision 7). `posted_through` = latest `approved_at` among the summed runs.
- One non-superseded version per (company, form, period): finalising again is 409. The next version (after an amend, L1b) links `amends_version_id` to the newest one.
- Drift = regenerate and compare: VAT output/input/net and `sarsFields`; EMP PAYE, ETI, payable, UIF, SDL, employees, taxable remuneration, directive totals, the run set with each `approved_plan_hash` (`changed: ['runs']`) and `unfinalRuns` (a summed run no longer R-035 final). `lockRemoved` = the version's lock has `unlocked_at` (someone used `/vat-period-locks` directly). `vatReturn` is the older `vat_returns` row, shown with a mismatch flag; this module never posts and never writes it.
- app_user has SELECT and column INSERT only on the table (no `status` column: rows are born `finalised`); no UPDATE/DELETE until L1b grants its columns. A BEFORE INSERT trigger refuses another company's lock, submission or amended version.
