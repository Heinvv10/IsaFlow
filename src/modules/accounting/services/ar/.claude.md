# AR service group

Accounts Receivable covers the full order-to-cash cycle: quotes → sales orders → customer invoices → payments → collections. Also provides a customer self-service portal, recurring invoice scheduling, write-offs, and smart collections with tone-calibrated reminders.

| `quotePdfBuilder.ts` | PDF generation for quotes (PDFKit). |

## Multi-tenant rules

Every DB call filters on `company_id`. `portalService` uses a separate `portal_users` table with its own auth (bcrypt) — portal users are NOT GoTrue users. The portal user's `client_id` is always verified against the calling company before returning any data.

**Customer invoices**: queries use `COALESCE(ci.client_id, ci.customer_id)` — both columns exist (legacy migration artefact). Never assume only one is populated.

## Key tables

- `customers` — master (also called `clients` in some older columns).
- `customer_invoices` — `status`: `draft | sent | partial | paid | void | written_off`.
- `customer_payments` + `customer_payment_allocations`.
- `customer_credit_notes` — linked to original invoice.
- `quotes` / `sales_orders` / `delivery_notes` — pre-invoice documents.
- `recurring_invoices` — schedule master; `next_invoice_date` drives generation.
- `customer_write_offs` — audit log for bad debt decisions.
- `portal_users` — bcrypt-hashed passwords, linked to `customers`.

## Gotchas

- **`COALESCE(ci.client_id, ci.customer_id)`** — required on all `customer_invoices` queries. Forgetting this returns null client on older records.
- **Portal auth is bcrypt, not GoTrue** — `portalService.authenticatePortalUser` calls `bcrypt.compare`. Do not route portal endpoints through `withAuth`.
- **`confirmCustomerPayment`** posts the GL entry and updates invoice balances in a `withTransaction` block. If either step fails the whole transaction rolls back — partial allocation state is impossible.
- **`smartCollectionsService`** is pure (no DB). The amounts in escalation logic use R50 000 as a high-amount threshold — hardcoded, not configurable.
- **`recurringInvoiceService.generateDueInvoices`** creates invoice rows but does NOT post them — caller must post separately.
