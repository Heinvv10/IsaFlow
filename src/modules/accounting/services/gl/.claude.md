# GL service group

The General Ledger is the financial spine of IsaFlow. It owns the chart of accounts, fiscal periods, journal entry lifecycle (draft → posted → reversed), trial balance, year-end close, and the approval workflow that gates posting of high-value entries. Every other module posts to GL through `createJournalEntry` / `postJournalEntry`.

## Files

| File | Role |
|---|---|
| `journalEntryService.ts` | Facade: re-exports `createJournalEntry`, `postJournalEntry`, `reverseJournalEntry`, `getJournalEntries`, `getTrialBalance`, `mapEntryRow`, `mapLineRow`. Kept for backward compat. |
| `journalEntryCrudService.ts` | `createJournalEntry`, `getJournalEntries`, `getJournalEntryById`, `resolveUserUuid`. Calls `validateJournalEntry` (debit == credit). |
| `journalEntryPostingService.ts` | `postJournalEntry` (validates balance + fiscal period open, then UPDATE status → posted), `reverseJournalEntry` (creates mirror entry, marks original reversed). |
| `trialBalanceService.ts` | `getTrialBalance(companyId, fiscalPeriodId, costCentreId?)` — JOIN on `jl.company_id` AND `je.company_id` (defence-in-depth added in BL-13 / migration 329). Returns flat `TrialBalanceRow[]`. |
| `chartOfAccountsService.ts` | `getChartOfAccounts`, `createAccount`, `updateAccount`, `getAccountTree`. Uses in-memory cache via `cacheThrough` from `@/lib/cache`. |
| `systemAccountResolver.ts` | `getSystemAccount(key, companyId)` / `getSystemAccountId`. Resolves system accounts by `account_subtype` (not hard-coded codes) with 1-minute per-company in-memory cache. `clearSystemAccountCache()` must be called after COA changes. |
| `fiscalPeriodService.ts` | CRUD for `fiscal_periods`. `closeFiscalPeriod` sets status → closed; posting to a closed period throws. |
| `yearEndService.ts` | `listFiscalYears` (groups periods by `fiscal_year`), `closeYear` — creates a closing journal entry (revenue/expense → retained earnings), locks all periods. |
| `approvalService.ts` | `checkApproval`, `requestApproval`, `approveRequest`, `rejectRequest`. Rule-based: amount threshold per document type. |
| `monthEndCloseService.ts` | Pure business logic (no DB). `generateCloseChecklist`, `checkCompleteness`, `detectCutoffIssues`. Checklist driven by company type. |
| `glCrossModuleHooks.ts` | `postAssetDepreciationToGL`, `postAssetDisposalToGL`. Bridge between FAR engine and GL posting. Uses `systemAccountResolver` to find depreciation-expense / accumulated-depreciation accounts. |
| `chartOfAccountsImportService.ts` | Bulk import of COA from CSV/JSON template. |
| `recurringJournalService.ts` | CRUD + `generateRecurringJournals` for scheduled (weekly/monthly) template journals. |
| `transactionLedgerService.ts` | Paginated ledger view per account — joins entries + lines filtered by date range. |
| `continuousCloseService.ts` | Checks all periods closed for a given fiscal year; gates `closeYear`. |
| `glImportService.ts` / `glImportExecuteService.ts` | Import GL data from external source (staging → validated → execute). |

## Multi-tenant rules

All queries scope on `company_id`. After BL-13 (migration 329), `gl_journal_lines` gained its own `company_id` column; every query using `jl` now filters both `je.company_id` AND `jl.company_id`. `systemAccountResolver` caches per `companyId` key — cache invalidation is explicit.

## Key tables

- `gl_accounts` — chart of accounts. `is_system_account`, `account_subtype` drive `systemAccountResolver`.
- `gl_journal_entries` — header. `status`: `draft | posted | reversed`. `source` identifies originating module.
- `gl_journal_lines` — double-entry lines. `company_id` added migration 329.
- `fiscal_periods` — 12 rows per year, `status`: `open | closed | locked`.
- `approval_rules` / `approval_requests` — configurable threshold-based approval workflow.

## Gotchas

- **`journalEntryService.ts` is a facade only** — do not add logic there. Add to `journalEntryCrudService` or `journalEntryPostingService`.
- **`postJournalEntry('')`** (empty string userId) silently resolves to `00000000-0000-0000-0000-000000000000` via `resolveUserUuid`. Known pattern across 10 services (see `project_bank_allocation_bugs.md`); treat it as a system user.
- **Trial balance container key is `rows`**, not `accounts`. Callers that unwrap `json.data.accounts` are broken (see `feedback_api_response_shape.md`).
- **`systemAccountResolver` cache** is process-local. Serverless cold-starts get fresh data. Local dev cache persists until restart; call `clearSystemAccountCache(companyId)` after COA mutations in tests.
- **Year-end**: Revenue and expense accounts are identified by `account_type`. The closing entry posts all revenue credits and expense debits to retained earnings in a single transaction.
