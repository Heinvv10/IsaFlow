# gl/closeRun/ — Close Agent v1

Month-end close automation flagship (A–Z Phase 5). Turns a period's readiness
checklist into a persisted, review-and-approve list of PROPOSALS. Composes
existing pieces; rebuilds nothing.

## Modules
- **closeRunTypes.ts** — shared types (ProposalKind/ActionType/Status, CloseRun, CloseProposal, AccuracyStats).
- **closeRunProposalBuilder.ts** — PURE (no DB/clock): `buildProposals`, `validateDecision`, `computeAccuracy`. Primary TDD target.
- **closeRunRepo.ts** — persistence (company-scoped): insert run/proposals, `fetchDraftJournals`, guarded `updateProposalOutcome`, reads, `getOutcomeCounts`.
- **closeRunService.ts** — orchestration: `startCloseRun`, `getCloseRun`, `decideProposal`, `completeCloseRun`, `getAccuracy`.

## Caller contract
Invoked by `withAuth`-wrapped routes in `pages/api/accounting/close-run/*`
(`index` start/fetch, `decide`, `complete`, `accuracy`). Every function takes
`companyId` first. Runs inside the request tx (ALS `sql`), so a posted journal
and its audit row commit together.

## Composes (do NOT reimplement)
- `periodCloseReadinessService.getCloseReadiness` → the 6-check checklist state.
- `journalEntryPostingService.postJournalEntry` → the ONLY posting the agent runs (draft→posted, period+balance validated).
- `core/auditTrailService.logAuditOrThrow` → the financial audit trail (reasoning goes in `changes.metadata`).
- `fiscalPeriodService.getFiscalPeriodById` → period date bounds for the draft-journal drill-down.

## Business rules (P5.3 honesty — non-negotiable)
- NOTHING posts without an explicit per-proposal `decideProposal(..., 'approve', ...)`. No autonomous posting.
- Only `auto_post` proposals execute; v1 auto_post kind = `post_draft_journal` only, and only when the draft is well-formed (has lines AND balances — `isPostableDraft`). `advisory` proposals can only be `dismiss`ed once a human clears them elsewhere.
- `fetchDraftJournals` keys on `fiscal_period_id` (status='draft'), matching the readiness `unpostedJournalsCheck` exactly. The aggregate `unposted_journals` advisory is suppressed ONLY when every unposted entry (`countUnpostedInPeriod`) was drilled into a postable proposal — a pending/unbalanced/out-of-period entry the agent cannot post stays visible.
- Approve is CLAIM-FIRST INSIDE A `withSavepoint`: it claims the proposal (`updateProposalOutcome … 'approved' … WHERE status='proposed'`) BEFORE posting, then post → audit → `finalizeClaimedProposal` (approved→posted). A concurrent double-approve loses the claim (null) and bails before any post — no redundant post/duplicate audit. **Critically**, the savepoint means a failed post (which is translated to a 409, and `withAuth` COMMITs on <500) rolls the claim back so the proposal returns to `proposed` (retryable) — it can never be orphaned in `approved` and let `completeCloseRun` close over an unposted JE.
- Every executed approval writes an `audit_log` row: action `post`, entity `gl_journal_entry`, `changes.metadata = { source: 'close-agent:v1', closeRunId, proposalId, reasoning }` — same tx as the post (both commit or both roll back via the savepoint / outer tx).
- Expected posting failures (`ClosedFiscalPeriodError`, already-posted, unbalanced, `Journal entry … not found`) are translated to `ProposalDecisionError` → HTTP 409 (regex anchored to postJournalEntry's own messages so a genuine fault stays a 500).
- `decideProposal` refuses any decision unless the run is still `open` (`getCloseRunStatus`) — a superseded/abandoned or completed run never posts.
- One open run per period: `startCloseRun` calls `abandonOpenRunsForPeriod` before inserting, so two runs can never hold auto_post proposals for the same draft JE.
- `completeCloseRun` refuses while any proposal is still `proposed`, AND refuses unless the run is still `open` (idempotent — no re-stamp / duplicate close audit).
- Accuracy = `posted / (posted + rejected)` over auto_post proposals; null when none decided. Failed posts reported, excluded from the denominator.
