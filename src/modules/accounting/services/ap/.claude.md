# AP service group

Accounts Payable manages the full supplier-side procure-to-pay cycle: purchase orders → supplier invoices → payment → GL posting. Also provides EFT file generation for South African banks, Netcash integration, and batch payment processing.

## Files

| File | Role |
|---|---|
| `supplierInvoiceService.ts` | CRUD for `supplier_invoices`. Filters on `status`, `supplierId`, `matchStatus`. Explicit column list (not `SELECT *`) to avoid `purchase_orders` join (table absent in standalone app). |
| `supplierInvoiceWorkflowService.ts` | `approveInvoice`, `postInvoice` (creates GL journal: DR Expense + VAT Input, CR AP), `matchInvoice` (PO/GRN 3-way match). |
| `supplierPaymentService.ts` | CRUD for `supplier_payments`. Payment allocation validation via `validatePaymentAllocations` from utils. |
| `supplierPaymentWorkflowService.ts` | `approvePayment`, `processPayment` (GL: DR AP, CR Bank). |
| `purchaseOrderService.ts` | DB layer for `supplier_purchase_orders` + `supplier_purchase_order_items`. Calculates subtotal + tax at insert/update. |
| `procurementService.ts` | Pure business logic: PO validation, GRN matching, budget-check rules. No DB dependencies. |
| `purchaseOrderPdfBuilder.ts` | Generates PO PDF (PDFKit). |
| `supplierInvoicePdfBuilder.ts` | Generates supplier invoice remittance PDF. |
| `apAgingService.ts` | `getApAging` — buckets overdue AP into 0–30, 31–60, 61–90, 90+ day bands per supplier. |
| `batchPaymentService.ts` | `createBatch`, `addToBatch`, `processBatch` — bulk supplier payments with single GL journal covering all allocations. |
| `eftService.ts` | Pure functions: `generateStandardBankEFT`, `generateFNBEFT`, `generateABSAEFT`, `generateNedbankEFT`. Fixed-width format builders. No DB. |
| `netcashService.ts` | `submitNetcashBatch`, `getNetcashBatchStatus`. Real Netcash API (30 s timeout). Returns `mock: true` when `NETCASH_API_KEY` absent. |
| `migrationApService.ts` | Imports AP invoices from migration staging tables. |
| `index.ts` | Barrel re-export. |

## Multi-tenant rules

All DB services pass `companyId` as the first arg and filter on `company_id`. `batchPaymentService` has a special carve-out: when `companyId` is empty string (internal call after batch creation), it skips the filter to avoid N+1 lookup. This is intentional — the batch ID itself provides the scope.

## Key tables

- `suppliers` — master. Joined into most AP queries for `supplier_name`.
- `supplier_invoices` — `status`: `draft | approved | posted | paid | void`. `match_status`: `unmatched | partial | matched`.
- `supplier_purchase_orders` + `supplier_purchase_order_items` — PO lifecycle (`draft | sent | partial | received | closed`).
- `supplier_payments` + `supplier_payment_allocations` — payments linked to invoices.
- `supplier_payment_batches` — groups multiple payments for bulk EFT run.
- `gl_journal_entries` — AP journals reference back via `source_document_id`.

## Gotchas

- **`purchase_orders` table absent** in standalone accounting app. `supplierInvoiceService` guards this with `NULL::text AS po_number` in explicit SELECT. Do not add `JOIN purchase_orders` without checking deployment context.
- **EFT amounts in cents** — `eftService.formatEFTAmount` multiplies by 100 and returns a string. Do not pass pre-centified values.
- **Netcash mock mode** — `netcashService` falls through to a mock response structure when credentials absent. Callers see `mock: true` flag. Do not gate production behaviour on absence of the flag.
- **`validatePaymentAllocations`** is imported from `../../utils/paymentAllocation` — shared with AR. If allocations don't sum to payment amount it throws before any DB write.
