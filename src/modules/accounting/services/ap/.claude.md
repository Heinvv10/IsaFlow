## Caller contract
Invoked by `withCompany`-wrapped API routes in `pages/api/accounting/ap/*`. Every public DB function takes `companyId` first. Workflow functions additionally take `userId` for stamping.

## Main function signatures
- `getSupplierInvoices(companyId, filters?) / getSupplierInvoiceById(companyId, id) / createSupplierInvoice(companyId, input)`.
- `approveSupplierInvoice(companyId, id, userId)` — posts JE: DR Expense + DR VAT Input, CR AP.
- `performThreeWayMatch(companyId, invoiceId, userId)` — links PO ↔ GRN ↔ invoice; persists via parent `supplier_invoices` scope (2026-04-22 fix).
- `createSupplierPayment / approveSupplierPayment / processSupplierPayment(companyId, id, userId)` — JE: DR AP, CR Bank.
- `generateStandardBankEFT(batch) / generateFNBEFT / generateABSAEFT / generateNedbankEFT` — pure, return fixed-width strings.
- `submitNetcashBatch(payload) / getNetcashBatchStatus(ref)`.
- `getApAging(companyId, asOfDate)`.

## Business rules
- `supplier_invoices.status`: `draft → approved → posted → paid`, plus `void`. `match_status`: `unmatched | partial | matched`.
- PO state: `draft → sent → partial → received → closed`.
- Posting runs under `withTransaction`; JE header gets `source='supplier_invoice'` but NOT the invoice id as `sourceDocumentId` (2026-04-24 fix — FK is to `documents`).
- 4-way match uses separate qty + price tolerances; Phase 6 expectation engine + missing-invoice chase triggers when POs lack invoices (PRD-05).
- `purchase_orders` legacy table absent in standalone app — `supplierInvoiceService` uses `NULL::text AS po_number` to avoid phantom JOIN.
- EFT amounts are centified (×100) inside `formatEFTAmount` — pass Rands, not cents.
- `netcashService` returns `mock: true` when `NETCASH_API_KEY` missing — production must not gate on absence.
- `validatePaymentAllocations` (shared with AR, in `utils/paymentAllocation`) throws if allocations ≠ payment total before any DB write.

## Recent changes
- 2026-09-03: **Cash application — `supplierPaymentApplicationService` + `supplierAllocationLines` + `supplierBankPaymentService`.** The AP mirror, and the AP defect is worse than the AR one. `allocateTransaction(allocType='supplier')` inserts NOTHING: it posts DR Accounts Payable / CR Bank and calls `fourWayMatchService#recordPaymentMatch`, which sets a `payment_matched` BOOLEAN and never moves `amount_paid` or `status`. There is no payment document at all, so a bill can never be reconciled to the cash that paid it — 17 Brightsphere bills read as open at R613,641.77 against a Sage book showing every one paid, and **397 Velocity Fibre bills are flagged `payment_matched = true` while still showing R16,151,543.00 outstanding**. `supplierBankPaymentService` creates the missing `supplier_payments` row at status `processed` carrying the allocation's journal. Four things worth not re-deriving. (1) **`payment_allocations` is the LIVE table.** Migration 201's `supplier_payment_allocations` holds zero rows in dev AND prod and is read by nothing; `processSupplierPayment`, `voidSupplierPayment` and `batchPaymentService` all use `payment_allocations`. `pages/api/accounting/supplier-allocations.ts` used to read and write the dead one, so every allocation it made was invisible downstream — it now calls this service, on both halves. (2) **`payment_matched` is DERIVED, never preserved.** `recordPaymentMatch` flags the FIRST invoice named using the FULL bank-line amount, so a R1,000 line allocating R300 to a R600 bill flags it matched before the apply runs. A `CASE … ELSE payment_matched` kept that lie; the column is assigned from the settlement state and `payment_matched_at` is cleared when the flag goes false. (3) **A partly applied payment KEEPS its status.** The old route set a PROCESSED payment back to `'approved'`, walking a posted payment backwards — and `voidSupplierPayment` accepts only `processed`, so it also quietly became un-voidable. Only a FULLY applied payment moves, to `reconciled`. (4) Plan/apply split, row lock, guards-before-writes and the closed-period pre-check all mirror the AR side exactly; see `ar/.claude.md`.
