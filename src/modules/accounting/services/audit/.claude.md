# services/audit/ — audit snapshots, comparison, check runs, sealed packs

## Purpose
Forensic-controls step 4 (migration 891). A **snapshot** freezes a company's books at a cutoff — TB, every POSTED
journal and line ≤ cutoff as canonical rows with a material hash, ageing / control totals and a sealed **check
run** — under SHA-256 + HMAC-SHA256 with a server key the database never sees. A **comparison** shows what changed
behind it; an **audit pack** (ZIP) is built from it. Caveat: current values of records ≤ cutoff, as at taken_at.

## Caller contract
- `takeSnapshot(principal, { cutoff, trigger })` (by hand: always a fresh copy) / `takeAutoSnapshot` (after a lock
  commits; `unchanged` when a verifying snapshot at the cutoff holds the same books) — one REPEATABLE READ tx on its
  own connection as app_user with the person's claims (`runAuditTx`); `principalFromRequest()` inside withAuth / MCP.
- `verifySnapshot` / `verifyChain` (RLS: owner / admin / manager); `compareSnapshotToLive` / `compareSnapshots`.
- `takeCheckRun(principal, asAt)`; `runAllChecks` = 15 integrity + 4 anomaly + 5 journal-risk.
- `scheduleAutoSnapshot(trigger, cutoff)` — closePeriod, lockPeriod, closeYear, closeFiscalYear, lockVatPeriod.
- `buildSnapshotPack` / `storePack` / `verifyPack` / `verifiedPackZip` (`packExport.ts`); who: `auditAccess.ts`.

## Business rules
- Rows are spelled by the database so a hash recomputes years later; canonical JSON refuses floats and Dates.
- Written only through 891's definers (one call, every row), binding taken_by, company, now(), channel and role.
  Append-only for every role; purge cascade only.
- Verify decides integrity before the key and checks the filing columns. Each document stores `document_version` in
  its sealed totals and is rebuilt under it. Comparisons compare only columns both sides froze (`notCompared`).
- Chain: `seq` + `prev_hmac` (the newest earlier row whose seal verifies), signed. Forged rows are skipped and listed.
- Attempts (failed / unchanged) carry an attempt seal; `unrecordedLocks` (own module) counts only rows that verify.
- `unchanged` = same books (ledger + ageing / control totals) as a verifying snapshot; it must carry its own check run
  (same tx: cutoff, now(), purpose). The chain requires taken_at to increase with seq.
- Load: `snapshotSlots` — two per process, one per company, one per person, one automatic; manual refused (409),
  automatic queues ≤ `SLOT_WAIT_MS`, people in turn (≤ 50 per person), then the chain lock ≤ `AUDIT_WAIT_MS` — neither is budget time;
  it re-reads in its own tx that its close / lock stands (`lock_gone` otherwise). Each step tightens statement_timeout to what is left of `SNAPSHOT_TIME_BUDGET_MS`; past it a
  watchdog cancels the running statement.
- Packs: ZIP sealed (`zip_hmac`), checked before parsing; exact central directory; ready only once built and then
  immutable (891 guard); downloads serve a ZIP only through `verifiedPackZip` (`packVerify.ts`).
- Keys: `AUDIT_SNAPSHOT_RETIRED_KEYS=id=secret@retired-at,…` verifies seals taken before retired-at only; a malformed
  entry is a config error (503). MCP audit tools charge the member's audit bucket (`chargeAuditJob`).
- Column census: decisions in `tests/helpers/auditSnapshotColumns.ts`; integration (schema) + unit (migrations).
- `bulkPlan` (nested loops off) for bulk reads: stale statistics made 50 000 lines take 65 s.

## Known limits
- The owner can disable guards (N1/N3 boundary), but nobody without the key makes a seal verify.
- A removed LATEST snapshot shows only against the chain head logged on every seal.
- Throughput: one automatic snapshot at a time per process (`MAX_AUTOMATIC`), ~110–330 an hour at 11–33 s each;
  raise it, or run more processes, before month-end volume nears that.
- Storage ~520 bytes per frozen line per snapshot (`docs/evidence/audit-snapshots/size-cap-measurement.txt`).
