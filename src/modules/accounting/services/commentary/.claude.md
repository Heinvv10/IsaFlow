# commentary/

## Purpose
Generated commentary on a report pack, held as a DRAFT until a named person approves it. Table `report_commentary`, migrations 611 and 612.

## Caller contract
Called by `pages/api/accounting/commentary/*` under `withAuth`; company always from the session. Consumed on the public side by `share/sharedPackService.ts`, which selects `approved_text` and filters `status = 'approved'`. Every statement here carries `company_id`, including the UPDATEs.

## Main signatures
- `listCommentary(companyId, params) → CommentaryRow[]` — the whole pack, unfiltered. There is no section parameter on the route or the hook; `CommentaryBlock` owns the per-section filter.
- `generateDrafts({ companyId, userId, params, data, replace? }) → { written, skipped }`.
- `approveCommentary(companyId, id, userId, editedText?)` / `rejectCommentary(...)` → `CommentaryResult`, failing with `not_found` (404), `empty_draft` (400), `commentary_budget_exceeded` (400) or `invalid_state` (409) — the route must not collapse them. `editedText` absent copies `draft_text`; present writes the trimmed text and leaves `draft_text` the machine draft.
- `MAX_APPROVED_PACK_CHARS`, `approvedCharCost`, `packCharsUsed` (`commentaryLimits.ts`, client-safe) — the pack-wide budget on approved text (each row costs trimmed length + 1).
- `nextStatus(current, action) → Transition`; `buildDraftSentences(data) → DraftSentence[]`; `buildManagementPackData(companyId, params)`.

## Business rules
- **Status machine** (`commentaryState.ts` is the only place a status changes): `draft → approved` (approve), `draft → rejected` (reject), `* → draft` (generate). `generate` on an approved row FAILS.
- **The `replace` gate.** `replace: true` is the only path that re-drafts a row a person already ruled on: it withdraws an approval and revives a rejection. Without it both are left alone and reported in `skipped` — a discarded sentence does not come back because somebody pressed Generate again. The route restricts `replace` to owner/admin; `CommentaryPanel` puts an explicit, single-use confirmation in front of it.
- A withdrawal is STAMPED, not erased: `withdrawn_by`/`withdrawn_at` are set and `approved_text`/`approved_by`/`approved_at` survive, so the row still says who signed off. Nothing leaks — the published query filters on status.
- The `ON CONFLICT ... DO UPDATE ... WHERE` repeats the decision at the write, on the row's state at write time, because another session can approve or reject inside the read-to-write window.
- An empty or whitespace-only draft is never approvable. The 611 CHECK would store the blank.
- Approval writes status, text, approver and timestamp in ONE statement so the CHECK never sees a half-approved row; the WHERE repeats the guard so two racing approvals cannot both write.
- The draft builder never writes `approved_text`. Nothing generated reaches a share link without a person.

## Recent changes
- 2026-10-07: approve-with-edits. `POST .../[id]/approve` takes an optional `{ text: string }` (non-string is a 400, never coerced); an edit writes the trimmed text and leaves `draft_text` the machine draft. EVERY approval (edited or not) is held to `MAX_APPROVED_PACK_CHARS = 1300` across the pack's approved rows (company + report_kind + params_hash): page 4 joins every approved row into one paragraph and an overflowing page REFUSES the whole pack (`PackRefusal`), it does not truncate. Measured: the tightest fixture fits 1435 joined chars of prose (1925/2177/1827 on the others); 1300 leaves ~9%, 1560 (+20%) refuses (`packApprovedCommentaryCap.test.ts`). Known limit: only-widest-glyph text fits ~770. Approvals are serialised per pack by `pg_advisory_xact_lock(hashtextextended('<company>:<kind>:<hash>', 611))` taken BEFORE the sum is read, inside the `withAuth` transaction (the service throws without one; the lock would release instantly on a pooled connection). Proved against real Postgres by `tests/integration/commentary-budget-race.int.test.ts` (needs the disposable fixture DB). `fitBodyPage` (`packs/pages/packNarrativeFit.ts`) gives an overflowing approved page 4 its own user message. UI: `CommentaryEditor` shows characters remaining for the pack.
- 2026-09-26 (R-032 L5): `approveCommentary`, `rejectCommentary` now call `assertNotImpersonating()` (`src/lib/auth/impersonationGuard.ts`) as their FIRST statement: a platform-admin "Login as" session gets `ImpersonationForbiddenError` → 403 `IMPERSONATION_FORBIDDEN` before anything is read or written. Bearer callers (MCP, PATs) and jobs carry no `session_id` and pass. The guard runs one `sql` query, so a unit test that mocks `sql` with a positional queue must also mock the guard (`vi.mock('@/lib/auth/impersonationGuard', ...)` with `assertNotImpersonating: async () => undefined`) or every later query shifts by one.
- 2026-09-06: the list route's GET arm is owner/admin/manager (`canReadSharingSurface`). It returns DRAFT text, and `withWriteAccess` lets every read method through.
- 2026-09-06: migration 612 adds `withdrawn_by` / `withdrawn_at`; the replace path stamps them and leaves the approval columns intact.
- 2026-09-06: `useCommentary` no longer accepts a `sectionRef` it ignored, and a 2xx carrying the wrong envelope arm throws `ApiEnvelopeError` instead of rendering as "no commentary".
