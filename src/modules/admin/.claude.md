# Admin Module

Platform administration for ISAFlow SaaS operations — company management, user management, billing, feature flags, and system analytics.

## Services (22)

| Service | Purpose |
|---------|---------|
| `adminCompanyService.ts` | Company CRUD, suspension, metadata management |
| `adminUserService.ts` / `adminUserActionsService.ts` / `userImpersonationService.ts` | Platform user management, role assignment, impersonation |
| `adminDashboardService.ts` | System-wide metrics and KPIs |
| `adminWebhookService.ts` | Outbound admin webhooks (events, retries) |
| `analyticsService.ts` / `trendsService.ts` | Usage analytics, company activity, trend rollups |
| `announcementService.ts` | System-wide announcements to all users |
| `auditService.ts` / `auditQueryService.ts` | Admin-level audit logging + query (separate from accounting audit) |
| `billingService.ts` / `revenueService.ts` / `trialService.ts` / `invoiceService.ts` | Subscription management, plan assignment, MRR/ARR rollups, trial state, platform invoices |
| `dataExportService.ts` | Platform data export for compliance |
| `featureFlagService.ts` | Feature flag management, per-company feature gating |
| `healthAlertService.ts` | Tenant health/anomaly alerts |
| `impersonationService.ts` | Admin impersonation of company users (legacy; new flow uses `userImpersonationService.ts`) |
| `planService.ts` | Subscription plan CRUD (Starter, Professional, Enterprise) |
| `sarsCodesAdminService.ts` / `sarsCodesParser.ts` | SARS codes catalogue + parser (admin-managed reference data) |

## Key Rules

- All admin APIs live under `pages/api/admin/`
- Admin middleware uses `withAdmin()` (NOT `withCompany()`)
- Admin pages at `pages/admin/`
- Separate from accounting module — different auth scope
- Feature flags stored in `platform_features` table
- Plans stored in `platform_plans` table
- **Plan-level feature gating reads the plan from the company's current subscription** (latest created of trial/active/past_due), never `companies.plan_id` (vestigial). Precedence: override > global > plan. All three readers in `featureFlagService.ts` share that subquery; `tests/integration/feature-flag-plan-via-subscription.int.test.ts` pins them. Gate routes by calling `hasFeature` in the handler (the dead `withFeature` wrapper was removed).
- **`logAdminAction` fails closed.** `BEST_EFFORT_ACTIONS` is empty, so an audit-write failure — including for an action nobody has added to a list yet — raises `CriticalAuditError`, `withPlatformAdmin` ROLLBACKs the request transaction and the route answers 4xx/500. An unaudited admin mutation must not commit.
- **Fail-closed rolls back the DB, not the outside world.** Actions whose side effect has already left the process before the audit write — `invoice.send` (email dispatched), `user.reset_password` / `user.force_logout` (GoTrue already mutated) — leave that effect done with no DB trace when the audit INSERT fails. An operator reading such a 500 must assume the email or the password change DID happen. Where a route allows it, order the external call AFTER the audit write. Since 2026-10-08 ANY 5xx rolls the admin action back (its own audit row with it), and `withPlatformAdmin` records the attempt as an `admin_request_failed` row after the rollback (`src/lib/auth/adminFailureAudit.ts`): that row is the DB trace of a failed action.
- **Trial state comes from one query** (`trialQueries.loadTrials`): the Trials list, its cards, the billing overview's `trial_count` and health's `expiring_in_7d` all derive from its rows. A company is `converted` (an active/past_due subscription on a plan other than `trial`), else `expired` or `active` by `trial_ends_at`; `companies.status` does not decide it. The conversion date in the stats is the `trial.convert_to_paid` audit row with `target_type = 'company'`.
- **Convert to Paid** (`trialService.markAsConverted`) runs in one `withTransaction` under a `FOR UPDATE` on the company row. It is refused (409) unless the company is `trial`/`active`, for a company that already pays, and for a company with any paused subscription; internal plans (`trial`, `payg`: `types/trialPlans.ts`) and archived plans are refused (400).
- **Convert writes:** it converts the newest live trial row, cancels any other live trial rows of the company, inserts a subscription only when there is none (there is no unique index on `subscriptions.company_id`, so never ON CONFLICT), starts a monthly period now, and never touches `suspended_*`. The 200 returns `firstChargeAt` and `hasActiveMandate`: billing needs an active Paystack mandate.
- **Extending a trial** (single, bulk, `companies/bulk-action`) counts from the later of the current end and today, moves the trial subscription's period end, is refused (409, single) or skipped (bulk) for a paying company, and is 404 for an unknown or deleted one.
- **Nothing enforces trial expiry:** tenant access does not depend on `trial_ends_at`.
