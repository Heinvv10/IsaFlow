# Admin Module

Platform administration for ISAFlow SaaS operations — company management, user management, billing, feature flags, and system analytics.

## Services (22)

| Service | Purpose |
|---------|---------|
| `adminCompanyService.ts` | Company CRUD, suspension, metadata management |
| `adminUserService.ts` / `adminUserActionsService.ts` / `userImpersonationService.ts` | Platform user management, role assignment, impersonation |
| `adminDashboardService.ts` | System-wide metrics and KPIs |
| `adminWebhookService.ts` | Outbound admin webhooks (events, retries) |
| `analyticsService.ts` / `trendsService.ts` | Usage analytics, company activity, trend rollups |
| `announcementService.ts` | System-wide announcements to all users |
| `auditService.ts` / `auditQueryService.ts` | Admin-level audit logging + query (separate from accounting audit) |
| `billingService.ts` / `revenueService.ts` / `trialService.ts` / `invoiceService.ts` | Subscription management, plan assignment, MRR/ARR rollups, trial state, platform invoices |
| `dataExportService.ts` | Platform data export for compliance |
| `featureFlagService.ts` | Feature flag management, per-company feature gating |
| `healthAlertService.ts` | Tenant health/anomaly alerts |
| `impersonationService.ts` | Admin impersonation of company users (legacy; new flow uses `userImpersonationService.ts`) |
| `planService.ts` | Subscription plan CRUD (Starter, Professional, Enterprise) |
| `sarsCodesAdminService.ts` / `sarsCodesParser.ts` | SARS codes catalogue + parser (admin-managed reference data) |
| `sageSession.ts` | Sage Business Cloud session auth (cookie headers, allowed hosts) shared by the server-side pull and the allocation probe |
| `sageAllocationProbe.ts` / `sageProbeShape.ts` | Read-only, shape-only probe of Sage allocation endpoints; run by a human via `scripts/sage/probe-allocations.ts`. Output never carries a value, id or data-shaped key (deny-by-default key vocabulary) |

## Middleware

| File | Purpose |
|------|---------|
| `withAdmin.ts` | Admin role guard — restricts to super_admin users |
| `withFeature.ts` | Feature flag gate — checks company has access to feature |

## Key Rules

- All admin APIs live under `pages/api/admin/`
- Admin middleware uses `withAdmin()` (NOT `withCompany()`)
- Admin pages at `pages/admin/`
- Separate from accounting module — different auth scope
- Feature flags stored in `platform_features` table
- Plans stored in `platform_plans` table
