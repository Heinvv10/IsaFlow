# Module — `src/modules/billing/`

## Purpose
PAYG Flow wallet, subscription billing, and Stitch Express payments. Owns every mutation of `flow_wallet`, `flow_ledger`, `flow_purchases`, and the recurring-debit lifecycle. Spec: `docs/superpowers/specs/2026-04-19-payg-flows-pricing-design.md`.

## Services

| Service | Purpose |
|---------|---------|
| `flowOperationCatalog.ts` | Single source of truth for Flow costs per operation code (`bank.import`=1, `invoice.create`=3, `report.tb`=10, `afs.generate`=50). Categories: `basic` / `standard` / `advanced` / `premium`. |
| `flowWalletService.ts` | Wallet CRUD + ledger writes. All mutating calls are atomic (balance + ledger row in same `withTransaction`). `balance_after` on the most-recent ledger row always equals `flow_wallet.balance_flows`. |
| `stitchClient.ts` | Stitch Express REST client (NOT GraphQL). OAuth2 `client_credentials` → bearer token cached in-memory until 60s before expiry. |
| `subscriptionBillingService.ts` | Recurring-debit lifecycle: `generateDueCharges` (queue) → `runQueuedCharges` (execute via `debitFromMandate`). |

## Caller contract
- Wrapped metered API routes call `getFlowCost(code)` from `flowOperationCatalog` — NEVER hard-code Flow integers in route handlers.
- Wallet mutations always take `companyId` first; routes live under `pages/api/billing/`.
- Admin routes for plan/invoice/PAYG management live under `pages/api/admin/billing/`.

## Main function signatures
- `getWallet(companyId) → FlowWallet | null`
- `deductFlows(companyId, opCode, units, metadata?)` — atomic balance↓ + ledger row, throws on insufficient balance
- `refundFlows(companyId, ledgerId)` — reverses a prior `debit`
- `adminAdjust(companyId, units, reason, adminUserId)` — emergency credit/debit
- `startBundlePurchase / completeBundlePurchase / failBundlePurchase` — Stitch payment-link lifecycle
- `triggerAutoTopup(companyId)` / `setAutoTopup(companyId, enabled, bundleId, paymentMethodToken)`
- `recalculateNudge(companyId) → NudgeLevel` — `none|yellow|orange|red` based on balance + monthly burn
- `resetMonthlyCounter()` — cron tick that resets `month_flows_used` for all companies
- `createPaymentLink(amount, reference, redirectUrl)` / `getPaymentStatus(paymentId)` — Stitch
- `debitFromMandate(mandateId, amountCents, ref)` — recurring debit (currently throws — see Gotchas)
- `generateDueCharges(now?)` / `runQueuedCharges(now?)` — subscription cron

## Business rules
- Ledger types: `purchase | debit | refund | admin_adjustment`. Every balance change writes exactly one row.
- Nudge levels drive the in-app banner; `recalculateNudge` is invoked after every deduction.
- Auto-topup fires inside `deductFlows` when `nudge_level` flips to red and `auto_topup_enabled = true`.
- Subscription charge state: `queued → succeeded | failed`. `failed` is retried up to `MAX_ATTEMPTS=3` with 24h backoff.
- Mandate must be `active` for billing; otherwise charge → `failed` with `reason='no_mandate'`.

## Gotchas
- **Stitch recurring debits are gated.** `debitFromMandate` throws until Stitch upgrades the tenant to the `client_recurringpaymentconsentrequest` scope. `subscriptionBillingService` is wired and tested but disabled at runtime (2026-04-23). Tables stay in place — re-enabling needs no migration.
- Stitch token cache is process-local; in serverless contexts each cold start re-auths. Acceptable today (low call volume).
- `flowOperationCatalog` is `as const satisfies Record<...>` — adding a new op code MUST update the type-narrowed map; do not push to it dynamically.
