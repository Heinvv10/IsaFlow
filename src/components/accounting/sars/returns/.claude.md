# sars/returns/ (return lifecycle UI)

Wave 5 L2. The tax return lifecycle on `pages/accounting/sars/vat201.tsx` and `emp201.tsx`, over the L1a/L1b routes `pages/api/accounting/sars/returns/[form]/{versions,finalise,file,amend}.ts` (service rules: `src/modules/accounting/services/returns/.claude.md`).

## Caller contract
Mount `<ReturnLifecycleBar form="VAT201"|"EMP201" periodStart periodEnd role={companyRole} />` once the return is generated, keyed by the period so a new period remounts it. It loads its own versions (`useReturnLifecycle`) and company-member names (`GET /api/accounting/company-users`).

## Main pieces
- `ReturnLifecycleBar`: status line, every step (vN finalised / filed with reference / amended with reason, each with who and when), the live version's badges (lock removed outside the lifecycle, drift, the older `vat_returns` record differing), the actions, and the Versions button.
- `ReturnActionDialog`: Finalise, Mark filed, Amend. `postReturnAction` returns a refusal instead of throwing: status, the server's message (shown verbatim in `data-testid="return-refusal"`), `details.code` (or `details.reason` for Login-as) and the VAT gate's `details.counts`.
- `ReturnVersionsDrawer`: every version newest first with figures (`figureRows`), filing, amend reason, mismatch reason and the live version's drift.
- `returnLifecycleModel.ts`: pure rules (`availableActions`, `lifecycleSteps`, `figureRows`, `isImpersonating`).

## Business rules
- Finalise: write roles (`canWrite`: owner/admin/manager) when no live version. Mark filed and Amend: owner/admin only (the only roles both `withWriteAccess` and `assertMayActOnReturns` pass). Under Login-as (`is_impersonating=1` cookie) nothing is offered; the server refuses all three anyway (`assertNotImpersonating`), and a refusal it sends is still shown.
- Next steps offered from a refusal, by `details.code`: VAT gate counts -> `VatGateOverrideBox` (owner/admin reason, posted as `overrideReason`); `RATE_CHECK_FAILED` -> a force checkbox; `VAT_RETURN_MISMATCH` -> a mismatch reason; `LEGACY_SUBMISSION_EXISTS` -> the server's `details.legacySubmissionIds` are sent back as `correctsLegacySubmissionIds` with a reason; `LIVE_VERSION_EXISTS` (a stale tab) -> the bar reloads and the dialog offers Amend instead (owner/admin) or Close. The server re-judges every one. Never match on message text.
- Status and actions show only from a settled load (no "Not finalised" for a return that failed to load); a failed reload keeps the steps it had. A new period clears the last period's dialog, message and drawer (the bar resets itself; pages pass no key).
- "Lock removed outside the lifecycle" is shown only for a non-superseded version: an amend releases its own version's lock by design.
