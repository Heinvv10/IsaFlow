# 13-week cash forecast page (`src/components/accounting/cashForecast13/`)

cash13 PR 3. Page `pages/accounting/reports/cash-flow-forecast.tsx` (the menu's "Cash Flow Forecast"): tabs **13 weeks** (default, `Cash13Tab`) | **AI outlook** (`?tab=ai`, `AiCashFlowOutlook.tsx`, the old AI page body). Engine and route contract: `src/modules/accounting/services/cashForecast13/.claude.md`; stored inputs: `pages/api/accounting/cash-forecast-13/.claude.md` (PR #1509).

## Shape
- `cash13Client.ts`: every fetcher returns an `ApiResult` via the budget workspace's `call` (apiFetch resolves on 4xx). The store's wire types are written out from #1509 until it merges; then `import type` them and register the routes.
- `useCash13.ts`: forecast + overrides + items + pay day in one load with a sequence guard (only the latest load applies). GET overrides 404 = data layer not deployed → `store: 'missing'`, read-only.
- `useGuardedSubmit.ts`: one submit at a time (ref, not state); success → `onSuccess`, refusal → the server's message.
- Pure: `overridePayload.ts` (draft → PUT body), `editorBase.ts` (base + preview via the engine), `forecastRows.ts` (groups, labels, lowest week), `cash13WarningText.ts`, `cash13RunwayOption.ts`.
- Views: `Cash13Summary.tsx` (KPIs, runway, overdue AR, warnings), `ForecastGrid.tsx`, `CellEditor.tsx`, `AddItemForm.tsx`, `Cash13Inputs.tsx` (pay day, items list).

## Rules
- AR lines are one per customer (`ar:<customerId>`, #1509 82e1ceea2f): the badge lists the bases held, its tooltip is `basisBreakdownText(basisCents)`, and a `no_history` flag shows "no payment history". Never read a line-level `basis` (removed). `basisCentsOf` widens the type until #1509 merges; then drop it.
- Money on the wire is CENTS (forecast) and RAND (store bodies). Grid shows whole rands via `formatStatementFigure`; negatives bracketed and red.
- Override sign: the person types a positive magnitude and picks Money in / Money out (default `cellSign`: cell, else line total, else first non-zero week, else category: receipts +, rest −); set/add go out signed by that choice, and the editor states the result before Save. move_to: magnitude > 0, or null for the whole week; never from an empty cell; target ≠ the cell's week.
- A save REPLACES the cell's stored override (PUT upserts per line + week). The editor's base is `editorBase` (editorBase.ts): the source line with every stored override of that line EXCEPT this cell's, through the engine's pure `applyOverrides`, weeks mapped as #1509's adapter does; the preview (`previewOf`) applies the draft on that base, so it is the engine's arithmetic. Default direction, the move guard and the radio use the base; "This week" shows the figure in force. A stored change pre-fills the editor (`draftFromOverride`). Known limit: the preview applies the draft LAST; a note-only re-save keeps its stored place (applied_at), which differs only when another change moves money into this week.
- A failed items / store read is said to everyone (never an empty list). The pay-day form resets only when the stored value changes. Tabs stay mounted (hidden) once opened, so a generated AI forecast is not lost and re-billed.
- Editing needs `canWrite(companyRole)` AND `store: 'ready'`. Override lines (`kind: 'override'`) are never editable; edits go on the source line key.
- After any write, reload everything (`useCash13.write`). Never show a warning code: add the code to `cash13WarningText` when the engine gains one (a test lists them).
- AI tab: `aiConfigured` comes from `getServerSideProps` → `aiForecastConfigured()` (same test as the AI service); never call Anthropic to find out.
- Not done: the minimum-cash line (needs a three-way run per load).
