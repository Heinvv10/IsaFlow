# components/accounting/approvals/

## Purpose
The approval-workflow UI pieces: the Approvals page's Rules tab, the per-type Enforce switches, and the approval panel on a document page.

## Files
- `ApprovalRulesTab.tsx` — the Rules tab: rule table with Edit, activate/deactivate (PUT `isActive`), Delete; "New rule"; "Start from recommended rules" while some type in `STARTER_RULES` has no active rule.
- `ApprovalRuleForm.tsx` — New/Edit modal. POST for new; an edit PUTs only the fields that changed; the document type is fixed on edit.
- `ApprovalStarterPanel.tsx` — the starter preview (tick, amount, approver per row) → one `{ action: 'starter', rules }` POST → created / skipped.
- `ApprovalRoleSelect.tsx` — approver-role picker: `demandableApproverRoles(actorRole)`; a value above the actor is shown as a disabled option.
- `ApprovalEnforcementPanel.tsx` — Enforce switches, preview counts, legacy-rule warnings, and (prop `activeRuleTypes`) "No active rule for this type — turning this on gates nothing."
- `approvalRuleDisplay.ts` — `ApprovalRuleRow`, `DOC_TYPE_LABELS`, `OPERATOR_LABELS`, `formatCurrency`, `parseAmount`.
- `DocumentApprovalPanel.tsx`, `approvalDocumentHref.ts` — the document-page panel and request links.

## Caller contract
- `pages/accounting/approvals/index.tsx` owns the data: it passes `rules`, `actorRole` (from the rules GET — the role withAuth resolved, never the client context) and `onChanged` (reloads the rules without the page spinner, so a starter result stays on screen). Without `actorRole` no form is offered.
- `activeRuleTypes` is undefined while the rules list is not known; the panel then says nothing about missing rules.

## Business rules
- The server is authoritative: every 4xx body message (403 authority, 400 legacy, 400 rule in use) is shown verbatim; `apiFetch` resolves on 4xx, so every write goes through `assertOk`.
- Imports from `services/gl` are the PURE modules only (`approvalRank`, `approvalRuleOptions`, `approvalStarterRules`) — anything importing `@/lib/neon` must not reach the client bundle.
- Never offer a legacy type (`credit_note`, `payment`, `journal_entry`) for a new rule.
