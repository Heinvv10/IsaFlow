# present/

Presentation mode: a report pack paged on a boardroom screen.

## No nav entry

`pages/accounting/reports/present/[pack].tsx` has no entry in
`accountingNavConfig.ts`, by design. It is a full-screen presentation
surface entered only from a "Present" button on `report-packs.tsx` for a
specific pack + date range — there is no standalone destination for it to
land a user on, and a nav entry with no query params would open a page that
immediately reports "Unknown pack".

## No app chrome

`pages/accounting/reports/present/[pack].tsx` does not use `AppLayout`. The
sidebar, header and tenant switcher are what this route removes; adding the
layout back defeats it.

## One slide in the DOM

`PresentDeck` renders only the current slide. Paging holds at both ends
rather than wrapping — a presenter who over-clicks at the end should see the
last slide, not the cover.

Keys: right / down / PageDown / space / enter advance; left / up / PageUp /
backspace go back; Home and End jump; Escape exits.

## Files
- `presentSlides.ts` — `buildSlides`, `clampSlide`. Unknown section types are
  dropped, never paged to as a blank slide.
- `PresentDeck.tsx` — the shell and the keyboard map.
- `PresentSlide.tsx` — section kind → component. Every slide that shows a
  sentence instead of a figure goes through `SlideNote`, which carries the
  section title: a presenter paging onto a bare grey line cannot tell which
  section of the pack it is, and the room reads it as a rendering fault. Maps, never computes. The
  income-statement slide is the one exception: it fetches
  `reports-income-statement` and maps it with `toIncomeStatementRows` rather
  than reading the pack section, because the pack's income-statement section
  carries band totals with no `accountCode` and the trend/budget comparators
  need one. Its `budgetedCount` prop mirrors
  `useStatementComparators`'s guard via `hasBudgetData` — the budget
  comparator is applied only when a real budget was captured, never against
  an implicit budget of zero. `[pack].tsx` fetches it from
  `reports-budget-comparator`'s `budgetedCount` alongside `lines`.
  `trendsFailed` / `budgetFailed` distinguish a rejected fetch from "no data
  captured yet": the trends and ratios slides fall through to the generic
  "no presentation renderer yet" message only when nothing failed, and show
  an explicit "could not be loaded" message when `[pack].tsx`'s
  `Promise.allSettled` reports a rejection.
- `[pack].tsx` renders an explicit "Unknown pack" error (via the same error
  state as a pack-fetch failure) once `router.isReady`, rather than spinning
  forever on an unrecognised `pack` type or a missing `from`/`to` range.
