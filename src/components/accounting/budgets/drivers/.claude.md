# Budget drivers UI (`src/components/accounting/budgets/drivers/`)

P4's UI on P2's budget grid (spec `docs/plans/budgets/P4-drivers-forecast-spec.md` §1, §6, §7): driver chips, the driver editor drawer, override marks with Reset, closed-month "Actual" cells, the headcount panel and planned hires, "New reforecast from actuals" and the rolling forecast's controls. No page of its own: it renders inside `workspace/BudgetWorkspace.tsx` (`/accounting/budgets`).

## Shape
- `driverClient.ts`: fetchers for `budget-drivers/**` and `budget-versions/[id]/reforecast` over the workspace's `call` (`ApiResult`; nothing throws on a 4xx). Every write sends the version token as `expectedUpdatedAt` (query for DELETE).
- `useDriverActions.tsx`: the workspace's driver layer: `handlers` (`GridDriverHandlers`, handed to `BudgetGrid` → rows), the editor node, the headcount cache the preview reads, `runWrite` (THE path for every driver / override / hire / refresh write), `notice`.
- Pure: `driverText.ts` (chip words, description), `driverDraft.ts` (form → `DriverLine`, field errors), `driverRows.ts` (labels, the row at the view's grain, pct_of_line targets, cost centres), `driverPreview.ts` (P4's PURE engine `computeVersion` over the grid's cells: editor preview, override "driver value").
- Components: `DriverChip`, `DriverEditor` + `DriverKindFields`, `OverrideMark`, `HeadcountPanel` + `PlannedHires`, `ReforecastDialog`, `RollingControls`.

## Caller contract
- `useDriverActions(grid, editable)`: `grid` is `useBudgetGrid`'s API (needs `adoptToken`, `refresh`). `handlers` keeps its identity across edits (render-count gate); it changes on a load.
- `runWrite(write, done)`: refuses on a dirty grid (a write recomputes cells), sends `grid.token`, on success adopts the answer's token FIRST, then `grid.refresh(warnings)` (in place, no skeleton), puts the recompute's warnings on the rows' chips. 409 STALE re-reads and says so; a 400 DRIVER_CYCLE comes back with `path`.
- `HeadcountPanel` reads counts + hires itself; writes through `runWrite`. `RollingControls` renders nothing for a non-reforecast version (and reads no status).

## Rules
- Import the engine (`budgets/drivers/driverEngine`, `driverLine`, `driverTypes`, `grid/*`) only: never a service file with `sql`. Server types are `import type`.
- The grid store holds each loaded cell's `source`, the closed months (months holding an 'actual' cell) and the drivers by row key. A closed month's column (and the FY column of such a version) is not editable; `apply` drops writes to it and clears of 'driver' cells (the server refuses both).
- A save in a version with drivers (or whose answer carries `recomputed` / `reset` / `driverWarnings`) re-reads the version in place: typed driver cells became overrides, dependents moved. The save bar shows the recompute count and the warnings.
- Override Reset: mouse on the mark's note; keyboard through the row's actions (Shift+F10: "Reset <month> to driver", "Reset all overrides").
- Headcount: COUNTS ONLY (payroll actives, hires, total). A planned hire is a role label, never a person's name (the placeholder says so).
- Tooltips are React text (`title`, text nodes), never HTML strings, so `charts/escapeHtml.ts` does not apply (escaping would show `&amp;` to the user).
- Tests: `tests/unit/components/budgets/drivers/` (happy-dom, `vitest.components.config.ts`); mutation log `~/.cache/redchk/budgets-p4/pr5-mutations/`.
