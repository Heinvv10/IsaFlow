# Budget drivers UI (`src/components/accounting/budgets/drivers/`)

P4's UI on P2's budget grid (spec `docs/plans/budgets/P4-drivers-forecast-spec.md` §1, §6, §7): driver chips, the driver editor drawer, override marks with Reset, closed-month "Actual" cells, the headcount panel and planned hires, "New reforecast from actuals" and the rolling forecast's controls. No page of its own: it renders inside `workspace/BudgetWorkspace.tsx` (`/accounting/budgets`).

## Shape
- `driverClient.ts`: fetchers for `budget-drivers/**` and `budget-versions/[id]/reforecast` over the workspace's `call` (`ApiResult`; nothing throws on a 4xx). Every write sends the version token as `expectedUpdatedAt` (query for DELETE).
- `useDriverActions.tsx`: the workspace's driver layer: `handlers` (`GridDriverHandlers`, handed to `BudgetGrid` → rows), the editor node, the headcount cache the preview reads, `runWrite` (THE path for every driver / override / hire / refresh write), `notice`.
- Pure: `driverText.ts` (chip words, description), `driverDraft.ts` (form → `DriverLine`, field errors), `driverRows.ts` (labels, the row at the view's grain, pct_of_line targets, cost centres), `driverPreview.ts` (P4's PURE engine `computeVersion` over the grid's cells: editor preview, override "driver value").
- Components: `DriverChip`, `DriverEditor` + `DriverKindFields`, `OverrideMark`, `HeadcountPanel` + `PlannedHires`, `ReforecastDialog`, `RollingControls`.

## Caller contract
- `useDriverActions(grid, editable)`: `grid` is `useBudgetGrid`'s API (needs `adoptToken`, `refresh`). `handlers` keeps its identity across edits (render-count gate); it changes on a load.
- `runWrite(write, done)`: refuses on a dirty grid (a write recomputes cells), sends `grid.token`, on success adopts the answer's token FIRST, then `grid.refresh(warnings)` (in place, no skeleton; `workspace/gridRefresh.ts`), puts the recompute's warnings on the rows' chips. A failed re-read after a write that stood is said in the notice (never a refusal). 409 STALE re-reads and says so; a 400 DRIVER_CYCLE comes back with `path`.
- `grid.refresh(warnings?)` has its own sequence: it never cancels a version switch, a pending load skips it, and absent `warnings` keep the rows' current ones.
- `openEditor(accountId, onClosed)`: the row actions and the chip both pass a refocus; focus returns to the row's first cell after the drawer unmounts (after Save, Delete, Cancel or Escape).
- `HeadcountPanel` reads counts + hires itself (a good read clears an earlier error; a refused hire write reads the hires again); writes through `runWrite`. Delete driver / Delete hire confirm in place (never `window.confirm`).
- `RollingControls` renders nothing for a non-reforecast version (and reads no status). Roll now: the answer's warnings go to `grid.refresh`, its `unplaced` are listed (`UnplacedList`, the reforecast dialog's), a skipped roll (`locked` / `primary` / `not_rolling`) is said; the status is read again after every write (a roll that changes no cell keeps the token). The stale badge, the reopened banner and Roll now show on ANY reforecast, rolling or not (Roll now is also the manual refresh; PR-4's final API); turning rolling on shows the closed months stale until the first roll. The status's `reopenedMonths` show the spec §6 banner "<Mon> reopened after the roll — Roll now refreshes it" and its `unplaced` sit behind a disclosure. `RollingStatus` is declared in `driverClient.ts` (the service type moves with PR-4).

## Rules
- Import the engine (`budgets/drivers/driverEngine`, `driverLine`, `driverTypes`, `grid/*`) only: never a service file with `sql`. Server types are `import type`.
- The grid store holds each loaded cell's `source`, the closed months (months holding an 'actual' cell) and the drivers by row key. A closed month's column (and the FY column of such a version) is not editable; `apply` drops writes to it and clears of 'driver' cells (the server refuses both).
- A save in a version with drivers (or whose answer carries `recomputed` / `reset` / `driverWarnings`) re-reads the version in place: typed driver cells became overrides, dependents moved. The save bar shows the recompute count and the warnings.
- Override Reset: mouse on the mark's note (fixed in the viewport, follows scroll / resize, disabled while its reset runs); keyboard through the row's actions (Shift+F10: "Reset <month> to driver", "Reset all overrides"). One Reset per cell or row at a time (`resetting`).
- A clear of a driver cell typed over since (unsaved) goes back to the driver's loaded value; a clear of an untouched driver cell is dropped with `DRIVER_CLEAR_REASON`.
- "Spread across months…" in a version with closed months spreads over the open months only and says so; with none open it is refused (`FY_CLOSED_REASON`).
- A per_head preview whose headcount read failed says so (retried when the editor asks again).
- Headcount: COUNTS ONLY (payroll actives, hires, total). A planned hire is a role label, never a person's name (the placeholder says so).
- Rulings (round 1, 2026-10-29): (a) the Headcount button shows on every version: hires are entered before a per_head driver exists. (b) After a save in a version with drivers the grid re-reads the version, which clears the undo stack: the recompute rewrites cells, so undoing over recomputed values would be wrong. Versions without drivers keep undo across saves as before.
- Contrast: a closed month's cell and its "A" marker are `--ff-text-tertiary` on `--ff-bg-tertiary`: 5.37:1 light, 5.04:1 dark (on the selected fill 4.94 / 5.80); pinned by `driverContrast.test.ts`.
- Tooltips are React text (`title`, text nodes), never HTML strings, so `charts/escapeHtml.ts` does not apply (escaping would show `&amp;` to the user).
- Tests: `tests/unit/components/budgets/drivers/` (happy-dom, `vitest.components.config.ts`); mutation log `~/.cache/redchk/budgets-p4/pr5-mutations/`.
