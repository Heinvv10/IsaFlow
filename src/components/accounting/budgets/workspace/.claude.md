# Budget workspace UI (`src/components/accounting/budgets/workspace/`)

The budgets P2 planning grid (spec `docs/plans/budgets/P2-budget-grid-spec.md` §4.4). Page: `pages/accounting/budgets/workspace.tsx` (AppLayout, NOT in the nav until PR-D points `/accounting/budgets` at `BudgetWorkspace`).

## Shape
- Data: `budgetWorkspaceClient.ts` (every fetch returns `ApiResult`; nothing throws on a 4xx) → `useBudgetGrid.ts` (load / view / save / 409) → `gridStore.ts` (external store, per-row + per-metric subscriptions; hooks in `gridStoreHooks.ts`).
- Grid: `BudgetGrid.tsx`, `BudgetGridRow.tsx`, `BudgetSubtotalRow.tsx`, `BudgetCellEditor.tsx`, `useGridKeyboard.ts`, `useGridClipboard.ts`, `useRowActions.tsx` + `SpreadDialog.tsx` / `GrainChangeDialog.tsx`, `MobileCellSheet.tsx` (coarse pointer / <768px).
- Shell: `BudgetWorkspace.tsx` (page body + states), `useWorkspaceVersions.ts` (year list, versions list, bar actions), `VersionsBar.tsx` + `VersionStatusDialogs.tsx`, `GridToolbar.tsx`, `SaveBar.tsx`, `StaleVersionDialog.tsx` + `downloadDirtyCells.ts`, `WorkspaceEmptyState.tsx`.
- Wizard / Excel: `CreateWizard.tsx` (+ `Wizard*Step.tsx`, `wizardDraft.ts`, `seedPreview.ts`), `ImportDialog.tsx` + `ImportDiffPreview.tsx`, `TemplateDownloadDialog.tsx`.

## Caller contract
- `<BudgetWorkspace />` takes no props: role from `useCompany().companyRole`, years from the legacy `GET /api/accounting/budgets` (the only route listing registry years; its first answer names the year holding today).
- `VersionsBar` props: `versions, current, role, dirtyCount, disabled, compareVersionId, onSelect, onCompare, onNewReforecast, onAction(req) → Promise<string|null>` (null = done, else the dialog shows the message). `versionButtons(version, role)` is the §10 matrix.
- `StaleVersionDialog`: `stale, onChoose('reapply'|'discard'|'download'|'copy') → Promise<string|null>, onClose` (close keeps the cells).
- `SaveBar`: `dirtyCount, saveState, readOnly, onSave, onDiscard` (Discard confirms). `GridToolbar`: view + member picker (member FY NP), rounding, density, PY/Δ toggle, Template, Import (null hides it).
- `downloadDirtyCells(input)`: one .xlsx per grain in the template layout, `_meta` unsigned and no `_base`.

## Rules
- The server is authoritative; UI gating is cosmetic. Approve/Lock/Set primary: owner/admin. Unlock: owner, reason 1–500 chars trimmed (`validUnlockReason`). Delete: not primary, not locked; draft any writer, approved owner/admin; always confirmed.
- Every transition, a version switch and a year switch need a clean grid; transitions send the token and reload (new token).
- A 409 never discards: the store keeps the cells; only "Discard mine and reload" or the save bar's confirmed Discard drops them. Locked → "Copy into a new draft version" (P1 copy, then `reapplyMine(copyId)`: my cells land dirty on the copy for review and save).
- `downloadDirtyCells` writes a dirty row WHOLE (a blank month imports as "not budgeted"); multi-dimension rows are left out and counted. exceljs is `import()`ed on click only.
- Colours only from `--ff-*` tokens; money via `formatStatementFigure`; no `console`; `apiFetch` resolves on 4xx (always check).
- Tests: `tests/unit/components/budgets/workspace/` (happy-dom, `vitest.components.config.ts`). Every file that stubs `fetch` (the workspace ones through `workspaceHarness.ts`) re-stubs it to reject after each test, so a late effect never reaches :3000. `tests/unit/services/budgets/workspace/downloadDirtyCells*.test.ts` round-trips the file through `budgetImportParse` and pins the `@/lib/saveBlob` hand-off.
- Render-count gate (§13): `BudgetWorkspaceRenderCount.dom.test.tsx` profiles the REAL rows under the workspace; anything in a row's props (`handlers`, `members`, `cols`) must keep its identity across edits. `useRowActions` and `useGridKeyboard` read changing inputs through refs; `members` is one shared empty array in the Company view, and member NP follows `store.getRevision()` in a dimension view.
- The undo stack survives a view switch (cell keys do not depend on the view): a deliberate deviation from §5.5's "clear behind a confirm".
- Chained saves are cut on account boundaries (`chunkByAccount`); a non-409 refusal part-way puts `failedChunk` / `chunks` and "Part(s) 1–k of n were saved" in `SaveState.error`.
