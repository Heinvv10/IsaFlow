# budgets/tracking/ (components)

The Budget vs Actual page's parts (budgets P3 PR-B, spec `docs/plans/budgets/P3-tracking-spec.md` §1, §2.2–§2.7). The page is `pages/accounting/reports/budget-vs-actual.tsx`; the report is the engine's (`services/budgets/tracking/`, route `reports-budget-tracking`).

## Caller contract
- Render, never compute: rows come from `statementRows/budgetTrackingRows`, the bridge from `budgetBridgeSteps`, the bullets from `trackingByMember.toBulletLines`. No figure is added up here.
- Only the parameters the period takes are sent (`trackingControls.trackingSearch`); the route answers anything else with a 400.
- A version belongs to one year: choosing another window returns to each year's primary (`withPatch`). Whether a window spans two years is the response's answer (`versionsByFy`), never re-derived here; then the picker is disabled and says why (`crossYearReason`). `group_by` (bullets) is sent only without a filter; the export never sends it.
- The controls live in the page URL (`controlsFromQuery` once the router is ready, `controlsToQuery` written back with a shallow replace): Back and a shared link reopen the same report. A chosen financial year stays in the URL under every period (the request sends it only where the period takes it); any other off-period parameter or a malformed id in the URL is dropped. The drill's entry links carry no `return_to` (nothing reads it; Back uses the URL).
- A response that arrives after a newer request is dropped; a failed load clears the report, so the exports are disabled rather than exporting the last window.
- Control changes are coalesced: one request once they have been still for 350 ms. A refusal (429) reads "Too many report requests: try again in <wait>" from the response's Retry-After (the route's own cap sends one; the shared withAuth reports limiter does not, so that reads "about a minute"), with a Retry button that re-sends the same request (one per click, no auto-retry). An inverted custom range is said under the inputs and nothing is sent (`controlsProblem`). Quarter opens on the quarter holding today (`quarterHolding`; Q1 for a year that does not hold today), as Month opens on the month holding today; another year keeps the chosen quarter, clamped to that year's last. The heatmap judges through the engine's `projection.judgedThrough`.
- The charts are images with their figures as the text alternative (`trackingChartSummaries`), and link to the statement table (`#bva-statement`).
- The drill reads the filter from the REPORT (`report.filter`), not the controls, so it foots to the lines on screen, and runs with `budgetTracking` (source documents, sign by account type). The grid runs with `budgetTracking` too (zero budget 0.00, Var R opens the drill).

## Files
- `trackingControls.ts` — pure: `TrackingControls`, `trackingSearch`, `withPatch`, `controlsFromQuery` / `controlsToQuery`, `quarterOptions` (Q5 of 2 in a 14-month year), `crossYearReason`.
- `useBudgetTracking.ts` — state, the report fetch (`apiJson`, registered in `lib/apiRoutes.ts`), versions of FY* (`budget-versions?fiscalYear=`, primary first), cost centres (CC1 / CC2 by `ccType`) and business units.
- `BudgetTrackingControls.tsx` — period, month, financial year, quarter, from/to, version, CC1 / CC2 / BU.
- `BudgetTrackingNotices.tsx` — header (window, version read, in progress / posted through), `projectionHeading`, and the notices: no budget for FYxxxx in this window, partial budget, unbudgeted, unallocated footer with "View unfiltered".
- `BudgetTrackingVisuals.tsx` — profit bridge, bullets by CC1 / CC2 / BU (unfiltered only), heatmap (months after the projection cutoff are not judged).
- `trackingChartSummaries.ts` — pure: `bridgeSummary`, `bulletSummary`, `heatmapSummary` (the charts' aria-labels).
- `useVarianceNotes.ts` / `VarianceNoteButton.tsx` (budgets P5-5) — a line's variance note on a ONE-month window (the report's version and month; slice = account + the report's CC1/CC2/BU filter; nothing loads on a longer window). The icon is coloured by status; the dialog shows the approved note to everyone, the draft labelled "Draft" (or "Rejected") to owner/admin/manager, an editor to writers (an approved note: owner/admin only, saving withdraws the approval), Approve / Reject to owner/admin. Roles from `useCompany().companyRole` and `varianceNoteTypes`; the server is the authority. Approve sends the editor's text as an approve-with-edit when it differs from the shown draft (else a plain approve); approve and reject carry the shown draft (409 → reload). Until the person types, the editor follows the loaded note (a refused approve/reject reloads it and the editor takes the new draft; a refused save keeps the typed text). Icon colours are defined tokens only (approved `--ff-brand-dark` / dark `--ff-brand-light`; `--ff-brand-500` does not exist and renders grey). Nothing is written unless `useVarianceNotes().ready` (this scope's notes loaded without error; a scope change clears the map first). Rendered through `StatementGrid`'s `renderLineAside`. Tests: `budgetVarianceNotes.test.tsx`; the page tests mock `@/contexts/CompanyContext`.
