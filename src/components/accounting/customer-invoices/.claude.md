# customer-invoices/ (list page components)

## Purpose
Sage-style filters for `pages/accounting/customer-invoices/index.tsx`: status, search, customer, invoice-date period, aging chips. Mirrors `../supplier-invoices/` (FilterBar + URL-state hook).

## Caller contract
- The URL is the state: `?status=&q=&customer=&from=&to=&aging=&page=`. `?filter=<status>` (dashboard widgets) is still read. `listQuery.ts` is the only place that maps URL ↔ filters ↔ API params (`client_id`, `from_date`, `to_date`); the list and the CSV export both take `arFiltersToApiParams`.
- Hydration is lenient (a bad value in a hand-edited URL is dropped); the API is strict (400).
- Links in: `../ViewAllInvoicesLink.tsx` (aging panels) builds `?customer=<id>`.

## Main signatures
- `hydrateARFilters(query)`, `arFiltersToQuery(f)`, `arFiltersToApiParams(f)` — `listQuery.ts`.
- `useCustomerInvoiceListState()` — re-hydrates whenever the URL changes under it (back/forward), writes with a shallow `router.replace` only when the query changes.
- `ARFilterBar`, `CustomerTypeahead`, `CustomerInvoiceTable`.

## Business rules
- The customer's NAME is never read from the URL: a URL label could name a different customer than the id it filters. It comes from the typeahead pick or the loaded rows' `client_name`, keyed by id.
- The typeahead searches only once something is typed — `/api/accounting/customers` without `?q=` returns the whole directory.
- A month is a UI convenience (`../invoicePeriod.ts`): it becomes an inclusive from/to pair; never `toISOString()` a date here.
