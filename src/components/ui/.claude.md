# components/ui/ (the kit)

## Purpose
The shared controls and page furniture every screen is built from: `Button`, `Input`, `Select`, `DateField`, `MoneyField`, `PageHeader`, `Breadcrumb`, `Drawer`, `StatusPill` and friends. Everything is drawn from theme tokens, so it reads in both themes.

## Caller contract
- Import from `@/components/ui`. A form control takes its label through the kit (`no-raw-form-input` and `no-unnamed-control` refuse a raw one).
- `PageHeader` is the page header. Never draw a dark gradient banner: `tests/unit/ci/themeContrastBanner.test.ts` refuses one, and nothing remaps a dark title on it in the light theme any more. A back link is a `breadcrumb` whose last item is the current page. Pass `className="mb-0"` when the content brings its own padding.

## Main signatures
- `PageHeader({ icon, title, subtitle?, actions?, breadcrumb?, backLink?, chipColor?, className? })`: `title` is a string, and the h1; the h1 truncates and carries `title=` only while it is clipped.

## Business rules
- **Label case (wave 3 spec, decision 8; applied in wave 4).** Field labels are sentence case in the kit's `text-sm font-medium`. Uppercase is for eyebrows and table headers only. New code follows this now; the 18 files still on `uppercase tracking-wider mb-1.5` convert in wave 4: `git grep -l "uppercase tracking-wider mb-1.5'" -- pages src`.
- **IDs use `font-id`** (`styles/globals.css`): the app face with tabular figures and a slashed zero, for invoice, journal, employee and account numbers. `font-mono` is for code alone: `eslint/font-mono-allowlist.json` lists the files still using it and only shrinks. After converting a file, run `bun scripts/ci/check-font-mono-allowlist.ts --write` and regenerate rather than hand-merge the list on a conflict.
- **Counts and dates use `tabular-nums`, not `font-id`.** `font-id` is for identifiers, where the slashed zero tells 0 from O. The figures faces (`public/fonts/figures`) are Plex Sans cut to the digits plus the `zero` feature; re-cut them with `scripts/fonts/cut-figures.sh` (`--no-zero [outdir]` rebuilds the pre-slashed-zero cut, which `o3-banner-titles.spec.ts` must fail against, at weights 400, 500 and 600). Needs `pyftsubset` (fonttools + brotli).
- **DateField is typed first, calendar second (22 Nov 2026).** The text box stays the primary input (`15`, `15/3`, `15032026`, `15/03/2026`, `t`, `+30`, `eom`). The calendar (`CalendarPopup`, W3C date-picker-dialog keys, Monday-first, a bottom sheet below lg) opens only from the button beside the box or Alt+ArrowDown, never on focus, click or typing. `minDate` / `maxDate` disable days in it. Closed-period blocking is not in the field yet. The default placeholder stays `dd MMM yyyy` because tests and golden specs find fields by it; the shortcut hint lives in the popup.
- **Report ranges use `DateRangeField` / `FiscalPresetBar`; as-at reports use `AsAtPresetBar`** (not hand-made pills). Presets follow the company financial year (`src/lib/fiscalRangePresets.ts`; the month comes from the active company, March when unset): this/last month, this/last FY quarter, this FY, year to date, last FY, last 30 days, Custom. A page that owns its From/To fields and `useDateGate` keeps them and adds `FiscalPresetBar`; `onPick` must set both dates and call `gate.reset` for each so refused text is dropped. VAT201 keeps its own SARS-period quick buttons (a VAT period is not a financial-year preset); the trial balance picks a fiscal period, not dates.
- **Months use `MonthField`, never a native `<input type="month">`** (22 Nov 2026; `tests/unit/lib/rawDateMonthInputCensus.test.ts` fails on any native date, month, week or time input in `src/` or `pages/`). Typed first, like DateField: shows "Mar 2026", emits `YYYY-MM`, reads `3/2026`, `2026-03`, `mar 2026`, `maart`, a bare `3`, `t`, `+1` / `-1`; ArrowUp / ArrowDown step a month. The year-and-month grid (`MonthPopup`) opens only from the button or Alt+ArrowDown. `minMonth` / `maxMonth` refuse and disable months. `DateField`'s calendar and the month grid share `usePopupPanel` (sheet below lg, popover from lg up, focus trap, outside press). `FieldFrame` takes `labelHidden` for a label that is only for assistive tech.
- **Posting dates know the fiscal calendar** (date rework 4/4). `<DateField postingDate>` is for a date a document is POSTED on (invoice, bill, journal, payment, credit note, bank transaction), never for a report or filter date. A date in a `closed` or `locked` fiscal period is refused at the field (validity code `'closed-period'`, message names the period and its state) and its day is disabled, with the reason as its title, in the calendar; a date outside the current financial year shows an amber `warning` (FieldFrame, `role="status"`) and is still accepted. The rule is the pure `src/lib/fiscalDateCheck.ts`; the periods come from `useFiscalCalendar` (one `GET /api/accounting/fiscal-periods` per company, shared for 60 s). Until they load, or if the request fails, nothing is blocked: the server (ClosedFiscalPeriodError) still judges every save, the field only says so earlier. A date no period covers is not blocked (the period is created on posting); `closing` is not blocked. **No lock date:** `companies.lockdown_date` is read only by payroll year-end status; no posting path enforces it, so the field does not either. Every DateField (not just posting ones) reads `y` as the first day and `r` as the last day of the financial year (periods when loaded, else the company's start month).
