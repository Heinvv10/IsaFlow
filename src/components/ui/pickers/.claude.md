# src/components/ui/pickers/ (shared record pickers)

`ContactPicker` (customers | suppliers), `AccountPicker` (GL accounts), `ItemPicker`, `TaxRatePicker` - labelled,
searchable, keyboard-navigable single-selects built on `Select`. Import from `@/components/ui`.

## Caller contract
- `label` is required (it is the accessible name; the search box is named `Search <label>`).
- `onChange(value, option)`; a record outside the loaded page shows `valueLabel`. `AccountPicker` also takes
  `valueKey="code"` (value = account code, for code-keyed reports), `accountType`, `accountSubtype`, `refine(rows)`.
- `onCreateNew(query)` adds a trailing `+ Create new <noun> "<query>"` row. The picker never creates anything.

## Rules
- Lazy: nothing is fetched until the dropdown opens; every open refetches. Typing is debounced (250 ms) and a newer
  request cancels the older one (`useRemoteOptions`).
- A failed load shows an alert INSTEAD of the list (never an empty list) and offers no create row. `apiFetch`
  resolves on 4xx/5xx, so every request goes through `apiJson` (`pickerData.ts`), which throws.
- The chart-of-accounts route has no `q`: `AccountPicker` reads the whole chart once per open and filters locally.
  That one request takes no AbortSignal (shared between the name lookup and typeahead; aborting it for one fails the other).
- `TaxRatePicker` is a static list (`none | standard | zero_rated | exempt`, rate from `SA_VAT_RATE_PCT`): there is
  no VAT-code endpoint. Items use `'zero'`, not `'zero_rated'`; this picker does not serve the items form.
- `Select` additions these rely on (all optional): `onSearch`, `onOpenChange`, `loading`, `loadError`, `onCreateNew`,
  `valueOption`, `emptyText`. Keep the combobox ARIA contract: `aria-controls` -> a listbox that exists in every state.
