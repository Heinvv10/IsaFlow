# email-templates-trial/

## Purpose
The four trial lifecycle emails sent by `src/modules/onboarding/services/trialLifecycle/` (day 3 setup nudge, day 10 check-in, 5 days before the end, trial ended). Each file returns `{ subject, html }`.

## Key exports
- `shared.ts`: `TrialEmailPayload`, `trialLayout` (shared header and button, own footer), `upgradeUrl()` (env `TRIAL_UPGRADE_URL` if `https://` or `mailto:`, else a mailto to `LEGAL_ENTITY.contactEmail`), `headerSafe`, `formatEndDate` (Africa/Johannesburg).
- `setupNudge.ts` `renderSetupNudge(payload, steps)` (at most `MAX_SETUP_STEPS`), `checkIn.ts` `renderCheckIn`, `endingSoon.ts` `renderEndingSoon`, `ended.ts` `renderEnded`.

## Critical notes
- Not `emailLayout`: its footer says "do not reply", links a `/preferences` page that does not exist, and carries an em dash.
- Copy rules: plain English, no em dashes, "IsaFlow", no prices, no claims. No unsubscribe line: there is no mechanism behind one, so day 10, ending soon and ended are strictly service mail with no promotional language (no feature pitch, no retention promise, neutral "Contact us" button).
- "Ended" says only what is true today: nothing locks an expired trial; plan-only features may stop.
- Every company, person and link value is escaped; subjects are collapsed to one line.
- Unit test: `tests/unit/lib/trialLifecycleTemplates.test.ts`.
