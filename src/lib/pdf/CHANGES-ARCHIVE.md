## Recent changes
- 2026-10-03 (R-188): the `AUTH_POOL_MAX` default fell from 20 to 10, so `20.0` now gives 10 (not 20) and `10.0` is the default. The render ceiling is `floor(pool/4)`: 2 at the default (was 5), and the default of 3 renders is clamped to 2 SILENTLY when `PDF_MAX_CONCURRENT_RENDERS` is unset (an explicit value above the ceiling still warns once). The bound is up to half the pool: at the old pool of 20 the ceiling was 5 renders = 10 of 20 (50%) and the old default of 3 renders took 6 of 20; now 2 renders = 4 of 10 (40%). The queue bound is 4 (was 6). Operator-visible: an unset `PDF_MAX_CONCURRENT_RENDERS` no longer warns; both env variables take plain digits of 1 or more as given (an explicit value above the ceiling is clamped with a warning). For `PDF_MAX_CONCURRENT_RENDERS` (a count, where smaller is safer) any other finite value above 0 (`1.0`, `1.9`, `2.5`, `0x3`, `3e0`, `+3`, `0.5`) gives `min(default, max(1, floor(value)))` (so `0.5`, `1.0` and `1.9` give 1, `2.5` gives 2, as a floor did before R-188) and anything else gives the default. For `PDF_RENDER_QUEUE_TIMEOUT_MS` (a time) every refused spelling gives the 10 s default, since rounding `0.5` up would be a 1 ms wait that refuses every waiter. Each is logged once as invalid (name, length, digits-only flag, never the text); the result is still clamped to the ceiling, silently. Rollback: `AUTH_POOL_MAX=20` in the prod env and restart.
- 2026-10-02 (R-182): `AUTH_POOL_MAX` is validated (`poolSizeFromEnv`, floor 2). An unusable value (NaN, 0, negative, Infinity) now gives a pool of 10 and a render ceiling of 2 (it was 3: the semaphore's own NaN guard); a numeric refused spelling such as `15.0` gives its own size, and a value of 1 is raised to 2 so a render's re-entry can get a second connection (the ceiling stays 1), and `20.0` still means the default 20.
- 2026-09-07 (task 20c): **`capabilities.metadata` is `'guaranteed' | 'best-effort'`, not a boolean.** `writePdfInfoDictionary` returns the file unchanged for any PDF whose cross-reference section it does not recognise, so a `true` on the Playwright transport told a call site gating PDF/A that the metadata was certainly there. Gotenberg's renderer takes the Info dictionary as a form field and is `guaranteed`; Playwright post-processes and is `best-effort`. The writer now returns `{ pdf, written }` rather than a buffer and a `log.warn`. `PdfMetadata` gained `custom` — non-standard Info keys (`IsaFlowPack`, `IsaFlowPeriod`, `IsaFlowStatus`…), written through `pdfName` escaping, because `pdfinfo` reports `Custom Metadata: no` for a dictionary of standard keys however well populated, and that literal line was the acceptance check. Both transports write them.
- 2026-09-07 (task 20b): `pdfInfoDictionary.ts` added — `page.pdf()` exposes no metadata option, so the Playwright transport appends the Info dictionary as a PDF incremental update instead of logging that it dropped what the call site asked for. `playwrightTransport.capabilities.metadata` stopped saying `false` (see task 20c above for what it says now). It returns the input unchanged for any file it does not fully understand (a cross-reference stream cannot take a classic xref section appended to it).
- 2026-09-06: `withAuth` routed through `verifyPrintToken`; separators banned in all three signed fields; render semaphore added; Chromium reused; print gate scoped to the pack page.
- 2026-09-06 (PR review): the render slot moved OUTSIDE `withAuth` and the wait queue gained a bound; pool constants moved to `src/lib/limits/`.
