# lib/pdf/

## Purpose
Renders one authenticated app page to PDF bytes by photographing the page a user would see. The figures in a PDF are therefore COPIED from the rendered page, never re-derived — a document and the screen behind it cannot disagree on a number.

## Caller contract
`renderPagePdf(options)` is called from API routes (`pages/api/accounting/packs/[id]/pdf.ts`). It mints the print token itself; the token never leaves the process. `APP_URL` must be set and must be reachable **from the Gotenberg container**.

## Main signatures
- `renderPagePdf({ companyId, userId, path, query?, apiPaths?, landscape? }): Promise<Buffer>`
- `withRenderSlot<T>(fn): Promise<T>` / `class RenderCapacityError` (`renderSemaphore.ts`)
- `mintPrintToken(companyId, userId, paths, ttlSeconds = 120)`, `verifyPrintToken(token, requestPath)`, `verifyPrintTokenSignature(token)` (`printAuth.ts`)
- `isPrintRender(router)`, `PRINT_RENDER_PATH` (`printRenderQuery.ts`)
- `chooseTransportName(env)` (`selectTransport.ts`), `buildGotenbergFields(request, env?)`

## Business rules
- **Print token contract**: HMAC-SHA256 over `company|user|paths|exp`, bound to an EXACT set of API pathnames matched with `===` (never a prefix) and to the company. 120-second TTL. It is **replay-bounded by the TTL only** — there is no nonce and no revocation, so a captured token is usable for its remaining lifetime; accepted, because every bound path is a read-only GET and the token is minted per render, server-side, and travels only to the renderer. All three signed fields reject `|` and `\n` on both mint and verify: without that `sign` is not injective and one signature validates a different tenant's payload.
- `withAuth` accepts the token ONLY through `authenticatePrintToken` (`src/lib/auth/withAuthPrint.ts`), which calls `verifyPrintToken`. Never re-implement the path check at a call site: the inline copy is how the tested function ended up with no production caller. The whole branch is disabled unless `PRINT_TOKEN_SECRET` is set and at least 32 characters.
- A genuine token presented on an unbound path 401s **without clearing cookies**; only a forged/expired one clears. Clearing wiped the render's own credentials mid-render.
- **Gotenberg cookies go in the `cookies` form field, never `extraHttpHeaders`** — that header attaches to every resource the page loads, including cross-origin ones, and would leak the print token off-domain. Residual, accepted: Gotenberg's cookie object requires `domain` and offers no host-only/`url` form, so a bare hostname is the tightest scope available and matches subdomains. The container's `--chromium-allow-list` is what contains it — Chromium can only navigate to the app host.
- **In production, an absent or blank `GOTENBERG_URL` THROWS.** It is not a silent fallback to Playwright; that path is reachable only by setting `PDF_TRANSPORT=playwright` deliberately.
- **Concurrency is bounded process-wide** (`renderSemaphore.ts`, default 3 via `PDF_MAX_CONCURRENT_RENDERS`). Each render holds a `withAuth` pool connection AND the browser re-enters the API for the report, so unbounded renders exhaust `AUTH_POOL_MAX` and stall every tenant. Excess waits `PDF_RENDER_QUEUE_TIMEOUT_MS` (default 10s), then the route answers 503. The PPTX route is NOT gated: it launches no browser and makes no inbound call.
- **Both env knobs are CLAMPED to ceilings derived from `src/lib/auth/poolLimits.ts`, never restated there.** The queue wait caps at the pool's `connectionTimeoutMillis` minus a 2s margin — a request waiting for a slot already holds a connection, and a refusal arriving after the pool has failed the next caller refuses work that has already died. Concurrency caps at a quarter of `AUTH_POOL_MAX`, because a render takes at least two connections and the pool must stay usable for other tenants. An over-large value is clamped and logged once, never honoured. Change a pool constant and both bounds move with it.
- **The provider gate is scoped to the pack page**, not global on `?print=1`. `print` is not a reserved parameter, and a global gate would strip an unrelated page's auth and company context with no error. `_app.tsx` gates `AuthProvider`, `CompanyProvider` and the analytics tracker on it: `/api/auth/me` CLEARS the cookie carrying the print token, `/api/accounting/companies` 401s into a redirect to `/login`, and the tracker would record a synthetic pageview for every export.
- The PAGE adds `print-mode` to `<html>` and drops `.dark`, not the renderer — Gotenberg cannot execute a script on our behalf.
- One Chromium is reused for the process; the per-render isolation is the CONTEXT.
