## Current request and contract path

`pages/api/mcp/index.ts` serves public GET discovery from `src/lib/mcp/clientMetadata.ts`, and POST JSON-RPC initialize/tools-list/tools-call using `src/lib/mcp/toolIndex.ts`. POST uses `withBearerAuth` -> `bearerPipeline.ts`: token validation, request transaction, app_user role/GUCs, current membership/account-status checks, then sequential batch dispatch on the one connection. Feature gating applies to POST, batch maximum 20, body cap 1 MB, company limiter 120 calls/minute, pre-auth IP limiter 300/minute (implementation comment documents burst/cache limitations). Responses flush only after transaction finalization.

`McpRegistry` resolves tool -> required scope -> write:post -> optional company assertion -> required write idempotency key -> advisory lock/replay/hash conflict -> metering -> handler inside write savepoint -> audit. Company assertion is injected into write manifests and never selects tenant. Registry strips internal `billable`/`wroteNothing` flags from live and replay wire results. Domain failures use `McpToolResult.content[]`/`isError`; malformed protocol and dispatch failures use JSON-RPC error; authentication failures keep HTTP authentication envelope. Preserve this deliberate distinction.

Existing shared contracts: `src/lib/mcp/contracts/{envelope,cursor,mutation,actor,externalRef,figures}.ts`. Do not rename existing mixed-case report fields. `posted_through` is a watermark, not an immutable materialized snapshot or edit-version history. Existing nullable provenance/completeness semantics must remain honest.

## Confirmed source gaps and limits

1. **Effective permissions missing from MCP dispatch.** `src/lib/auth/bearerPipeline.ts:194` loads current companyRole, but line 195 assigns token scopes unchanged; transport context omits role, and `src/lib/mcp/registry.ts:93` checks only granted scopes. Current account/membership checks exist and must not be incorrectly reported missing. Role downgrades cannot be assumed to remove token authority without explicit intersection.
2. **Schema is discovery documentation, not runtime validator.** `registry.ts:74` dispatches raw args; `writeContacts.ts` explicitly documents enum nonvalidation. Handwritten guards vary. A global strict validator needs compatibility fixtures first: several current handlers intentionally coerce numeric strings, clamp limits or accept omitted/null assertion. Do not silently reject historically valid inputs without root's compatibility decision.
3. **Supplier bank changes use ordinary contact writer.** `tools/writeContacts.ts:109` exposes account number, line 331 calls `updateSupplier`; proposal/verification/version/policy enforcement must be in shared service so other paths cannot bypass.
4. **Payroll detail reveals more than list defaults.** `tools/payrollComponents.ts:119` emits full identity and tax numbers under `read:payroll`; list_employees and irp5_data offer caller-selected reveal without an extra sensitive-data scope. Freeze consistent least-privilege redaction and test both detail and list.
5. **Invocation replay is absent from audit.** `registry.ts:141` returns replay before audit. `audit.ts` uses `mcp_tool_calls` both for history and replay protection. A key-conflict rejected row carries the already-used key and ON CONFLICT drops it. Split attempts from idempotency retention/effect records.
6. **Failed-attempt durability is bounded by outer transaction.** Registry errors are recorded outside the tool savepoint but inside the request transaction; outer rollback/failed COMMIT loses them. `audit.ts:104` fail-closes successful write audit failures, which is good and must survive refactoring. Reads/rejections swallow audit errors; PostgreSQL transaction poisoning still needs real-DB proof.
7. **Concurrent same-key protection already exists.** `audit.ts:46` acquires transaction advisory lock and registry checks argument hash. Old module docs claiming both concurrent handlers run are stale. Preserve this protection; add bounded lock wait, durable per-attempt history and real-DB evidence, not duplicate replacement code based on stale prose.
8. **Misleading tool descriptions reach agents directly.** `tools/bankCoverage.ts:39` calls an empty-day gap evidence of missing lines; spec forbids this inference. `tools/auditTrail.ts:25` asserts all production journals have identical raiser/poster and line 30 asserts five audit rows; static text cannot establish current production facts. Remove historical numeric/absolute claims and report measured source coverage only.
9. **No generic dry-run fence.** Only 25/62 writes advertise dry_run. Sending dry_run to another tool does not centrally prevent mutation. Add explicit unsupported-preview rejection before handler or document per-tool supported capability; never retrofit silently to a write-capable handler.
10. **Non-ledger history is not audit_trail.** It enumerates GL entries; customer/supplier, components, rules, locks, approvals and drafts need change-event capture. Existing historical actor inference must remain flagged, not converted into a recorded human claim.

## Concrete fixtures and expected-red scenarios

Use tenant A/B, A users preparer and independent approver, B user, two tokens for preparer (PAT and OAuth), a revoked token, downgraded approver, deactivated user, current/dormant grants; nonoverlapping UUIDs and obvious synthetic sensitive values. Populate >401 documents/findings to force three 200-row pages; 50,000 ledger rows and 10,000 bank lines for bounded-scan trials. Those sizes are proposed local capacity fixtures, not baseline measured limits.

- All 131: valid args success contract, missing/wrong scope no handler, post-only grant cannot substitute tool scope, foreign every parent/child identifier same generic miss, malformed nested arrays/types rejected before query.
- Write fixture: correct/mismatched company assertion; absent/blank key; same key+same args one effect and two invocation attempts; same key+different args conflict recorded; different tools/tenants do not collide; per-user namespace only where declared.
- Dry-run fixture: each of 25 advertised tools performs zero domain writes and consumes no approval/key; subsequent actual call same key executes once. For other 37 writes, unexpected dry_run must not silently execute while caller expects preview.
- Downgrade same active token from authorized role to viewer, then invoke supplier bank edit/payroll approval; expect deny even though token still lists old scopes. Current code gap predicts failure; not yet executed.
- Read payroll with ordinary payroll permission via get_employee/list_employees/irp5_data; expect consistent masked values; reveal denied without dedicated current effective permission. get_employee currently emits raw values; expected red before patch.
- Call a current write twice with same key: financial effect one, invocation count two. Current replay early-return predicts missing second attempt. Conflict retry likewise must appear separately.
- Throw after successful service DML: savepoint rolls back effect, attempt survives. Then force outer COMMIT failure/rollback: failed invocation still retained by durable bounded path, committed event absent.
- Approval: same person/different tokens, revoked role, foreign tenant, edited amount/beneficiary/document/policy, expiry/rejection/cancellation all deny. Two concurrent consumers yield one success. Valid independent approval executes once. Amount split aggregate control uses server totals.
- Bank proposal: direct REST/import/contact bank update cannot bypass; rejected change preserves old bank; prepared payment carries beneficiary version and is held/reapproved after material change; foreign evidence never validates proposal.
- Detective: recurring legitimate invoice/payment distinguishable from candidate duplicate; 401 findings totals constant over pages; failed check unknown, not overall pass; transaction-free day never missing-source evidence; absence independent statement unknown; payroll shared-account alert masks account values.
- Snapshot: concurrent backdated writer does not produce mixed population; repeated canonical hash stable; changed rendering does not change source hash; altered retained evidence detected; original reconstructable; cross-tenant export denied; failed recheck cannot close finding; high-risk self-verification denied; recurrence reopens.
