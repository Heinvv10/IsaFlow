# Genuine indexless retained snapshot conversion

Plan-only owner invoice_evidence; exact base75fb304d9. Root owns request/schema/registry freeze and migration allocation. No runtime changes or heavy commands in this task.

## Confirmed path and available trust

`enqueueAuditComparison` immediately requires two `readAuditSnapshotIndexHeader` results. The latter joins the signed original index, original snapshot and succeeded result pointer; a genuine pre-index snapshot therefore refuses before enqueue. Companion-only conversion in `ensureComparisonSource` cannot repair that foreground prerequisite. `getAuditJob` also calls `readAuditComparisonInputs`, so merely loosening enqueue would still make pending status/replay fail.

`openAuditJobRequest` independently opens the original protected intent, binds company/job/person/kind and recomputes the request hash. `auditSnapshotPermissions(saved.request)` therefore supplies bounded, authenticated intended-domain permissions WITHOUT loading snapshot contents. It does not prove what contents were retained. The worker must later call the existing original-seal verifier, verify the independent snapshot HMAC and expected company/snapshot identity, and assert the retained body against that same original request. An adjacent `s.canonical_hash` can be compared after authentication; it must never become the trust anchor for a pending request.

`readRetainedAuditSnapshotSeal` already performs these worker-only checks. `readRetainedAuditSnapshot` additionally loads and verifies the exact retained artifact population. `buildSnapshotIndex` requires original artifact bytes: its evidence section includes their base64 bytes. A metadata-only original index must NOT be labeled a complete original index. Missing retained artifacts fail conversion atomically; comparison companion metadata alone cannot conceal that failure. Original independent signing-key availability is a prerequisite; unknown old keys or genuinely unsigned historical snapshots remain explicit unsupported evidence, never re-signed as trusted.

## Proposed contract: versioned deferred source verification

Keep the public `{firstSnapshotId,secondSnapshotId,idempotencyKey}` unchanged. Preserve parsing/execution of all existing stored comparison requests exactly. Introduce a disjoint stored v2 with `requestVersion:2`, `sourceVerification:'worker'`, public ordered IDs/key, ruleVersion1, exact sorted permission union and two anchors `{snapshotId,sourceJobId,sourceRequestHash}`. Anchor hashes are authenticated ORIGINAL INTENT request hashes, explicitly not snapshot canonical hashes. Do not put unknown/null/zero canonical hashes into fields that currently promise authenticated snapshot hashes. Never mutate the saved v2 request when conversion finishes.

For new enqueues use v2 consistently, whether indexes happen to exist or not; this avoids a different idempotency hash after asynchronous conversion. Existing key lookup stays under the current per-company/person advisory lock. Authenticate the existing saved request, compare its public ordered IDs/key to this call, and recheck its saved source anchors/current permissions before returning its existing status. Preserve existing v1 hash bindings. A same-key changed source order refuses; same key by a second person remains a distinct job. Current checks run before cached MCP replay too.

New bounded `readAuditSnapshotIntentMetadata(ctx,snapshotId)` selects only original snapshot id/job linkage, succeeded job pointer and protected original intent (bounded DB byte limit), never protected_snapshot or artifact rows. It authenticates kind/audit request/owned identity and current derived domain reads. Returns `{snapshotId,sourceJobId,sourceRequestHash,permissions}`; no claimed content hash. `readPendingComparisonInputs` checks both anchors and union against current metadata. Deliberately corrupt original seals may enqueue successfully, then fail authenticated worker verification: queued status must not describe sources as verified. No reads trigger conversion.

`getAuditJob` keeps requester ownership and uses that bounded metadata authority for v2 queued/running/failed jobs. Succeeded v2 status may additionally validate the signed completed result/current original indexes, but never starts work. Retained page/header reads continue same-company current union authorization; original delegation expiry is irrelevant to retained reading. The result's first/second canonical hashes are authenticated resolved values produced by the worker, cross-checked against the newly authenticated original indexes. Reader validation must branch explicitly for stored v1 pinned hashes versus v2 anchored source requests; do not broadly make existing pinned hashes optional.

## Worker and storage

Add background-only `ensureRetainedSnapshotIndexes(ctx,lease,sourceAnchors,options)` in a new service. It runs under the actual isolated comparison job's current lease/delegation/app_user transaction and unchanged deadline/RSS limits. Acquire source conversion transaction advisory locks for unique `(company,snapshotId)` in fixed code-unit order before checking missing headers (self comparison acquires once; reversed pairs share lock order). Under repeatable-read, a concurrent converter may be invisible after waiting: return retryable40001 on exact conflicting unique insert; never swallow arbitrary integrity errors. Existing complete indexes are authenticated and census-checked, not overwritten or repaired from mutable accounting data.

For a missing original index: verify full original immutable seal and its original request; derive actual body permissions and require exact agreement with saved intended union; load exact retained artifacts with original identity/length/hash verification; invoke `buildSnapshotIndex`. Publish the original header, every item and every chunk with exact returned-ID/count validation in bounded SQL batches. The existing publisher assumes snapshotId==lease.jobId, so extract a shared material writer accepting explicit targetSnapshotId plus actual build lease; keep normal snapshot publisher's original bound checks. Never pass a comparison lease masquerading as the old snapshot job.

Then build/retain the comparison companion from the same authenticated original seal using the existing source cryptographic domains and source-ID/ordinal bindings. Compare both projected streams and publish the normal result header/items/success pointer. All newly converted indexes, companion rows and comparison output belong to the same worker transaction/savepoint. Failure/cancel/deadline/expired lease rolls them back together. Pre-existing originals/indexes remain byte-for-byte unchanged. No foreground full-material or binary load; no arbitrary smaller admitted population/byte limit.

Migration required, root allocates: migration652 original-index INSERT policies permit only the original snapshot requester. A different currently authorized comparison requester cannot currently build its historical index. Add nullable historical build-lineage columns to original index headers (`build_job_id`, `build_generation`, `build_lease_id`) with same-company job FK and all-or-none constraint; existing retained rows remain readable without inventing historical leases. Require actual non-null current live snapshot/compare builder lineage on every NEW header insertion, and child INSERT policy checks its parent's current live builder lease/generation/requester. Update normal snapshot publisher to supply its actual lease. Snapshot builder must target itself; comparison builder's source binding is additionally enforced by authenticated saved request in the shared publisher. Preserve SELECT-only/INSERT-only app_user grants: no UPDATE/DELETE repair privileges. Root should decide exact DDL/backfill compatibility; do not simply loosen policies to company membership.

## Mandatory failing scenarios and acceptance

- Current baseline actual indexless enqueue refusal; queued v2 accepted with two authenticated original intent anchors but no content-hash claim. Repeated status/replay reads leave indexes, attempts and artifacts untouched.
- Actual worker conversion of both missing sides, mixed existing/missing, self comparison and differently owned same-company originals. Three-page original index and comparison paging reproduce original canonical material and deterministic comparison hash. Protected original rows/artifact bytes before/after unchanged.
- Missing/tampered original HMAC plus changed adjacent plain hash cannot publish. Foreign/revoked current permissions fail before cached replay and in worker. Original intent tampering, wrong source request/kind/pointer and mismatched body-domain permissions fail. Expired original delegation still readable; expired new conversion delegation cannot execute.
- Missing/corrupt retained artifact refuses without any partial original index, companion or result. Inject suppressed header/item/chunk INSERT independently; require exact affected sets and rollback. Existing complete index corruption refuses instead of silently rebuilding trusted material.
- Two real processes convert the same source, including reversed pairs and self pair; one conversion only, retryable serialization/unique race safely reuses verified committed output. Actual hard kill after partial writes, lease expiration/new generation and retry: no published partial index/result, stale generation cannot write. Do not use sequential Promise-only mocks as this concurrency evidence.
- Actual100k source population and large retained evidence under unchanged isolated worker bounds after explicit resource lease. Record conversion's extra index/artifact work honestly; current comparison small tests are not scale proof. If bound failure occurs, optimize the true producer or define a separately leased conversion stage under a new root-approved contract; never silently truncate or extend the deadline.

This is a proposed design, not an implemented or verified capability. Migration number and exact v2 union/lineage schema require central freeze before source edits.
