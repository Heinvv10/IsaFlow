# Payroll controls: materializer checkpoint

Exact base `d6d8b48f`, isolated branch `feat/mcp-forensic-payroll-writers-20260909`. This checkpoint contains the payroll materializer, exact journal-plan adapter and their tests. Shared writer changes remain uncommitted pending root dispatcher/generated-journal integration and independent core review.

`materializePayrollOperation(ctx, ref)` supports payroll_run.post and payroll_run.reopen and returns the common material shape with supplierId empty. Approval and direct posting will share payroll_run.post. Payroll reopening binds a frozen reversal target date and retains the original journal link through after-effect materialization. No payroll financial effect is performed by this materializer.

The source collector acquires control-payroll:<company> before row locks. Calling authorization/policy code must run before that fence. It locks the owned company, run, run lines, current company employees and components/assignments, costing allocations/mappings/centres, GL accounts, loans/schedules/payments, leave types/balances and bank details. Owned parent joins protect child tables without company_id. Existing linked journal/lines/accounts and target fiscal period are also bound. Current full company payroll populations deliberately invalidate approvals on changes to other employees; this is conservative and may require narrower persisted calculation snapshots later.

Money comes from decimal text, reconciles run header totals to employee lines, uses actual employee/employer UIF rather than assuming equal halves, and retains precision with a private Decimal context. Cost-centre allocations distribute residual cents deterministically and require 100 percent. Missing/ambiguous/inactive accounts, nonpositive/unbalanced money, foreign employees/components and uncovered/ambiguous periods refuse. The existing labour formula subtracts ETI without a matching credit offset; unbalanced ETI-positive input is refused instead of inventing statutory treatment. Company default_currency is the explicit locked ledger source. Payroll facts remain under the payroll_run evidence type, whose generic projection excludes amounts and personal details.

## Calculation freshness and population limits

Independent review of `71f1c85b` identified that an approval could bind newly changed employee inputs to old calculated lines. Posting now requires the latest immutable control_payroll_calculations receipt to match both current authoritative input populations and persisted calculation outputs. A missing legacy receipt or changed input/output refuses with an explicit recalculation instruction. Calculation will write the receipt only after its loan/line/total mutations and encrypted calculated event, at that event's newVersion. Header workflow status, journal link and timestamps are excluded from output hashes; monetary totals, period, employee count and persisted lines are included. Reopen can reverse a historical journal even when subsequent employee inputs differ.

Every source population query now limits to 10,001 rows and refuses any population above 10,000, rather than hashing a truncated set.
