## Shared contracts proposed for root freeze

- `ControlContext`: authenticated companyId, principalId (person), connectionId/grantId nullable, actingFirmId nullable, requestId, operationId; permissions freshly resolved server-side; never accept these from MCP args. Carry transaction context explicitly or require ALS transaction.
- `ChangeEvent`: eventId, context, entityType/id, previousVersion/newVersion, operation/policy versions, actual occurredAt using clock_timestamp, accountingDate nullable, allowlisted protected before/after, action, provenance, outcome=committed. Insert same transaction as mutation; rollback eliminates it. Unknown legacy actor/version is explicit, never backfilled with invented person/time.
- `InvocationAttempt`: unique attemptId, request/operation correlation, argsHash (not raw arguments), safe tool/result summary, startedAt/completedAt, outcome started/rejected/error/replayed/succeeded, committedEffectId nullable. Started row must commit on a separate bounded pool/transaction BEFORE effect; final status update separately, with unfinished state after process loss. Actual effect truth must come from committed effect row, not premature success label. Use authenticated tenant GUCs on dedicated connection, no user-controlled SQL; bounded timeout/pool/backpressure. No FK dependency on uncommitted effect rows. Fail closed before high-risk writes if durable attempt cannot be accepted; finished audit failure leaves recoverable started state, not fake success.
- Separate `operation_idempotency` durable key/hash/replay result/effectId unique(company, tool, normalized key), transaction lock unchanged; migrate existing successful keys before disabling legacy fallback. Audit retention must never delete dedup keys. Replay payload restricted to service account/current effective permission checks.
- `ControlCheckResult`: checkId/version, status pass/fail/unknown/error, candidate vs confirmed classification, universeCount/excludedCount/findingCount and decimal-string amounts, bounded findings/cursor, source cutoff+capturedAt, coverage and missing-source reasons, source version/evidence refs; aggregate status never pass if error/unknown remains. Stable finding identity excludes run time and severity; include company/check/normalized sorted entity ids/condition kind.
- `EvidenceNode/Edge`: store+id+entityVersion/hash, explicit relation and provenance recorded/derived/candidate, authorized parent endpoints, missing/ambiguous/reversed flags, traversal depth/node/page budgets; no raw object URLs for unauthorized callers.
- `AuditSnapshot`: immutable materialized canonical records and check outputs, accounting cutoff, capture time, schema/check versions, source versions, exclusions, counts/totals, canonical SHA256; separate rendered artifact SHA256. Dedicated worker opens fresh repeatable-read transaction BEFORE first query; nested savepoint cannot promote existing READ COMMITTED request. Retain actual evidence bytes in content-addressed tenant storage, explicit missing/unavailable entry when unavailable.
- `ControlException`: stable finding key, occurrence history, owner/due, status open/in_review/remediated/accepted_risk, evidence/recheck references, reviewer identity; immutable resolution events; high risk independent verifier different from assignee/remediator; recurrence reopens and keeps prior acceptance visible.
