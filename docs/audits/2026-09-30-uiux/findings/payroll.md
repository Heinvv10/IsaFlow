# Payroll & Bureau — audit

Scope: every `/payroll/*` route, `/bureau`, `/bureau/clients`, `/accounting/timesheets`, `/accounting/time-tracking`.
Code: `.worktrees/uiux-audit` @ 66e776d81. App: localhost:3200 (isaflow_dev). Company: ISAFlow Demo (plus Brightsphere for empty states).
Shots: `$AUD/shots/payroll/` (desktop), `*.m.png` (390px mobile), `flow/` (interactive), `bs/` (Brightsphere).
Nothing was calculated, approved, posted, filed or saved. No UXAUDIT records were created: the new-employee and leave forms were filled for validation only and never submitted.

## Verdict
Payroll lives inside the main app shell (Library → Payroll) and has its own 4-group sub-nav and a VIP-style "period bar", so it looks consistent with the rest of the app. The lifecycle breaks at the most important step, though. A calculated run has **no Approve button anywhere in the UI**, there are **no payslips**, and there is no payment/EFT step. The payroll **Year-End Workflow link redirects to the irreversible GL fiscal-year close**. The run detail cannot explain how Gross becomes Net. The statutory screens also disagree with each other: EMP501 says "ready to submit" while IRP5 shows 0 of 10 certificates ready. The bureau cockpit has payroll signals, but I couldn't test it in the browser because the QA user isn't a bureau member. The code shows it would flag every approved run as pending forever. Overall this is a set of record-keeping forms. There is no guided payroll cycle yet.

## Top 5 recommendations for this area
1. **Close the pay-run loop in the UI.** Stepper: Calculate → Review (variance + warnings) → **Approve** → Payslips → Bank file / Mark paid → EMP201. Today it stops at "calculated" (PAY-01, PAY-05, PAY-13).
2. **Fix the statutory truth-tellers.** Unshadow the payroll year-end page, load or fall back SARS codes for 2027, and make EMP501 reconcile against EMP201 as filed and the GL (PAY-02, PAY-03, PAY-04).
3. **Make the run explain its numbers.** Show deductions and employer contributions, split UIF, add a totals row, and name the employee on every warning. Grouped warnings should fix themselves (DOB from ID number, bank details) in one click (PAY-06, PAY-07, PAY-08).
4. **One payroll context.** A payroll home/cockpit with the right "current period", EMP201 and IRP5/EMP501 kept inside the Payroll nav, and leave approvals as an operational queue rather than Setup (PAY-10, PAY-11, PAY-19, PAY-20, PAY-25).
5. **Bureau payroll board.** Clients × this month's payroll steps and EMP201 due, fed by the existing compliance calendar, with approved runs no longer shown as pending (PAY-13, PAY-27).
