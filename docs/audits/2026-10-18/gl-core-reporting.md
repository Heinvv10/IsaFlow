## PLAUSIBLE (not confirmed)

- `reports/balanceSheetService.ts:134-141` excludes level-1/2 accounts that have children, while `calculateRetainedEarnings`, the TB and the GL include them. A posted line on such a header (from history before the header guard, or an account that later gained children) drops out of the BS only, so A ≠ L + E, and the only signal is a `log.warn` (line 200).
- `gl/assetDepreciationPosting.ts:~130` (legacy single-asset `postAssetDepreciationToGL`) is a born-posted insert with no period-status check. The batch run is guarded by its planner.
- The Sage supplier-invoice commit (`sageMigrationCommitService.ts:277`) and AR historical import (`customerInvoiceGlPosting.ts:~161`) skip the period check on purpose. They can land P&L lines in a year that already has a `YE-` journal, leaving post-close residual P&L.
- The wizard `importOpeningBalances` skips rows whose account is not found after the balance pre-check, then throws "not balanced" after `reversePriorOpeningBalances` has run. Whether that commits depends on the route's status mapping.
- `getCurrentOpenPeriod`/`getCurrentFiscalPeriod` use `CURRENT_DATE` in the DB timezone, which picks the previous period from 00:00 to 02:00 SAST on the 1st if the DB runs in UTC.
- Reversing a journal whose account was later deactivated fails (`assertNoInactiveAccountLines` has no reversal exemption). The draft is cleaned up, so nothing is corrupted.
- Free-text `vatType` on journal lines has no CHECK constraint (mig 210); how VAT201 treats an unknown value was not traced.
- The entry-number advisory lock (mig 857) has no lock_timeout, so cross-year inserts in opposite order in one tx could deadlock. No app path was found that does this.
