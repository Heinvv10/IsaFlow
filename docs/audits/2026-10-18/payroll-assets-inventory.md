## PLAUSIBLE (unverified)

- Payroll: when deductions exceed gross on a line, `netPay` is floored at 0 (`payrollCalculator.ts:94`), but the journal's 2175 residual (`gross − paye − uifEe − net`) then disagrees with the deductions actually recorded.
- Payroll: medical credits count dependants as "main + first" when the employee is not the main member (`payrollCalculator.ts:49-51`).
- Payroll: ETI `monthlyRemuneration` is total `grossPay`, including non-taxable reimbursive travel (3703), which can push an employee over the R7 500 ceiling.
- Payroll: `GET /api/payroll/runs/[id]/journal-plan` lacks `withPayrollDetailAccess`, so a single-employee cost centre's labour line reveals that salary.
- Payroll: an active employee whose `start_date` is after the period is still included (only `status` is filtered).
- Practice: grouped WIP invoice lines use `unit_price = round2(value/hours)`, so unit × qty ≠ amount.
- Projects: project profitability sums are unrounded floats.
- WIP: `getWipByClient` counts NULL `line_total` as R0 while invoicing refuses it.
- Assets: `afs-summary.ts:75` counts an asset bought in a prior year but first depreciated this year as a current-year addition.
- Assets: concurrent runs for different periods read a stale `policy_acc_dep` before the row lock, which could over-depreciate at the final-month true-up.
- Assets: the final-month true-up fires only when `monthsElapsed` exactly equals the life, so a missed month strands the shortfall.
- Assets: the closed-period check is taken at plan time without a lock.
- Assets: SARS rates for office equipment (5 y vs BGR 7's 3 y), machinery and small tools are unverified. The R5 000 capitalisation default is labelled "SARS guidance", but the SARS small-item limit is R7 000.
- Assets: API POST defaults `salvage_value` to 0, so category `residual_pct` is ignored. The reconciliation caps at 5 000 assets.
