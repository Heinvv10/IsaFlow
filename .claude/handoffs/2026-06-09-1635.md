## Context the next session needs
- **The resolver split is load-bearing.** `getActiveModuleId` = the verbatim original route→module mapping (used by the secondary nav to know which module you're in); `getActiveTabId` = a wrapper that collapses the 8 demoted ids → `'library'`. Don't "simplify" by merging them — the secondary bar needs the raw module id while the top bar needs the collapsed one.
- **A `practice` branch was ADDED to `getActiveModuleId`** (`if (pathname.startsWith('/accounting/practice')) return 'practice';`). The original resolver never resolved practice routes (the old Practice tab silently never highlighted). Keep it — without it, practice routes mis-highlight Dashboard + get no secondary bar.
- **`SecondaryModuleNav` self-gates** (returns null for any moduleId not in its 8-module `MODULE_BY_ID`), so `AppLayout` renders it unconditionally in top mode with NO duplicated demoted-list. Don't add a `showSecondaryNav` boolean or a `DEMOTED` array in AppLayout — that would be the demoted-list's 4th copy.
- **The demoted-module list lives in 3 places** (`DEMOTED_MODULE_IDS` in activeTab.ts, `LIBRARY_MODULES`/`MODULE_TABS` in library.ts, `MODULE_BY_ID` in secondaryNav.ts). `tests/unit/nav/demotedConsistency.test.ts` asserts all 3 are set-equal — adding/removing a demoted module without updating all 3 fails CI. Update all 3 together.
- **topItems (quick-creates) are intentionally NOT in the Library flyout or secondary bar** — `CreateNewMenu` owns quick-create. The spec was reconciled to match (commit on-branch). Don't "fix" this by folding topItems back in.
- **Library tab is a link+flyout** (both `href` and `items`). `ModuleNav`/`SidebarNav` got a dedicated branch for that shape: label is a `<Link>`, hover opens the flyout. The hover-close timer in ModuleNav clears on EVERY tab enter (not just link+flyout) to avoid snapping an adjacent dropdown shut.
