## Context the next session needs

- **The bug was not where the tech-debt note said it was.** `project_known_bugs.md` and the previous handoff both pointed at `continuousCloseService.buildCloseState`. That function does not exist — `continuousCloseService.ts` is pure planning logic with no SQL. The queries were inline in `pages/api/accounting/continuous-close.ts`. The note also missed the fourth dead reference (`customer_invoices.purchase_order_ref`).
- **Unit tests and integration tests split on DB access.** `vitest.config.ts` includes `tests/unit/**` and injects a dummy `DATABASE_URL`; `vitest.integration.config.ts` includes `tests/integration/**`. `scripts/ci/run-ci.sh` runs integration **only if `DATABASE_URL` is set in the environment** — so `bun run ci` in a bare shell silently skips it. To run the full gate you must export the env first.
- **`.env.local` cannot be `source`d.** Line 34 is `SMTP_FROM=ISAFlow <noreply@isaflow.co.za>` — unquoted, so bash chokes on the `<`. Build an export file with a small Python loader using `shlex.quote`, or export individual vars.
- **`sql` from `@/lib/neon` falls back to the pool when no ALS store is bound** (`src/lib/neon.ts:91-97`). That is why an integration test can import a service and call it directly without a request context.
- Fixture UUIDs must be valid hex — `...cc1t0` was rejected as `invalid input syntax for type uuid`. Cost a round trip.
- `gl_journal_entries.created_by` is a **UUID**, not a varchar; `customer_invoices.created_by` **is** a varchar. They differ.
- `customer_invoices.invoice_date` / `due_date` appear to carry defaults — a "sparse" fixture must set them to `NULL` explicitly or it scores 0.2 instead of 0.
