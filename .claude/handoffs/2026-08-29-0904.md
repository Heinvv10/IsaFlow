## Done this session — all deployed and verified

### PR #276 — DATE columns read back a day early on UTC+2 (`99a61c90`)

Root cause: `node-postgres` parses a `DATE` column (OID 1082) into a JS `Date` at **local midnight**;
`.toISOString()` then read the UTC instant, which on SAST is 22:00 the **previous day**. Every DATE
value could render, export, filter or post one day early.

Fixed at the root, not per-helper: `src/lib/pgTypes.ts` registers
`types.setTypeParser(1082, v => v)` so DATE comes back as the literal `'YYYY-MM-DD'` string Postgres
sent. No `Date` is constructed, so no timezone can shift it. Registered from `src/lib/neon.ts` and
from every auth entrypoint that opens its own pool (`withAuth`, `bearerPipeline`,
`withExtensionToken`, `withInviteToken`, `withPlatformAdmin.pools`, `verify-email`,
`invitations/[token]/accept`).

`fmtDate` (`src/lib/fmtDate.ts`) stays canonical for mixed-shape values — TIMESTAMP/TIMESTAMPTZ still
arrive as `Date`. It lives in **its own module, NOT `@/lib/neon`**: 173 test files `vi.mock` that
module and mocking it deletes the export (broke 110 tests once). ~110 call sites moved off
`.toISOString().split('T')[0]`.

Second commit: `reverseJournalEntry` dates the contra to the **original entry date** when that period
is open, falling back to today when closed. Hein confirmed this behaviour explicitly before push. The
same commit deletes the draft contra when `postJournalEntry` fails.

### PR #277 — bulk allocation skips unresolved lines (`5f685ff0`)

A batch refused **whole** when any line's selector did not resolve (unknown `bank_reference`, an
ambiguous one, or a `transaction_id` naming no row in this company). One bad line in a 500-line
statement batch posted nothing and could only be found by bisecting.

The rule now, stated in `src/lib/mcp/.claude.md`: **a refusal is about the REQUEST; a skip is about
the DATA.** Malformed lines, oversize batches, duplicate lines and cross-tenant ownership stay fatal —
and ownership stays **batch-level** so naming a line never becomes an existence oracle. Everything the
data says about one row is a skip. `SkippedLine.transaction_id` is now `string | null`.
`nothingToPostText` still refuses an all-skipped batch, so a wholly wrong list cannot read as
`posted: 0`.

`reverse_bank_allocation_batch` moved to `src/lib/mcp/tools/writeBankReverseBatch.ts` to stay under
the 300-line cap (212 + 118).

### PR #278 — plain bank CSV importable (`1dc88e88`)

Two defects, reproduced against the real statements before any change:

1. Every `detectBankFormat` branch required an "Account Number" column, a debit/credit **pair**, or
   FNB's quoted headers. A plain `Date,Description,Amount,Balance` file — what every SA bank's
   "export to CSV" produces — matched nothing and threw *"please specify the bank"*. **There is no
   bank picker in the import UI**, so that was unactionable: the file was unimportable.
   Parsing was never broken — ABSA's parser is header-mapped and read it correctly. The mapping moved
   to `bankCsvParserGeneric.ts`; detection now calls the **same mapper the parser uses**, so it can
   never claim a file the parser reads as zero rows. `generic` is tried **last** (a debit/credit
   layout read as single-amount loses the sign on every debit).
2. Naming the wrong bank imported **zero rows silently**. `parseStatement` now throws
   `StatementNotImportableError` — typed, because `writeBankImport.ts` rethrows anything else and the
   registry then records a system failure and refunds the debit. A file with **no data rows** still
   imports (a bank can export an empty period); only a file that HAS rows and produced nothing is
   refused.

Also documented in `bankQifParser.ts`: **`N` is the only prefix that populates `reference`.** `P` and
`M` fold into `description`. That column is what MCP allocation resolves a `bank_reference` against,
so a QIF exporting its reference under `P`/`M` imports and displays fine but is invisible to
`allocate_bank_transaction` / `bulk_allocate_bank_transactions` by reference.
