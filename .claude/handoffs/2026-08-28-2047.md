## Status

The date off-by-one is fixed, reviewed by two independent blind reviewers, and committed on
`fix/date-utc-offbyone`. All three review findings were fixed. Nothing is pushed and no PR exists.
The root cause was a single mechanism behind all three of Hein's reported symptoms: node-postgres
returns a `DATE` column (OID 1082) as a JS `Date` at **local** midnight, this host runs SAST (UTC+2),
so any `.toISOString()` on it converted to UTC and reported the **previous day**.

Proven, not inferred, against `isaflow_dev`:

```
SELECT '2026-08-28'::date  ->  Fri Aug 28 2026 00:00:00 GMT+0200
  .toISOString().split('T')[0]  ->  2026-08-27   WRONG
  fmtDate()  (local getters)    ->  2026-08-28   correct
```

## What got done this session

**Commit `7c512cd6` — `fix(dates): DATE columns no longer read back a day early on UTC+2`** (128 files)

- **`src/lib/pgTypes.ts` (new)** — the root fix. `pg.types.setTypeParser(pg.types.builtins.DATE, v => v)`
  so DATE arrives as a plain `'YYYY-MM-DD'` string. Only 1082 is overridden; TIMESTAMP (1114) and
  TIMESTAMPTZ (1184) keep Date parsing. Imported **for its side effect** by all 9 app pool-constructing
  files, because `pg.types` is a module singleton and the override only applies once *some* module has
  called it — a request served by a route that never imported `neon.ts` would otherwise get the default.
- **`src/lib/fmtDate.ts` (new)** — `fmtDate` moved OUT of `@/lib/neon`. See "Context" below for why.
  `neon.ts` re-exports it, so old import paths still work.
- **Ledger write paths fixed** (this is the VAT-affecting part):
  - `bankRuleAutoPostLine.ts:63` and `provisionalPostingService.ts:201` derived a journal's `entry_date`
    from `bank_transactions.transaction_date` via `toISOString`. A transaction on the 1st of a month
    posted a journal dated the last day of the **previous** month — a different VAT period.
  - `bankRuleAutoPostLine` then ran `getPeriodStatusForDate()` against that same shifted date, so the
    open-period check validated the **wrong period**.
- **`search_gl` / GL ledger** — `accountLedgerService.toDateString` returned every `entry_date` a day early.
- **Second bug class Hein did not report** — `cashFlowForecastService.ts:87,118,133` and
  `reports-cash-flow.ts:39` build month buckets from LOCAL year/month components; `toISOString` named
  every bucket for the **previous month**. Always wrong, not just in a window.
- **Reversal re-dating** — `reverseJournalEntry` stamped every contra with today's date. It now carries
  the ORIGINAL entry's date when that period is open, falling back to today when it is not.
- **`periodStatusService.ts` (new)** — `getPeriodStatusForDate` + `PeriodStatus` moved from the bank
  module to the GL module (now that `reverseJournalEntry` needs it). `bankRulesMatchingHelpers.ts`

## Context the next session needs

- **Why `fmtDate` moved out of `@/lib/neon`.** The sweep initially broke **110 tests**. 173 test files
  call `vi.mock('@/lib/neon', ...)` with an explicit factory, and mocking the module *deletes* any export
  the factory omits — so every service that newly imported `fmtDate` broke its own tests with
  `No "fmtDate" export is defined on the "@/lib/neon" mock`. `fmtDate` touches no pool and no query;
  moving it to `src/lib/fmtDate.ts` removes that landmine permanently. **Do not move it back.**
- **New test-mock requirement:** any `vi.mock('pg', ...)` must now include a `types` stub, or the
  side-effect import of `@/lib/pgTypes` throws
  `Cannot read properties of undefined (reading 'setTypeParser')` before the test body runs. Helper:
  `tests/unit/helpers/pgTypesMock.ts`. Five auth test files already use it.
- **`noUnusedLocals` is NOT set in `tsconfig.json`** — `bun run type-check` will not catch an unused
  import. Do not rely on it for that.
- **Blast-radius checks already done (do not redo):**
  - Zero call sites invoke `Date` methods (`.getTime()`, `.getFullYear()`, …) directly on a date-column
    value, so the string switch breaks nothing.
  - `''::DATE` throws `22007` immediately — a loud failure, not a silent misdate. Unreachable anyway:
    `bank_transactions.transaction_date` and `gl_journal_entries.entry_date` are both `DATE NOT NULL`.
  - Balance cache does **not** go stale on a back-dated reversal: `createJournalEntry` derives
    `fiscal_period_id` from `entryDate` (and *rejects* a caller-supplied period that doesn't cover it),
    the DB trigger `resolve_je_fiscal_period` also resolves from `NEW.entry_date`, and
    `trg_gl_je_status_balance` fully recomputes `gl_account_balances` on the draft->posted UPDATE.
  - TOCTOU on the period check is not exploitable: `fiscal_periods_no_overlap` is a DB EXCLUDE
    constraint, and `postJournalEntry` re-checks status **by period id** before flipping to posted.
  - Ledger date comparisons happen **in Postgres** behind `::DATE` casts, never in JavaScript — which
    is why the string switch produced no comparison/sort defects.
