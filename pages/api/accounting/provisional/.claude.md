# provisional/

## Endpoints / Modules
PRD-05 Phase 5 bank-first inverted workflow. Provisional JEs are posted from bank transactions before evidence lands; the evidence-attach flow flips them to `ai-evidenced` later.

- `GET  /api/accounting/provisional/outstanding` — list JEs where `gl_journal_entries.needs_evidence=true`, joined with `bank_transactions` (description, amount, transaction_date), `suppliers.name`, + days-since-post.
- `POST /api/accounting/provisional/outstanding` — body `{ bankTxIds: string[] }`. Calls `postProvisional` for each; returns results array.
- `POST /api/accounting/provisional/[jeId]/attach` — body `{ capturedDocumentId: uuid }`. Manual attach via `capture/provisionalEvidenceAttach.ts`: locks bank line → journal → document; 404 journal/document not found (or other tenant), 400 journal reversed / already evidenced / slip already posted or rejected, 409 lock contention; then CLAIMS the slip (`captured_documents.posted_at`) and evidences the journal (`source_document_id`, hash from `raw_bytes_sha256`, `posting_agent='ai-evidenced:v1'`, `needs_evidence=false`, `evidenced_at`) and sets `bank_transactions.status='matched'`. The slip is spent: the provisional journal already expensed the bank line, so no capture route may post it again (R-107). Reversing the provisional journal releases it.

## Auth
`withAuth(withErrorHandler(withWriteAccess(handler)))`.

## Request / Response
ProvisionalEntry shape: `{jeId, bankTxId, bankAccountName, description, amount (absolute), transactionDate, daysOutstanding, predictedSupplierId, predictedSupplierName, predictionConfidence, glAccountId, glAccountName, postedAt}`.

## Business rules
- **Provisional flow**: bank import → `autoProvisionalBatch` (outflows only, confidence ≥ 0.7) → JE stamped `posting_agent='ai-provisional:v1'`, `needs_evidence=true`. `bank_transactions.status='provisional'`, `provisional_je_id` set.
- **Evidence attach**: called fire-and-forget from `/capture/[id]/post` + `ai-invoice-pipeline` after invoice creation. `attachEvidenceToProvisional` matches by supplier_id + ABS(amount) ±R0.01 + transaction_date ±2d. No match → silent null (not all invoices correlate to a provisional).
- **Dismiss is not yet wired** — the UI button shows a toast saying "reversal not yet implemented — manual reversal required". Reversing a posted JE is an auditor-grade operation; Phase 5 explicitly punts to a later pass.

## Learnings
- **D12 (2026-10-04)**: both attaches (manual `[jeId]/attach`, automatic `attachEvidenceToProvisional`) turn the line `matched` with `reconciliation_id = openStampOnly(...)`: a provisional line still carrying a COMPLETED session's stamp (claimed while imported, then provisional-posted) would otherwise join that signed-off session. An in-progress session's stamp is kept. Test: `tests/integration/d12-stale-stamp.int.test.ts`.
- **R-107 (2026-09-24)**: the manual attach had never worked (42703 on two columns `captured_documents` does not have), which hid that it never claimed the slip. A route that has never run is not evidence its logic is safe — fixing the crash is what exposes the defect behind it.
- **Status enum was extended post-FK**: migration 414's DO-block DROP+RECREATE pattern is how we add enum values to CHECK constraints without breaking existing rows.
