# audit-exports/ (PRD-05 Phase 12 — Audit Trail as a Product)

## Endpoints
- `GET /api/accounting/audit-exports` — list company's export packs
- `POST /api/accounting/audit-exports` — build a pack FROM a sealed audit snapshot (forensic step 4): a ZIP (manifest citing the snapshot hash + HMAC, CSVs, the PDF); owner / admin in their own session
- `GET /api/accounting/audit-exports/[id]` — metadata + status (`draft|building|ready|failed`); `?verify=1` re-reads the ZIP against its manifest and verifies the cited snapshot
- `GET /api/accounting/audit-exports/[id]/download` — stream the ZIP (or an older pack's PDF); owner / admin / manager
- `GET /api/accounting/audit-exports/[id]/sessions` — list auditor portal sessions
- `POST /api/accounting/audit-exports/[id]/sessions` — mint auditor access token (shown once)
- `DELETE /api/accounting/audit-exports/[id]/sessions/[sessionId]` — revoke auditor session

## Auth
`withAuth(withErrorHandler(withWriteAccess(...)))` on mutating routes; `withAuth(withErrorHandler(...))` on read-only. All tenant-scoped — auditor portal itself lives elsewhere and uses session tokens minted here.

## Request / Response
- `POST /audit-exports`: `{ periodStart, snapshotId }` or `{ periodStart, periodEnd }` (snapshot taken at periodEnd), `includeComparison?`, `includeSourceDocs?`, `expiresAt?`
- `POST /audit-exports/[id]/sessions`: `{ auditorEmail, ttlHours? }` — `auditorEmail` required, export must be `status='ready'`
- Download sets the ZIP's (or PDF's) `Content-Type`, `Content-Disposition: attachment`, `X-Content-SHA256`

## Business rules
- UUID validated via regex on all `[id]` / `[sessionId]` params before DB hit
- Download blocks unless `status='ready'` and a ZIP or PDF is stored (`exportDownload`)
- PDF pulled from Supabase bucket (`SUPABASE_CAPTURED_DOCS_BUCKET` env; default `captured-documents`)
- Session token returned exactly once on POST — no re-retrieval
