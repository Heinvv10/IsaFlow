# Budget grid API (`pages/api/accounting/budget-grid/`)

The budget workspace's routes (budgets P2). Version lifecycle (create, status, copy, primary, delete) stays in P1's `budget-versions/**`; nothing here creates a version except the seed wizard, through P1's `createVersion`.

## Endpoints

| Method + path | Handler | Purpose |
|---|---|---|
| `GET /api/accounting/budget-grid?version_id=` or `?fiscal_year=` | `index.ts` | Read model (primary, else newest version of the year; `version: null` when the year has none). `&cells_only=1` → cells + token only. |
| `GET /api/accounting/budget-grid/prior-actuals?fiscal_year=&grain=` | `prior-actuals.ts` | PY actuals at `company`/`cc1`/`cc2`/`bu`. |
| `POST /api/accounting/budget-grid/save` | `save.ts` | `{ versionId, expectedUpdatedAt, cells[] }` batch save via Next's bodyParser (4 MB, 413 past it), at most MAX_SAVE_CELLS = 20 000 cells (version lock held ~0.6–2.8 s). A bigger commit (an import, up to MAX_IMPORT_CELLS = 100 000) is CHAINED by the client: each chunk sent with the token the previous save returned. Delete a cell with `amount: null, clear: true` (a null without `clear: true`, `clear: true` with an amount, or the nil UUID as any id is 400 naming the cell). Ids are lower-cased once. `saved` = rows actually changed. |
| `POST /api/accounting/budget-grid/seed` | `seed.ts` | Wizard: new draft version from PY actuals +x%, a version copy, or blank; a plan over MAX_IMPORT_CELLS cells is 400. |
| `GET /api/accounting/budget-grid/template?version_id=&grain=&members=` | `template.ts` | `.xlsx` template (viewers allowed). Rows capped at floor(MAX_IMPORT_CELLS / max(12, months)) = 8 333 at 12 months (400: pick fewer members). |
| `POST /api/accounting/budget-grid/import-preview` | `import-preview.ts` | JSON `{ versionId, fileName?, fileData }` (`fileData` = the .xlsx as standard base64, ≤ 10 MB + 64 KB decoded; Next bodyParser 14 MB; the key is one the request-log scrubber omits) → diff preview. Writes nothing; commit goes through `save` in chunks. |

## Auth
GETs: `withAuth(withErrorHandler(...))`. Writes (save, seed, import-preview): `withAuth(withErrorHandler(withCsrf(withWriteAccess(...))))`. `makePrimary` on seed needs owner/admin (checked in the service). `withRole` is never widened.

## Response contract
Errors go through `respondBudgetVersionError`: 400 input/grain (the message names the account), 403 role, 404 version not found (another tenant's included), 409 `BUDGET_VERSION_LOCKED` / `BUDGET_VERSION_STALE` (`{currentUpdatedAt, status}`), 503 on a held row lock. Types are registered in `src/lib/apiRoutes.ts`.

## Gotchas
- The token is P1's UTC ISO text with microseconds; send back exactly what the read returned.
- An import preview's token goes stale if anyone saves in between: commit then 409s and the user re-runs the preview.
- Bodies are parsed by Next before withAuth (no pooled connection is held while a client uploads). The custom early body reader of rounds 3-8 was deleted in round 9 (review death spiral); do not reintroduce one.
- Template and import-preview run their spreadsheet work in `BUDGET_SPREADSHEET_SLOT` (`src/lib/withCpuSlot.ts`) OUTSIDE withAuth: 2 running, 4 waiting, at most 2 places per user (429), ≤ 10 s wait, else 503 + Retry-After 5.
- import-preview order: CPU slot (outside withAuth; per user 2 places, 429; full 503) → withAuth → CSRF (403) → write access (403) → `budget-import:<userId>` bucket (429) → body shape (400) → version + financial year check (404, before any decode or parse) → base64/decoded size/.xls (400) → parse. Queued requests whose client has gone are skipped. The file never touches disk.
- Rate limits are per USER, charged in the handlers with literal keys (the census reads them): `budget-save:<userId>` 120/min, `budget-import:<userId>` and `budget-template:<userId>` 60/15 min, `budget-prior-actuals:<userId>` 60/min. 429 with Retry-After.
- A save batch that changes nothing returns 200 with the verified token and writes no audit row (no false STALE for others).
- Request logs: `sanitizeRequestBody` omits arrays over 50 items and the `fileData` key, so cells and files are never logged.
