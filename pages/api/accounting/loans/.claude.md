# Loans API routes

PRD-03 loan module REST surface. All wrap `withAuth(withErrorHandler(withCsrf(withWriteAccess(handler))))` so `(req as CompanyAuthedRequest).companyId` is set and writes are gated by the `owner|admin|manager` role. GETs pass through `withWriteAccess` untouched.

## Endpoints

| Method + path | Handler | Purpose |
|---|---|---|
| `GET /api/accounting/loans` | `index.ts` | List loans. `?status=active|closed|written_off`, `?product=bond|...`. |
| `POST /api/accounting/loans` | `index.ts` | Create loan. Body = `LoanCreateInput`. Returns 201 with full loan row. |
| `GET /api/accounting/loans/[id]` | `[id].ts` | Loan detail. 404 if not scoped to the caller's company. |
| `PATCH /api/accounting/loans/[id]` | `[id].ts` | Partial update. Current write surface: `status`, `glAccountId`, `reference`, `description`. |
| `GET /api/accounting/loans/[id]/schedule` | `[id]/schedule.ts` | Get/compute schedule with inputs-hash caching. Response: `{ rows, runId, cached, computedAt }`. |
| `POST /api/accounting/loans/[id]/schedule` | `[id]/schedule.ts` | Preview schedule dry-run. Body: `{ events?: LoanEvent[] }` to override persisted events. Returns `{ rows }`, no persistence. |
| `GET /api/accounting/loans/[id]/events` | `[id]/events.ts` | List events sorted by date. |
| `POST /api/accounting/loans/[id]/events` | `[id]/events.ts` | Add event (LUMP / SKIP / RESTRUCTURE / WRITEOFF). LUMP requires `amount > 0`. |
| `GET /api/accounting/loans/[id]/gl-postings` | `[id]/gl-postings.ts` | List `loan_gl_postings` rows for a loan. |
| `POST /api/accounting/loans/[id]/gl-postings` | `[id]/gl-postings.ts` | Post journals for a period. Body: `{ period: number }`. Blocks when `row.nca_flagged` or period locked. |
| `GET /api/accounting/loans/[id]/compliance` | `[id]/compliance.ts` | Assessment history (NCA + IFRS 9). |
| `POST /api/accounting/loans/[id]/compliance` | `[id]/compliance.ts` | Run assessment. Body: `{ asOfDate?: YYYY-MM-DD }`. Defaults to today. |
| `GET /api/accounting/loans/[id]/payments` | `[id]/payments.ts` | List recorded payments for a loan. |
| `POST /api/accounting/loans/[id]/payments` | `[id]/payments.ts` | Record a payment. Body: `{ paymentDate: YYYY-MM-DD, periodNumber: int, bankAccountId?: uuid }`. Splits principal + interest per schedule, posts GL journal, reduces actual outstanding. UNIQUE per (company, loan, period_number) — second call throws "already recorded". |
| `GET /api/accounting/loans/portfolio/summary` | `portfolio/summary.ts` | KPI strip. `totalOutstanding` is ACTUAL (principal − loan_payments.principal). `totalOutstandingProjected` is the forward schedule estimate. Weighted rate weighted by actuals. |
| `GET /api/accounting/loans/portfolio/rate-sensitivity` | `portfolio/rate-sensitivity.ts` | IFRS 7 rate-risk: aggregate next-12m interest under ±100bp and ±200bp shocks across all active loans. |

## Sibling routes

- `GET|POST /api/accounting/loan-rate-curves` — list tenant + system curves / create tenant curve.
- `GET|POST /api/accounting/loan-rate-curves/[id]/points` — list / bulk upsert rate points (rejects writes to system curves).
- `GET|POST /api/accounting/loan-periods/[yyyymm]/close` — lock-status check / close period (reclassification journals + insert `loan_period_locks` row).

## Response contract
Every endpoint returns `apiResponse.success(res, data)` → `{ success: true, data, meta }`. Errors go through `apiResponse.badRequest` / `.notFound`, which return `{ success: false, error, meta }` with the appropriate status code. Clients MUST unwrap `json.data`.

## Auth expectations
- Session cookie from GoTrue (`sb-access-token`); `withAuth` reads it, decodes the JWT, sets `companyId` from the `company_id` claim, and also applies `set_config('request.jwt.claims', …, true)` inside the pg transaction so RLS policies fire.
- CSRF header required on mutating methods (enforced by `withCsrf`).

## Known behaviours
- **Route collision avoided**: `portfolio/summary.ts` and `portfolio/rate-sensitivity.ts` are static routes one level deeper than `[id]`; Next.js serves them before `[id]/...` despite the dynamic segment.
- **Period-close idempotency**: second POST to `/loan-periods/:yyyymm/close` returns 500 with "already locked" — callers should treat that as a success-equivalent during recovery.
- **GL posting prerequisite**: loan must have all five account FKs (`gl_account_id`, `interest_expense_account_id`, `interest_payable_account_id`, `bank_account_id`, `current_portion_account_id`) set or `postPeriodJournals` throws before creating any journal entry.
- **Payment date normalisation**: callers must format schedule-row dates via local getters (`getFullYear/getMonth/getDate`), not `.toISOString()`. UTC conversion under SAST (UTC+2) shifts first-of-month dates back by one day and `postJournalEntry` rejects with "Cannot post to closed fiscal period".
- **`loan_payments` table needs app_user GRANTs**. Mig 400 deploy required a manual `GRANT SELECT, INSERT, UPDATE, DELETE ON loan_payments TO app_user` — portfolio/summary 500'd with "permission denied" until granted.
