# Migration API routes

Data-migration wizard for onboarding companies from external systems (Sage, QuickBooks, CSV). Orchestrates a multi-step session: create session → import chart of accounts → import customers/suppliers/invoices → import opening balances → validate → complete. Delegates to `services/core/migration*.ts` services.

## Endpoints

| Method + path | Handler | Purpose |
|---|---|---|
| `GET /api/accounting/migration/session` | `session.ts` | Fetch the active `in_progress` session for the company. Returns `{ session: null }` if none. |
| `POST /api/accounting/migration/session` | `session.ts` | Create a new session `{ sourceSystem }`, or complete one `{ sessionId, action: 'complete' }`. Returns 201 for creation. |
| `GET /api/accounting/migration/validate?sessionId=` | `validate.ts` | Run all validation checks against a session. Returns `{ checks[], allPassed, summary }`. |
| `GET /api/accounting/migration/templates?sourceSystem=&step=` | `templates.ts` | Download a CSV template for a migration step. Streams CSV with `Content-Disposition: attachment`. |
| `POST /api/accounting/migration/chart-of-accounts` | `chart-of-accounts.ts` | Import accounts. Body: `{ sessionId, accounts[], systemAccountMap }`. |
| `POST /api/accounting/migration/customers` | `customers.ts` | Import customers. Body: `{ sessionId, customers[], duplicateStrategy }`. |
| `POST /api/accounting/migration/suppliers` | `suppliers.ts` | Import suppliers. Body: `{ sessionId, suppliers[], duplicateStrategy }`. |
| `POST /api/accounting/migration/ar-invoices` | `ar-invoices.ts` | Import AR invoices. Body: `{ sessionId, invoices[] }`. |
| `POST /api/accounting/migration/ap-invoices` | `ap-invoices.ts` | Import AP invoices. Body: `{ sessionId, invoices[] }`. |
| `POST /api/accounting/migration/opening-balances` | `opening-balances.ts` | Import opening balances. Body: `{ sessionId, effectiveDate, balances[] }`. |
| `GET /api/accounting/migration/sage-pull` | `sage-pull.ts` | Return JS injection scripts for the Sage browser extension. |
| `POST /api/accounting/migration/sage-pull` | `sage-pull.ts` | Receive raw Sage data from the browser extension, map to IsaFlow format. Body: `{ step, rawData }`. |

## Auth

- Most routes: `withAuth(withErrorHandler(withWriteAccess(handler)))` — only `owner | admin | manager` can write.
- `sage-pull.ts`: **`withAuth(withRole('super_admin')(withErrorHandler(handler)))`** — restricted to ISAFlow super admins only. This is an internal tool.
- `templates.ts` streams CSV directly without `apiResponse` wrappers.

## Response contract

All JSON routes use `apiResponse.success` / `.created` / `.badRequest` / `.notFound` / `.validationError`. `templates.ts` streams raw CSV — do not unwrap `json.data`. Clients MUST unwrap `json.data` for all other routes.

## Business rules / gotchas

- **Session is required** for all import steps — every import POST validates `sessionId` first.
- `session.ts` POST handles two actions in one endpoint: create (`{ sourceSystem }`) vs complete (`{ sessionId, action: 'complete' }`).
- `sage-pull.ts` is **super_admin only** — this is intentional; it is an ISAFlow internal migration tool, not tenant self-service.
- `validate.ts` only runs checks; it does not modify data. The `allPassed: false` result should block the wizard from advancing to "complete".
- `chart-of-accounts.ts` requires a `systemAccountMap` alongside the accounts array.
