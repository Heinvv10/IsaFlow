# capture/

## Endpoints / Modules
PRD-05 Phase 1 + 8 capture channels — inbound webhooks + PWA upload + inbox CRUD. All handlers delegate to `src/modules/accounting/services/capture/`.

- `POST /api/accounting/capture/inbound-email` — Postmark webhook. Verifies `X-Postmark-Token` when `POSTMARK_INBOUND_TOKEN` env is set (warn + skip otherwise). Calls `ingestPostmarkPayload` and fires `routeEvent` for each attachment. Returns 200 on rejection so Postmark doesn't retry.
- `POST /api/accounting/capture/inbound/whatsapp` — Twilio WABA webhook. Verifies `X-Twilio-Signature` via `twilio.validateRequest`. Parses body for expense commands (pure parser). Replies to sender via `sendWhatsAppMessage` (env-gated).
- `POST /api/accounting/capture/upload` — multipart form via `formidable`. Stores bytes via `storeCapturedBytes`, creates `captured_documents` + `capture_events` with channel='pwa'.
- `GET  /api/accounting/capture/inbox` — list pending events (status received/extracting/extracted), joined with extraction.
- `POST /api/accounting/capture/[id]/post` — runs the AI pipeline inline (not HTTP-call) so event and invoice are linked in one request. Gate-routes via `autoPublishGateService.decide` → duplicate_blocked (409) / route_review (draft) / auto_publish (approved). After insert, calls `performThreeWayMatch` + `attachEvidenceToProvisional` + `resolvePendingAlertForInvoice`.
- `POST /api/accounting/capture/[id]/discard` — status='discarded' + optional reason.
- `GET  /api/accounting/capture/inbox-address` — returns the company's active email inbox address.
- `POST /api/accounting/capture/inbox-address` — regenerates; deactivates prior row, mints new 6-hex slug.
- `GET  /api/accounting/capture/whatsapp-inbox` — same shape but for WhatsApp inbox (capture_inboxes channel='whatsapp'). POST upserts the WABA number (E.164 validated).

## Auth
- Webhook endpoints (`inbound-email`, `inbound/whatsapp`) are **no-auth** system-level; secret-gated via env token header instead.
- Everything else uses `withAuth(withErrorHandler(withWriteAccess(handler)))`.

## Request / Response
- Postmark body: `{ To, From, Subject, Attachments: [{Name, ContentType, Content(base64), ContentLength}], ... }`.
- Twilio WABA body: `{ From: 'whatsapp:+27...', To, Body, NumMedia, MediaUrl0..N, MediaContentType0..N, MessageSid }`.
- Capture event response shape: `{ id, received_at, channel, sender, status, captured_document_id, extracted_data, document_vendor, document_total, ... }` — snake_case, UI maps to camelCase.

## Business rules
- **Webhooks always return 200 on rejection** so the provider stops retrying; the service returns `{ rejected: '<reason>' }` for tenant miss / domain block / no attachments.
- **Fire-and-forget routeEvent**: webhook response doesn't wait for VLM extraction; the background `routeEvent` call catches and logs its own failures.
- **Post endpoint is the single source of truth** for gate decisions — does NOT re-call the gate after another service has posted, to avoid double-posting. Responds 409 on duplicate, includes gate reason strings in the response body.

## Learnings
- **Formidable + `fileWriteStreamHandler`**: needed to capture raw bytes (default handler writes to /tmp and returns a Path; we want a Buffer for SHA-256 + Storage upload in one shot).
- **Twilio signature verification requires the EXACT URL** the request was made to — behind a reverse proxy, check `x-forwarded-proto` + `host` or hardcode via `NEXT_PUBLIC_APP_URL`.
