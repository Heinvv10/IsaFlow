# Purchase Orders API routes

Sub-routes for the purchase order module, handling single-PO operations and supplier-scoped unmatched-PO queries. The primary CRUD list + create is in the flat file `pages/api/accounting/purchase-orders.ts`; this directory handles detail, update, delete, and a helper used during AP invoice matching.

## Endpoints

| Method + path | Handler | Purpose |
|---|---|---|
| `GET /api/accounting/purchase-orders` | `../purchase-orders.ts` (flat) | List POs with filters. |
| `POST /api/accounting/purchase-orders` | `../purchase-orders.ts` (flat) | Create a PO. |
| `GET /api/accounting/purchase-orders/[id]` | `[id].ts` | Single PO with line items joined from `po_items`. Includes supplier contact details. |
| `PUT /api/accounting/purchase-orders/[id]` | `[id].ts` | Update a PO. Only allowed when `status` in `['draft', 'submitted']`. Replaces line items if `items[]` provided. Recomputes totals. |
| `DELETE /api/accounting/purchase-orders/[id]` | `[id].ts` | Hard-delete. Only allowed when `status = 'draft'`. |
| `GET /api/accounting/purchase-orders/unmatched?supplierId=&purchaseOrderId=&include=` | `unmatched.ts` | Open POs and/or GRNs for a supplier not yet fully invoiced. Used to pre-fill AP invoice matching. |

## Auth

- `[id].ts`: `withAuth(withErrorHandler(withCsrf(withWriteAccess(handler))))`.
- `unmatched.ts`: `withAuth(withErrorHandler(handler))` — no CSRF (read-only).

## Response contract

All routes use `apiResponse.success` / `.badRequest` / `.notFound`. `[id].ts` GET returns the PO row merged with `{ items: po_items[] }`. `unmatched.ts` returns `{ pos: [], grns: [] }`. Clients MUST unwrap `json.data`.

## Business rules / gotchas

- PUT blocks on `status` not in `['draft', 'submitted']` — approved/received POs are immutable via this endpoint.
- DELETE is a hard-delete limited to `draft` status only.
- PUT line-item replacement deletes all existing `po_items` then re-inserts — not a diff/patch.
- `unmatched.ts` requires `supplierId`; `purchaseOrderId` and `include` (`pos | grns | both`) are optional. Default `include = 'both'`.
- Unmatched POs filter: `status IN ('submitted', 'approved', 'partially_received', 'received')` AND at least one item with `quantity_invoiced < quantity`.
- Line totals are computed server-side as `quantity × unit_price`; tax defaults to 15% if not specified.
