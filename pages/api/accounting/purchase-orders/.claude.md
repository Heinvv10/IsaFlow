# purchase-orders/

Sub-routes for single-PO operations + supplier-scoped unmatched-PO helper. Primary list/create handler is the flat file `pages/api/accounting/purchase-orders.ts`.

## Endpoints
- `GET /api/accounting/purchase-orders/[id]` — PO with line items (`{ ...po, items: po_items[] }`) + supplier contact
- `PUT /api/accounting/purchase-orders/[id]` — update; allowed only when `status IN ('draft','submitted')`; replaces line items if `items[]` provided (each may carry `cc1_id` / `cc2_id` / `bu_id`); recomputes totals. Sets `status` only to draft / submitted / cancelled: `approved` is 400 pointing to the Approve action, the receipt statuses 400 (budgets P5-3)
- `POST /api/accounting/purchase-orders/[id]/approve` — `{ budgetReason?, budgetOverride? }`: approves a draft/submitted PO under the budget check (`ap/purchaseOrderApprove.ts`; rules and lock order in `src/modules/accounting/services/ap/.claude.md`, P5-3 entry). 400 not approvable / reason required, 404, 409 `BUDGET_EXCEEDED`, 429 (120/min/user), 503 held
- `DELETE /api/accounting/purchase-orders/[id]` — hard-delete; only when `status='draft'`
- `POST /api/accounting/purchase-orders/[id]/cancel` — `{ reason }` (required): cancels an APPROVED PO with no goods received, releasing its budget commitment (`ap/purchaseOrderCancel.ts`). Owner/admin only. 400 not approved / goods received, 404, 409 changed, 422 bad body, 429, 503 held
- `GET /api/accounting/purchase-orders/unmatched` — `?supplierId=&purchaseOrderId=&include=pos|grns|both` — open POs + GRNs not yet fully invoiced

## Auth
- `[id].ts`, `[id]/approve.ts`, `[id]/cancel.ts`: `withAuth(withErrorHandler(withCsrf(withWriteAccess(handler))))` (approve: owner/admin/manager; cancel: `allowedRoles` owner/admin)
- `unmatched.ts`: `withAuth(withErrorHandler(handler))` — read-only

## Business rules
- PUT blocked on `status` not in `('draft','submitted')` — approved/received POs immutable via this route. The guard is in the UPDATE's WHERE, not only the earlier read; a zero-row UPDATE is classified by a company-scoped re-read: 404 gone, 400 naming the status, 409 if editable again (R-126)
- PUT line-item replacement is delete-all + re-insert, not diff/patch
- DELETE is hard-delete, `draft` only. The guard is in the DELETE's WHERE (`AND status = 'draft' RETURNING id`); a zero-row DELETE is classified by a company-scoped re-read: 404 gone, 400 naming the status, 409 if a draft again (R-129). `po_items` go by `ON DELETE CASCADE`. `goods_received_notes` references the PO with NO ACTION, but a PO with a GRN is never a draft: receipts need `approved`/`partially_received` (`goodsReceivedService.ts`), and the PUT cannot move those back, so the DELETE never reaches that FK
- `unmatched` requires `supplierId`; `purchaseOrderId` optional filter; `include` defaults to `both`
- Unmatched PO filter: `status IN ('submitted','approved','partially_received','received')` AND ≥1 item with `quantity_invoiced < quantity`
- Line totals computed server-side as `quantity * unit_price`; tax defaults to 15% when not supplied
- UUID guard on `[id]` (added 2026-04-20)
