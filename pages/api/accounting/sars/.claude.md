# SARS API routes

SARS (South African Revenue Service) tax-compliance surface. VAT201, EMP201, EMP501, IRP6 return preparation + submission tracking, and the compliance calendar. All routes live at the same depth (no subdirectories).

## Endpoints

| Method + path | Handler | Purpose |
|---|---|---|
| `GET /api/accounting/sars/sars-compliance?year=YYYY` | `sars-compliance.ts` | Compliance calendar from DB (`getComplianceCalendarWithDB`). Returns `{ events }`. |
| `GET /api/accounting/sars/compliance-calendar?year=YYYY` | `compliance-calendar.ts` | Pure calendar (no DB) — computed deadlines for VAT / EMP / IRP6 / IT14 for a given year via `calculateComplianceDeadlines`. Returns `{ year, deadlines, total }`. |
| `GET \| POST /api/accounting/sars/sars-submissions` | `sars-submissions.ts` | List (GET) / create (POST) SARS submissions (any tax type). Delegates to `services/reports/sarsService.ts`. |
| `GET \| POST /api/accounting/sars/sars-vat201` | `sars-vat201.ts` | VAT201 return build (GET) / submit (POST). Delegates to `services/reports/vat201Service.ts`. |
| `GET \| POST /api/accounting/sars/sars-emp201` | `sars-emp201.ts` | Monthly PAYE / UIF / SDL return. Delegates to payroll + SARS services. |
| `GET \| POST /api/accounting/sars/irp6.ts` | `irp6.ts` | Provisional-tax return (1st / 2nd / top-up). |
| `GET /api/accounting/sars/emp501.ts` | `emp501.ts` | Bi-annual employer reconciliation summary. Builds via `services/reports/irp5Service.ts`. |

## Auth
All routes: `withAuth(withErrorHandler(withWriteAccess(handler)))`. 

**Note: no `withCsrf` wrapper** — deviates from the `/loans` pattern which uses `withAuth(withErrorHandler(withCsrf(withWriteAccess(handler))))`. POST endpoints here rely on same-origin + bearer-token auth only. Verify this is intentional before adding new mutating routes.

## Response contract
`apiResponse.success(res, data)` / `apiResponse.methodNotAllowed(res, method, allowedMethods)` / `apiResponse.badRequest(res, msg)`. Clients unwrap `json.data`.

## Business rules / gotchas
- **SARS credentials are encrypted** — `sarsEfilingService` decrypts on read via `@/lib/encryption`. Never log the decrypted value from a route handler.
- **Two calendar endpoints intentionally coexist** — `sars-compliance` pulls from DB (tenant-customised deadlines), `compliance-calendar` is pure (no DB, no auth-sensitive data). Don't merge them.
- **Route naming is inconsistent** — some files have `sars-` prefix (`sars-vat201`, `sars-compliance`), others don't (`irp6`, `emp501`). Don't "fix" this without migrating the clients; the URLs are public API.
- **POST submissions are destructive** — `sars-submissions` POST actually files with SARS eFiling in non-test mode. Check `SARS_EFILING_ENV=sandbox` in dev/staging.
- **IRP5/EMP501 pull from payroll** — `emp501.ts` calls `buildEMP501Summary` over `EMP501MonthlyData`; upstream depends on payroll runs being posted for each month of the recon period.
- **No CSRF means no browser form POST protection** — if a browser client POSTs VAT201 submission, malicious cross-origin requests could trigger it. Mitigated by bearer-token auth requirement and same-origin fetch from the app.
