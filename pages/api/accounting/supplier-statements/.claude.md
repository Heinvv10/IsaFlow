# supplier-statements/ (PRD-05 Phase 7)

Upload supplier's monthly statement PDF → VLM extracts lines → per-line match against `supplier_invoices` with variance. Mig 417.

## Endpoints
- `GET /api/accounting/supplier-statements` — optional `?supplierId=`; **single JOIN query** (N+1 fixed d471d8c); list returns headers only — `lines` and `missingInvoices` are empty in list view
- `POST /api/accounting/supplier-statements` — multipart with `supplierId`; stores PDF, runs `vlmSupplierStatementService`, persists reconciliation + lines
- `GET /api/accounting/supplier-statements/[id]` — full reconciliation with matched lines + missingInvoices
- `POST /api/accounting/supplier-statements/[id]/rematch` — without re-calling the VLM, re-matches the lines against the current bills AND re-measures `isaflow_balance`/`variance` from the AP ageing at the statement date (the same `measureOurSide` creation uses). Refused with **409** (`ReconciliationClosedError`) once the statement is `reconciled`: re-measuring would overwrite the variance it was reconciled at, which is stored nowhere else. The page disables the button for a reconciled statement
- `POST /api/accounting/supplier-statements/[id]/mark-reconciled` — stamps status + timestamp with current user. **No server-side gate** (R-087): the only check is the page's `canReconcile`

## Auth
`withAuth(withErrorHandler(withCsrf(withWriteAccess(...))))` on mutating POST routes (all import `withCsrf`). `withAuth(withErrorHandler(...))` + `withCsrf` on GET detail. Listing uses `withAuth(withErrorHandler(handler))`.

## Request / Response
`SupplierStatementReconciliation`: `{id, supplierId, supplierName, statementDate, period, supplierBalance, isaflowBalance, variance, status, missingInIsaflowCount, missingInStatementCount, amountDiffCount, lines[], missingInvoices[], createdAt, reconciledAt}`

Line: `{matchedSupplierInvoiceId, matchedInvoiceNumber, matchConfidence, mismatchReason ∈ missing_in_isaflow|missing_in_statement|amount_diff|date_diff}`

## Business rules
- **Match ladder**: exact reference → confidence 1.0, null reason (unless amount > R0.01 diff → `amount_diff`, or date > 7d off → `date_diff`). Else fuzzy amount ±0.5% + date ±3d → 0.85. Else `missing_in_isaflow`
- **Missing-in-statement pass**: after line matching, every `supplier_invoices` in period without matched line becomes `missing_in_statement` synthetic line
- **Variance** = `supplier_balance − isaflow_balance`, where `isaflow_balance` is the AP ageing for the supplier **as at the statement date** (`measureOurSide`). Computed at creation and again on every Rematch, so the variance and the line counts always describe the same bills
- `mark-reconciled` does **not** gate on anything server-side (R-087, pre-existing). The page's `canReconcile` requires `|variance| ≤ R0.01`, `missingInIsaflowCount = 0` and `amountDiffCount = 0` — it does not consider `missingInStatementCount`
- **Match candidates** are the ageing's population (`shared/documentPopulation`): drafts and cancelled bills never match a line, NULL-status bills do (R-059 rounds 8-10)
- List view returns empty `lines` (performance — d471d8c). Callers needing line data fetch `GET /[id]`
