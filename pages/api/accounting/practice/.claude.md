# practice/ (Practice management — PRD-01)

Clients, staff rates, time entries, WIP, jobs/tasks, billing, reports. All services in `src/modules/accounting/services/practice/`.

## Endpoints

### Clients + contacts + groups
- `GET|POST /api/accounting/practice/clients` — list (filters: status, search, groupId, pagination) / create (seeds default job categories)
- `GET|PUT|DELETE /api/accounting/practice/clients/[id]` — CRUD
- `POST /api/accounting/practice/clients/bulk` — bulk ops (CSV import, status change)
- `GET|POST /api/accounting/practice/clients/[id]/rate-overrides` — per-client-per-staff rate CRUD (mig 395); PUT with `?overrideId=`
- `GET /api/accounting/practice/clients/[id]/staff` — list company users for dropdown
- `GET|POST /api/accounting/practice/client-contacts` (`?clientId=`) — list/create; `DELETE /client-contacts/[id]`
- `GET|POST /api/accounting/practice/client-groups`

### Jobs / tasks / work items / templates
- `GET|POST /api/accounting/practice/jobs` — filters: `practiceClientId, partnerId, preparerId, status, dueBefore`
- `GET|PUT|DELETE /api/accounting/practice/jobs/[id]`
- `POST /api/accounting/practice/jobs/transition` — `{ id, newStatus }`
- `GET|POST /api/accounting/practice/tasks` — filters: `jobId, assignedTo, status, overdueOnly, parentTaskId`
- `GET|PUT|DELETE /api/accounting/practice/tasks/[id]`
- `POST /api/accounting/practice/tasks/transition` — `{ id, newStatus }`
- `POST /api/accounting/practice/tasks/recurring` — `{ sourceTaskId }` generates next instance
- `GET|POST /api/accounting/practice/work-items`; `PUT /work-items/[id]`
- `GET|POST /api/accounting/practice/job-categories`; `PUT|DELETE /job-categories/[id]`
- `GET|POST /api/accounting/practice/entry-templates`; `GET|PUT /entry-templates/[id]`

### Time entries (Phase 1 staffing)
- `GET|POST /api/accounting/practice/time-entries`
- `GET|PUT|DELETE /api/accounting/practice/time-entries/[id]`
- `POST /api/accounting/practice/time-entries/submit` — bulk draft → submitted
- `POST /api/accounting/practice/time-entries/approve` — bulk submitted → approved
- `POST /api/accounting/practice/time-entries/write-off` — bulk write-off
- `POST /api/accounting/practice/time-entries/bulk` — fill date range from template
- `POST /api/accounting/practice/time-entries/duplicate` — duplicate entry to new date

### Rates
- `GET|POST /api/accounting/practice/staff-rates` (GET requires `?userId=`); `GET|PUT|DELETE /staff-rates/[id]`
- `GET|POST /api/accounting/practice/staff-cost-rates` (mig 386 — margin reporting); `GET|PUT|DELETE /staff-cost-rates/[id]`
- `GET /api/accounting/practice/rate-resolve` — `?userId=&clientId=&date=` effective rate

### WIP + reports
- `GET /api/accounting/practice/wip` — WIP board by client (read-only, viewer-accessible)
- `POST /api/accounting/practice/wip/invoice` — `{ practiceClientId, timeEntryIds, taxRate? }`; requires practice client `link_customer_id`
- `GET /api/accounting/practice/reports/utilisation|profitability|wip-aging|revenue-pipeline|compliance|service-mix`
- `GET|POST /api/accounting/practice/report-recipients`; `GET|PUT|DELETE /report-recipients/[id]`
- `GET /api/accounting/practice/users` — company users for dropdowns

## Auth
- Mutating (POST/PUT/DELETE): `withAuth(withErrorHandler(withCsrf(withWriteAccess(handler))))`
- Read-only (`rate-resolve`, `wip`, `users`, reports): `withAuth(withErrorHandler(handler))` — CSRF/WriteAccess intentionally omitted so `viewer` role can access WIP board

## Business rules
- Client creation fires `seedDefaultCategories` — failure is non-fatal (warn-log, doesn't roll back)
- `billingModel` and `status` required when creating a client
- `client-contacts` POST, `jobs/[id]` PUT and `entry-templates` POST / `[id]` PUT answer 400 when the body names a practice client that is not this company's (R-073, `PracticeClientNotInCompanyError`), before any write. The job PUT keeps its generic `Update failed` message.
- `clients` POST and `clients/[id]` PUT answer 400 when `clientGroupId` is not this company's group or is malformed (R-161, `ClientGroupNotInCompanyError`), before any write. An absent group is unchanged.
- `clients/[id]/rate-overrides` answers a malformed client id with 400 (`isUuidParam`) and another company's or an unknown client with 404, through `assertPracticeClientInCompany` (R-163). Its old local check had no savepoint, so a malformed id was a 500.
- `''` for `clientGroupId` or `linkCustomerId` means "none", same as omitting the field on create; on `clients/[id]` PUT it CLEARS the field (R-170) — both are normalised to `null` before the fence and the `::UUID` cast, which is not savepointed and 500'd on `''`. PUT distinguishes "field absent from the body" (unchanged) from `''`/null (clear) from a real id (set, after the fence): `'clientGroupId' in input` / `'linkCustomerId' in input` gate a `CASE WHEN … THEN … ELSE column END`, since `COALESCE` cannot express "clear". `clients/[id]` (GET/PUT/DELETE) also gained a top-of-handler `isUuidParam` guard — a malformed id reached the same unsavepointed cast on the first read and 500'd.
- `rate-resolve` precedence: client-specific staff rate → default staff rate → category default
- `wip/invoice` answers a `WipInvoiceRefusal` with 400 **and its own message**. That covers: no `link_customer_id` or a link to another company's customer, nothing eligible, a `taxRate` outside 0–100 or with more than 2 decimals, a negative, NULL or inconsistent entry, and a concurrent billing. A `201` result carries `skippedEntryCount`. A body that fails the schema is a 400 naming the field. Lock contention is 503; any other error is 500 (R-120).
